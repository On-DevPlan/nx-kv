# 场景：agent 领取主题任务并回填

> 归属主文档 [[nx-kv]]。当 agent 要消费任务队列（提交方 → KV 清单 → agent）时读。

## 何时进入

- 用户说「领取/看一下/处理某个主题的任务」
- 需要把某个 topic 的待办一次拿全并据此开工
- 完成后要回填结果，方便人和后续 agent 追溯

## 核心流程

```mermaid
flowchart LR
  A[1 确认登录与工作空间] --> B[2 拉该 topic 全部待办]
  B --> C[3 同时读 topic 提示词]
  C --> D[4 不要立即执行]
  D --> E[5 与用户对齐意图]
  E --> F[6 执行]
  F --> G[7 done 回填结果]
```

### 1. 确认登录与工作空间

```bash
nx-kv auth status --json      # loggedIn / groupId
nx-kv group current           # 当前在哪个空间
```

**先确认空间对不对**——数据按 groupId 隔离，在错的空间里会「什么都查不到」，
而那不是「没有任务」，是「看错地方了」。

### 2. 一次拿全该主题的待办

```bash
nx-kv todo list --status open --topic <topic> --json
```

不要「拉全量再自己过滤」：`--topic` 已经做了，全量里还有别的主题和历史噪音。

### 3. 同时读走主题提示词

```bash
nx-kv prompt get <topic> --json     # {topic, prompt, hasPrompt}
```

`prompt` 是 topic 级的共享上下文——项目约定、技术栈、注意事项都在里面。
**它是任务文本的背景，不是可选项**：缺了它，任务往往只是「半句话需求」。

### 4. 不要立即执行

拿到任务先停。直接开干是这里最常见的错误——任务文本经常是模糊的一句话，
盲目执行必然返工。

### 5. 与用户对齐意图

- 把每条任务改写成「可执行、有边界、可验收」的表述，但**不改原意**
- 向用户确认理解是否正确，让用户补背景、约束、优先级
- 多条任务按主题聚类后再开工

### 6. 执行

按对齐后的意图做。若中途发现任务描述与实际不符，**回到第 5 步**而不是自行改需求。

### 7. done 回填结果

```bash
nx-kv todo done <id> --result "改了什么 / 关键决策 / 遗留问题"
```

`--result` 会写进该任务的 `note`。**回填的价值**：done 是长期保留的历史，
下一个人（或下一个 agent）靠它判断「这件事当时怎么做的」，而不是重新猜一遍。

> ⚠️ 回填前确认 id 没歧义。若报「命中 N 条」，用 `--topic` 或 `--pick` 选准 ——
> 详见主文档的「id 不唯一」一节。

## 稳定契约（可依赖）

| 契约 | 内容 |
| --- | --- |
| `--json` | 单个 JSON 值到 stdout；无多余文本 |
| 退出码 | `0` 成功；`1` 失败（含需消歧） |
| 错误码 | `code` 可取 `INVALID_INPUT` / `NOT_FOUND` / `CONFLICT` / `EXTERNAL`，优先用它分支 |
| 幂等 | 重复 `topic add` / 重复删除不存在的主题都不报错 |
| 状态冲突 | 已完成再 `done`、已冻结再 `freeze` → `CONFLICT` + exit 1，语义是「已经是你要的」，跳过即可 |

## 一次拿齐上下文的捷径

```bash
nx-kv bootstrap --json
```

返回版本、登录态、当前工作空间、工作空间列表、**完整命令表**（每条含 `command` / `usage` / `http`）。
比多次往返省事，也让 agent 不必猜命令签名。

## 安全边界

- **不要**用 nx-kv 往别的 topic 写任务来「提醒自己」——那是污染别人的队列
- **不要**在没有 `--topic` 消歧的情况下对 done 里的 id 做删除
- 切换工作空间前先确认，别在别人的空间里写数据
- `--password` 写在命令行里会进 shell 历史；交互式输入更安全
