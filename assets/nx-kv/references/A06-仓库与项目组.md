# A06 · 仓库与项目组

## 三步

1. `board list --json`（要单仓库归属时 `repo list --json`）。
2. 按组名 / 仓库名 / 路径定位到成员与描述。
3. 出报告：成员行带组内 note，末尾原样附上组的 desc（含关键路径与关键词）。

两件事：**「这组仓库是什么、怎么配合」**（给人看的报告）和**「这个任务该去哪些仓库找上下文」**
（给自己用的定位）。

## 出关系报告（`/kv-repo <组名|仓库名|路径>` 的等价动作）

```bash
nx-kv board list --json
# → { boards:[{ id, name, desc, repos:[{ id, name, desc, path, note }] }], unassigned:[…] }
nx-kv repo list --json        # 扁平清单，每条带 key / boards[]（按仓库查归属）
```

- 参数是**组名** → `boards[]` 按 name 找（找不到再试包含匹配）；
- 参数是**仓库名或路径** → `repo list` 定位，报告它所属的**每个**组（一个仓库可归多组）；
- 任务 instruction 已带 repo/boards 时直接用，不必重查。

报告形状（**原样带上** desc 里的关键路径与关键词——那是前人留的搜索入口）：

```
【fr】Flutter 客户端组 —— 组内共享 API 契约
  fr      D:\code\a_dart\prj\fr      （组内）API 契约方：lib/api/ 是唯一入口，搜 fr_ 前缀
（领域描述）<组的 desc 全文>
```

每行优先读**组内描述（note）**（这个仓库在本组的角色），没写再回退仓库自己的 desc。
无参数时：全部组速览（组名 · 成员数 · desc 首行）+ 未分组计数，然后问一次深入哪组，
不要连环追问。

## 顺手维护描述（读到过期就修）

```bash
nx-kv board update <id> --desc "侧重…；谁配合谁（中心/终端、API 关联）；关键路径…；搜索关键词…"
nx-kv board note <仓库 id|路径> --board <组 id> --note "这个仓库在组里的角色…（留空 = 清除）"
```

四个要素：① 一句话侧重 ② 配合关系（组级写 desc，单仓库角色写 note）③ 关键路径 ④ 搜索关键词。

## 常用

```bash
nx-kv repo get <id|key|绝对路径> --json   # 单仓库详情 + 所在组
nx-kv board get <id> --json                # 单组详情（成员 + 组内描述）
nx-kv repo ref of <id|key|路径> --json     # 参考仓库（组级 + 仓库级两类）
nx-kv board assign --id <仓库> --board <组id> [--remove] [--before <仓库>]  # 成员增删 / 排序
nx-kv repo list --type dev|ref             # 只要开发仓库 / 只要参考仓库
```

概念（仓库 / 项目组 / 参考绑定 / key）见 [[B01-概念与寻址]]；登记与增删见 [[B02-CLI速查]]。

## 偏差

| 偏差 | 正确做法 |
| --- | --- |
| 只读仓库自己的 desc | 先读组内 note（它才是「在本组里的角色」） |
| 把 desc 里的关键路径/关键词省略 | 原样带上——那是前人留的搜索入口 |
| 无参数时连环追问 | 先给全组速览，只问一次深入哪组 |
