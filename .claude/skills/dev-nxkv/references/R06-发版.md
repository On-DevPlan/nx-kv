# R06 · 需求 · 发版（版本 / CHANGELOG / 契约 / 推送）

> 命中信号：「发个版」「打 tag」「升版本」「更新 CHANGELOG」「契约没生成」。
> 本仓库的节奏是**逐任务发版**：任务完成即 commit + push，发版跟着任务走。
> tag 与 npm publish 由 CI 自动完成——本地只负责「定级 + CHANGELOG + 契约重生成 + push」。
> 契约生成机制见 `P03-契约生成.md`；门禁与提交规矩见 `P05-交付门禁与提交.md`。

## ① 前置（先核对基线）

```powershell
git status --short                    # 并行会话可能也有改动；只提交自己的文件
git log --oneline -5                  # 本次发版包含哪些 commit（CHANGELOG 要覆盖全部）
git fetch origin main
git ls-remote origin main             # 远端指针；本地落后先 rebase
git tag --sort=-v:refname | head -5   # 已打到哪（别撞车）
cat package.json | grep version       # 当前版本号
```

## ② 判定：这次发什么级

| 内容 | 级 | 例 |
|---|---|---|
| 文档 / skill / 样式 / 小修 / 内部工具行为 | **patch** | 0.56.0 → 0.56.1 |
| 新命令、新面板能力、新附件类型、新设置项 | **minor** | 0.55.3 → 0.56.0 |
| 删入口、schema 不可升迁移、破坏命令兼容 | **major** | 慎用 |

- npm 侧发丢过版本（0.53.2 被丢弃）→ 重发也 patch 再 +1（0.53.3 先例），**别复用旧版本号**。
- 有历史遗留的 Unreleased 内容没发过 → 一并写进本次版本段，别让段落漂着。

## ③ 动作

**1. CHANGELOG.md 加版本段**（Keep a Changelog 格式）：

```markdown
## [X.Y.Z] - <YYYY-MM-DD> <一句话标题>

### Added / Changed / Fixed
- 写「为什么」而不只是「改了什么」（下一个人靠它判断能不能改）；
- 面板改动补一段「验证」：探针断言 + 门禁结果。
```

**2. package.json 升版本号**（只这一处；CI 检测版本变化后自动 publish + 打 `vX.Y.Z` tag）。

**3. 契约快照重新生成**（版本号嵌在契约里，每次发版必跑）：

```powershell
pnpm gen:dart        # 写 contract/contract.json + contract/dart/**（机制见 P03）
```

**4. 对外可见面收口**——一次行为改动要动四处，漏一处使用者就看到两个版本：

| 面 | 位置 | 查漏 |
|---|---|---|
| 实现 | `src/`（R01/R02/… 已完成） | — |
| 消费侧说明书（给使用者 agent） | `assets/nx-kv/`：`SKILL.md` 的 description 写「用户会怎么说」的触发词；`references/` 一文件一场景；命令/参数变了**全量搜旧名** | `grep -rn "<旧命令名>" assets/ README.md docs/` 应为 0 命中 |
| 用户文档 | `README.md`、`docs/` | 同上 |
| 变更记录 | `CHANGELOG.md` | 覆盖本次全部 commit |

（`assets/` 与开发手册 `dev-nxkv/` 是两个 skill，别改错地方——那是使用者说明书，这是开发者动作手册。）

**5. 发版前最后一遍门禁**（`P05-交付门禁与提交.md`），然后 commit + **显式推送**：

```powershell
git add package.json CHANGELOG.md contract/   # 只 add 本次发版的文件
git commit -m "chore(release): X.Y.Z —— 一句话标题"
git push origin main    # 不要裸 push：全局 remote.pushDefault 指向不存在的 upstream
```

**6. CI 接手**：push 到 main 后 `npm-publish.yml` 自动 publish 并打 `vX.Y.Z` tag，
`ci.yml` 与 `contract-guard.yml` 做校验。盯到绿：

```powershell
gh run list --limit 5
```

## ④ 自检

| 检查 | 命令/判据 |
|---|---|
| 门禁全绿 | `pnpm lint`、`pnpm test` 退出码 0 |
| 契约一致 | `pnpm gen:dart --check` 无差异；`git status --short contract/` 干净（已提交） |
| 远端收齐 | `git ls-remote origin main` = 本地 HEAD |
| CI 绿 | `gh run list` 三条流水线（CI / publish / contract guard）都 success |
| tag 出现 | `git fetch --tags` 后 `git tag --sort=-v:refname | head -3` 里有 `vX.Y.Z` |
| npm 可见 | `npm view nx-kv version` = 新版本号 |

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| contract guard 红 | 改了声明没跑 `pnpm gen:dart` / pubspec 缺 `environment` | 补生成；`environment` 字段不许删（见 `P03-契约生成.md`） |
| CI publish 跑了但 npm 上没有新版本 | 版本被 registry 丢弃（0.53.2 先例） | patch 再 +1 重走一遍（0.53.3 先例），别复用旧号 |
| push 报 tag 已存在 | 上次发版号没升 | 先升号再 push；别手工打 tag 抢在 CI 前面 |
| 裸 `git push` 报 upstream 不存在 | 全局 `remote.pushDefault=upstream` | 显式 `git push origin main` |
| 使用者说文档和行为对不上 | 对外收口漏了一处 | 按表 4 查漏补一笔 fix/docs commit，patch+1 再发 |
| Dart 端（fr）没跟着升级 | 契约变了但没人提醒 | 发版汇报/PR 描述里点名 bump（contract-guard 的约定） |

## ⑥ 反模式

- 手改 `contract/` 下任何生成物（`--check` 会红）。
- 手工 `git tag` / 手工 `npm publish`（CI 是唯一发布通道，抢跑会撞车）。
- CHANGELOG 只写「改了什么」不写「为什么」。
- 把多个不相关任务挤进同一个版本号（回滚粒度没了）。
- 忘了升版本号就 push（CI 检测不到变化，publish 直接跳过）。
