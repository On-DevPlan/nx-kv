# B01 · 架构分层：代码放在哪、谁能 import 谁

> B 序列 · 架构之一。回答「这个改动该落在哪一层、依赖方向是什么、模块骨架长什么样」。
> action 的声明与注册见 [[B02-action注册全表]] 与 [[B03-action契约]]。

## 1. 依赖方向（单向，不可逆）

```text
bin/kv.mjs ─┐
web 前端 ─────┼─→ /api ─→ runtime ─→ modules ─→ core
              │                     └→ shared ←─┘
              └→ shared（仅纯函数）
```

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 入口 | `bin/kv.mjs` | Node 版本硬拦 → 动态 import `runtime/cli.ts` | 写业务 |
| 运行时 | `src/runtime/` | registry / cli / api / server / cors / spec | 写业务 |
| 功能域 | `src/modules/<id>/` | action 声明 + 业务 + 仓储 | 互相 import 内部实现；import runtime |
| 原语 | `src/core/` | db、errors、模板引擎、workflow、路径、配置等跨模块原语 | 依赖 modules / runtime / web / shared；**放业务** |
| 同构 | `src/shared/` | 前后端**同构**的纯函数/常量 | 依赖任何东西（含 `node:`、第三方包）；有状态 |
| 前端 | `src/web/frontend/` | 面板 | import 后端模块 |

四条不可破的规则：

1. `runtime → modules` 允许；**反向禁止**（`registry → modules/system → cli → registry` 会成环）。需要运行期数据（命令表）时，由 runtime 把表**传给**模块的纯函数。
2. `modules/A → modules/B` 只能经 B 的 `service.js` 导出面；禁止深入 `B/repo`、`B/*.js` 内部。
3. `core/` 只放原语，`shared/` 只放无副作用纯函数，**业务留在模块 service**。
4. 前端只消费 `/api/*`；前端不得 import 后端模块，跨端纯函数放 `src/shared/`。

### eslint 的强制方式与它的盲区

- `eslint.config.js` 用 `no-restricted-imports` 表达上述规则；`tests/unit/layering.test.mjs` 另有一层。
- **盲区（要知道）**：模块互依禁列是**枚举式**的——当前只列了 `../repos/*`、`../skills/*`、`../github/*`、`../bundled/*`、`../system/*`、`../todo/*`、`../sessiontask/*`。其中 `skills` / `github` / `sessiontask` 已不存在（历史遗留），`setting` 未被列入（注释里的 `../settings/service.js` 是旧名笔误）。**新增模块必须手动补 `'../<新模块>/*'`，漏补不会报错。**
- `system` 是刻意的**聚合模块**（bootstrap 要一次拿齐各模块状态），放开「模块互依」这一条。
- `src/shared/**` 的规则最严：除同目录相对引用外不得依赖任何东西（碰 `node:` 就进不了浏览器包，碰第三方包就进不了 Node）。

## 2. 目录地图

```text
bin/kv.mjs                    CLI 唯一入口（Node 版本硬拦 → 注册 tsx → 动态 import runtime）
src/runtime/                  **全部 TS**（模板形态，双通道并存）
  types/module.ts             ModuleBase 基类 + AnyModule 契约
  action-base.ts              ActionBase（依赖经 IoC 容器拿）
  action-decorator.ts         @action 装饰器 + zodActionsOf（收集 action）
  zod-bridge.ts               zod ↔ CLI/HTTP 形态（归一化 + 校验）
  container.ts                IoC 容器（DependencyMap 键 → 类型）
  registry.ts                 Registry 类：模块注册表 + 装载期自检（双通道）
  spec.ts                     action 规格：legacy flags 表 + zod 用法串 + 路由编译
  cli.ts                      CliApp：argv → 匹配 action → 解析 → 执行 → 渲染
  api.ts                      ApiRouter：HTTP 路由表（由 action.http 编译而来）
  server.ts                   PanelServer：node:http 零依赖服务器（静态文件 + /api 分派）
  cors.ts                     跨域策略
  help.ts                     help 文本（由命令表派生）
  codegen.ts                  生成前端 typed client + CLI 树快照
src/core/                      db / errors / 模板引擎 / workflow / paths / config / attachmentdb …
                              （errors / paths / config / command-table / serve-port / open 已是 TS）
src/shared/                    前后端同构纯函数（prompt-blocks / graph / wikilink / frontmatter / task-status …）
src/modules/<id>/
  index.ts                     **模板形态**：ModuleBase 子类，只做装配（action 清单自动收）
  index.js                     **legacy 形态**：plain-object，action 声明（CLI/HTTP 的唯一出口）
  schemas.ts                   zod 契约常量（模板形态）
  actions/<名>.ts              一条 action 一个文件（@action 声明 + 实现）
  actions/_manifest.generated.ts  codegen 产物：收进本目录所有 ActionBase 子类
  service.js                   业务规则 / 事务边界
  repo/                        SQL 仓储（*.js），行↔对象映射集中在 rows.js
  <域内其他>.js                该域自己的实现（action-*.js / engine.js / store/ …）
src/web/frontend/
  main.jsx                     Provider 组装（store → toast → App）
  App.jsx                      应用壳 v2（FlexLayout 工作区 + hash 路由）
  app-context.jsx              运行时上下文（rows / repoData / model / openPage …）
  store.jsx                    全局 UI 状态（bootstrap + localStorage 持久化的「选择」）
  api/client.js                API 客户端（`api(path, {method, body})`）
  api/client.generated.ts      **codegen 产物**：zod action 的类型安全 client（type-only 引后端 schema）
  api/cli-tree.json            **codegen 产物**：CLI 命令树快照
  registry.js                  **视图注册表**（有哪些视图）
  panels.jsx                   **面板注册表**（工作区里能开哪些面板）
  route-map.js                 路由 ↔ 面板的纯映射（不引 React，可单测）
  workspace.js + workspace/    布局模型、开关面板的辅助
  page/<name>/                 页面
  modules/<name>/              可复用前端模块（md / board / prompts）
  components/<group>/          组件
tsconfig.base/node/web.json    strict TS 三配置（node 侧出 dist，web 侧只查类型）
vite.config.ts                 前端构建（root=src/web/frontend → src/web/public）
tests/unit/*.test.mjs          单测
tests/smoke.mjs                冒烟（假后端 + 临时配置）
tests/support/test-store.mjs   测试临时库（断言必须在 tmp 下）
scripts/                       gen-actions / gen-api-client / dev / lint 辅助 / link-local
assets/                        随包发布的用户侧 agent 技能
```

### TS 化路线（2026-11-11 起，见 plan/174-template-ts-refactor-stage1.md）

骨架已按 `nx-nx/templates/server-cli-web` 模板形态落地（runtime / codegen / 工具链 /
`system` 模块），**业务模块逐个迁移**：

- tsconfig 侧：`allowJs` 过渡——存量 `.js` 只解析不查类型，迁成 `.ts` 即纳入 strict；
  某文件「毕业」＝ 改扩展名 + 补类型。
- 模块侧：legacy flags 表通道与 zod 通道并存，新 action 一律走 zod 通道。
- 门禁：`pnpm typecheck`（tsc -b，strict）+ `pnpm lint`（typescript-eslint）+ `pnpm gen`（codegen 新鲜度）。
- bin **直跑 TS 源码**（tsx 注册），不走 dist——避免「改了忘 build」导致全局命令静默跑旧逻辑。

## 4. 模块骨架

### `index.js`：只放 action 声明

```js
import * as service from './service.js';

export default {
  id: 'demo',
  title: '演示',
  order: 100,
  actions: [
    {
      id: 'demo.list',
      cli: ['demo', 'list'],
      http: ['GET', '/api/demo'],
      summary: '列出演示项',
      flags: { limit: { type: 'number', default: 20 } },
      run: (ctx) => service.list({ limit: ctx.limit }),
      render: (d) => d.rows.map((x) => x.name).join('\n'),
    },
  ],
};
```

- 一个 action 同时声明 CLI 与 HTTP，二者**结构上**不会分叉。
- `run` 只做入参归一与调用 service；SQL / 事务不写在这里。
- **没有模块级 `view`**：视图归前端 `registry.js`，`tests/unit/registry.test.mjs` 会断言后端不出现该字段。

### `service.js`：业务与事务

- 事务用 `txw((conn) => { … })`；回调**同步**，里面不要 `await` 网络/文件 IO。
- 跨表写入、编号分配、依赖写入必须在同一事务。
- 抛错用 `src/core/errors.ts` 的 `badInput` / `notFound` / 等，保持 CLI 错误可读，并让 HTTP 错误码能映射到状态码。

### `repo/`：SQL 仓储

- `repo/open.js` 统一提供 `db()` / `txw`；**SQL 只出现在 `repo/*.js`**。
- 行 ↔ 领域对象映射集中在 `rows.js`（例：`tasks.body` → JSON `text`、`from_src` → `from`）。
- 新查询默认过滤 `deleted_at IS NULL`。
- 时间戳统一 `core/db/time.js` 的 `nowMs()`。

### 何时用 `ext` JSON

- 只放「展示附属信息」：icon、备注、原始远程列表、旧 id 取证等。
- **凡是要进 WHERE / 排序 / 唯一约束的字段，必须是真实列**（ext 无索引）。详见 [[A03-键与扩展位]]。

## 5. 新增一个模块的步骤

1. 建 `src/modules/<id>/index.js`、`service.js`，需要持久化就建 `repo/`。
2. 在 `src/runtime/registry.ts` import 并加入 `MODULES`。
3. **在 `eslint.config.js` 的模块互依禁列里补 `'../<id>/*'`**（枚举式，漏补是静默的）。
4. 需要面板：在 `src/web/frontend/page/<id>/` 写视图，并登记到 `src/web/frontend/registry.js`（见 [[D02-页面与组件关系]]）。
5. 加测试：`tests/unit/registry.test.mjs` 会校验视图归属的模块已登记、视图文件存在、`/api` 字面量有对应路由；补该域单测。
6. 更新 `README.md` / `docs/` / `assets/`（若对使用者可见）。
7. 跑 `pnpm lint && pnpm test:unit && pnpm build`。

## 6. `assets/`：用户侧 agent 的说明书

`assets/` 随包发布，由 `src/modules/bundled/` 的 `skill list/groups/install/get` 安装到 `~/.claude/skills`，或直接 `skill get` 吐全文：

```text
assets/
├── groups.json     # group 名 → skills[] + summary（别名表，不是第二事实源）
├── nx-kv/          # 每个目录一个 skill，必须有 SKILL.md
├── kv-get/
├── kv-submit/
└── kv-repo/
```

同步规则：

- 命令 / flag / 输出口径变了 → 改对应 `assets/<name>/SKILL.md` 与 `references/*.md`；`grep -rn "<命令名>" assets/` 找齐。
- 增删内置 skill → 建/删目录 + 同步 `groups.json`（group 名 kebab-case、`skills` 非空）。
- `groups.json` 缺失 / 错 schema 会降级成「每个目录各成一组」；测试 `bundled-multiskill.test.mjs` 用 `NX_KV_ASSETS` 指向伪资产树，**不要用测试改仓库里的 `assets/`**。
- assets 变化是对外行为，进 `CHANGELOG.md`。

## 7. 文件体量

单文件超过约 400 行就考虑拆分（service / repo / 子组件）。拆分按职责，不要按「代码行数」机械切。

## 8. 关键文件

| 文件 | 作用 |
|---|---|
| `src/runtime/registry.ts` | 模块注册表 + action 装载期自检 |
| `src/runtime/spec.ts` | action 规格解析（flag 强转 / 路由编译 / 用法串） |
| `src/runtime/cli.ts` | argv → action 匹配（最长路径优先）→ 执行 → 渲染 |
| `src/runtime/api.ts` | HTTP 路由表与分发 |
| `src/runtime/server.ts` | 静态文件 + `/api/*` 分派 |
| `src/core/command-table.ts` | 命令表快照格子（runtime 写、modules 读，避免成环） |
| `src/core/errors.ts` | 错误码 → 消息 / 退出码 / HTTP 状态 |
| `eslint.config.js` | 分层规则的执行者 |
| `tests/unit/layering.test.mjs` | 分层规则的第二道执行者 |
