# kv-submit — 提炼需求，委托其它 agent（提交侧）

把「这个对话里的上下文 + 用户需求」变成一条**自包含**的任务，投进目标工作目录
的任务队列。在那边工作的 agent（正在 wait 的立刻收到；不在等的下次领取）接手
执行。**你发的是任务，不是对话记录**——接收方看不到你的对话，任务文本必须
自己站得住。

## 三步走（核心流程）

1. **总结上下文**：当前对话聊了什么、做了哪些决策、涉及哪些文件/路径/约定。
   只挑与需求相关的，不搬流水账。会话很长、或要把会话保存下来交给其他
   agent 时，先按 [[context-layering]] 分层组织（旧对话结构化摘要 + 最近
   对话逐字保留），再挑。
2. **提炼用户需求**：把用户散落的表述收敛成一句明确的目标 + 验收标准；
   有歧义的先向用户确认，不要把猜测提交出去。
3. **打包提交**：写成自包含任务文本（模板见 [[submit-workflow]]），投给目标目录：

```bash
# 提交到目标目录的队列（务必加 --json；--cwd 是接收方 agent 的工作目录）
nx-kv localtask add "<任务文本>" --cwd "<目标工作目录>" --json

# 可选：顺带刷新该目录主题的现状展示（目标目录 agent 领取时会看到）
nx-kv localtask add "<任务文本>" --cwd "<目标目录>" --summary "<该目录当前现状>" --json

# 不限定接收方、谁闲谁领 → 推到全局任务池（--cwd 被忽略）：
# 任何目录的 agent 在本地队列空时都会自动领取（返回 source:"global"）
nx-kv localtask add --global "<任务文本>" --json

# 带时间目标（可选）：领取即计时，未到点不许标记完成
nx-kv localtask add "<任务文本>" --cwd "<目标工作目录>" --duration 2h --goal-prompt "<附加要求>" --json
```

返回 `{status:"ok", task:{id,text,...}, queued|delivered}`：

- `queued:true`（跨进程提交的常态）→ 已入队；目标目录里正在 wait 的 agent
  会在约 0.5 秒内取走，没人等就排在队列里等它下次领取。`--global` 提交则排在
  全局任务池，任何目录空闲的 agent 自动领取。
- 记下 `task.id`（主题内 `seq`），向用户报告「已提交到哪个目录（或全局池）、第几号任务」。

## 用户看完结果要改 → 重开那条任务

任务被领走、干完（`localtask done`）之后，用户提了修改意见——**那条任务要重开**，
否则 agent 看不到新一轮的诉求（已领取的任务不会再被派发）：

```bash
nx-kv localtask reopen --id <n> --text "<改后的正文（Markdown）>" --json
```

重开 = 回到待领取 + 领取时间作废（新一轮重新计时），上一轮的完成总结保留。
`--text` 不给则只重开、不改正文。重开的细节见 kv-get skill。

## 任务文本怎么写（一句话版）

接收方没有你的上下文，任务文本按这个顺序组织成一段（单行，用 ①②③ 编号，
总长 ≤20000 字）：

> 目标：做什么、做到什么程度算完成。
> 背景：相关文件/目录路径、已确定的技术决策、必须遵守的约束。
> 注意：不要做什么、有哪些坑（如果有的话）。

细节模板、多任务拆分、提交后的跟踪，读 [[submit-workflow]]。

## 硬规则

1. **`--cwd` 必须填接收方 agent 实际所在的目录**（完整 cwd + 项目组派生主题
   key；不同目录即使同名也不共用队列）。填错了任务就排到了没人看的队列——
   不确定就先问用户。**不限定接收方**的通用任务才走 `--global`（无需 cwd）。
2. **任务文本自包含**：不写「如上所述」「刚才那个」，不引用本对话；路径写全。
3. **提交前把提炼结果给用户过目**（尤其需求是提炼出来的而非用户原话时），
   确认后再 `add`。
4. **大需求拆成多条按序提交**，每条一个可独立完成的单元；顺序重要时提交后用
   `localtask reorder` 校正优先级。**全局池不保顺序**——「先做 A 再做 B」这类
   有依赖的步骤必须 `--cwd` 指名提交到同一目录队列，不要进池子。

## 什么时候不用

| 场景 | 用哪个 |
| --- | --- |
| 你自己干完活、等用户回填下一条 | kv-get（wait / done / reopen） |
| 主动领取排给**本目录**的任务 | kv-get（get） |
| 查 nx-kv 的本机命令手册（任务 / 附件 / 文档） | nx-kv（核心 skill） |
| 给**正在等待**的 agent 补一条任务 | 本 skill（add 到它的目录） |
| 不限定接收方、让任何空闲 agent 自取 | 本 skill（`add --global` 推全局任务池） |

## 与其它 skill 的分工

三者共享同一份本机任务存储与按目录划分的主题（SQLite：`~/.nx-kv/nxkv.db`，schema v4）：

- **kv-submit（本 skill）**：提交侧——总结上下文、提炼需求、投递到别的目录。
- **kv-get**：领取侧——目标目录的 agent 领活（get）、等人接力（wait）、标完成（done）、按反馈重开（reopen）。
- **nx-kv**：本机命令手册——任务队列、附件、文档库、本机仓库（纯本机，无需登录），是另外两个 skill 的底层命令来源。

## 安装

```bash
nx-kv skill install kv-submit         # 装到 ~/.claude/skills/kv-submit
nx-kv skill list                       # 列出 nx-kv / kv-get / kv-submit / kv-repo
```
