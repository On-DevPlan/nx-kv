# A04 · 阻塞等待与时间目标

## 三步

1. 本轮干完、要等用户回填 → `localtask get --timeout N`（N 秒，最大 600）。
2. 返回任务就接着干；返回 `timeout` 就收尾（业务结果，不是失败）。
3. 任务带时间目标时，每轮先 `timegoal check`，`reached:true` 后才允许 done。

## 阻塞等人回填 —— 只有一条路：`get --timeout`

```bash
nx-kv localtask get --timeout 60 --json      # 没活就阻塞最多 60 秒，有活立即返回
```

- 显式给 `--timeout` 时**即使项目没开「持续 get」也会阻塞**（旧的 `localtask wait` 能力已并入 get，
  wait 子命令只是兼容别名，**不要再写进流程**）。
- 这是**本轮最后一步**：拿到任务或超时之前不要提前结束本轮。
- 返回 `{ status:"timeout" }` 是正常出口（exit 0），不是失败。
- 同一目录同一时刻只挂一个等待；`get` 之间不要并发。

### 项目级「持续 get」（可省掉 --timeout）

项目打开 `repo update <id> --get-loop on [--get-loop-minutes N]` 后：

- `get` 无任务时自动阻塞到配置窗口（默认 10 分钟；配 `0` = 不阻塞，立即返回）；
- 交付文本自带「完成后再 get」的指令段（文案在 设置 → 提示词模板 → 持续 get，可改）。

## 时间目标：领取即计时

```bash
nx-kv localtask add "长任务" --duration 2h --goal-prompt "先写测试" --json
# 已存在但未领取的任务也可以补/改时间目标：
nx-kv localtask update --id <n> --duration 90m --goal-prompt "…" --json
nx-kv localtask update --id <n> --clear-goal --json
```

领取即起表，交付里带：

```bash
nx-kv timegoal check --task task:<topicKey>:<taskId> --summary "<本轮现状>"
```

每轮推进先跑一次 check（原文回显提示词，防长对话漂移）。未到点 `done` 返回
`blocked / goal_not_reached` → 派 sub agent 重提需求，`reached:true` 后再 done。

目录级预算是另一回事（和单条任务无关）：

```bash
nx-kv timegoal set --cwd "<目录>" --duration 8h --prompt "本轮整体目标" --json
nx-kv timegoal show --cwd "<目录>" --json     # 查看（list / log / update / clear / prune 同理）
```

## 偏差

| 偏差 | 正确做法 |
| --- | --- |
| 还在写 `localtask wait` | 用 `get --timeout N`（wait 只是兼容别名） |
| 把 timeout 当失败、重试 | 收尾，等用户回填 |
| 等的时候提前结束本轮 | 等待是最后一步 |
| 用 `sleep` / 自己算时间 | 阻塞交给 CLI，不要自己睡 |
