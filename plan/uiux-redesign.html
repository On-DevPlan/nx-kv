目标：用「侧边栏 + 目录全屏工作台 + 本地/云端任务并列」替换现有「顶栏 + 平铺 tab」。 本页上半部分是可操作原型，下半部分是设计说明。单文件自包含，无外部资源。

1 · 信息架构（v1 → v2）

现有壳是「顶栏 + 4 个平铺 tab（本地任务/清单/仓库/登录）+ hash 路由」；目录（topic）只是本地任务看板里的一行。 v2 把目录提升为一级导航：侧边栏即项目目录清单，详情页即该目录的全部任务工作台。

v1（现状）v2（本稿）说明
本地任务 tab：所有目录一张看板侧边栏目录 → 点开 = 目录详情全屏看板（#/dir/<key>）；全局池 = 独立全屏视图；跨目录视角 = 全部目录总览目录维度聚合本机队列 + 云端清单；全局池（__GLOBAL__）恒顶在侧边栏首行，点开是共享池看板，卡片菜单可「投放到目录…」固定归属；旧 tab 的跨目录用途由「全部目录总览」接管
清单 tab：远程 KV todo（按 groupId）并入目录详情的「云端清单」栏；侧边栏底部保留「云端总览」入口云端任务按 topic 字段映射到目录；总览页看跨目录全量
仓库 tab侧边栏底部「仓库管理」入口（低频，不占一级）仓库/看板绑定/克隆同步是配置型操作
登录 tab侧边栏底部状态行；云端栏未登录时给就地登录 CTA登录态只影响云端栏
IA 树：侧边栏 = 全局任务(恒顶) + 分组→目录（可拖拽编排）｜底部 = 云端总览 · 仓库管理 · 设置/登录｜主区 = 目录详情（默认）或全局页。

2 · 导航逻辑

  • 进入目录详情 = 默认全屏 + 侧边栏收起（收起为 52px 图标 rail，徽标仍在）。rail 悬停气泡显示名称；点 rail 图标 = 展开并定位该目录。
  • 返回：详情左上 ←，或 Esc —— 展开侧边栏并停在前一个位置。全局任务池同样是全屏工作台（点开即收起侧边栏）。
  • 两条「默认收起」设置（沿用 nx-ft 侧边栏设置模式，跨视图共享一份偏好）：侧边栏默认收起（进入面板初值）、分组默认收起（分组的初始展开态）。展开/选中记忆按各自存储 key 持久化。
  • 路由沿用 hash：#/dir/<key> 为目录详情、#/global 全局任务池、#/overview 全部目录总览、#/cloud 云端总览、#/repos 仓库管理——深链直达时按 chainByKey 思路自动展开沿途分组。

3 · 侧边栏规范

  • 结构：头部（品牌 + 搜索 + ＋添加 + 设置 + 收起把手）／树（全局任务恒顶 → 分组 → 目录行）／底部（云端总览、仓库管理、设置·登录）。
  • 行内容：目录行 = 名称 + 待领取数徽标 + 等待回填琥珀点 + 悬停 ⋯；分组行 = 折叠箭头 + 名称 + 计数。
  • 拖拽编排（吸收 nx-ft 三段式落点）： 行上缘 30% = 排到它前面（before 线）、下缘 30% = 排到它后面（after 线）、中段 = 移入该分组（into 描边，仅分组行接受）；目录行中段不作落点（没有「目录套目录」），不给假提示。 canDropInto 守卫：不能放进自己的子树；树空白处 = 拖到末尾（tail）。顺序持久化到偏好存储。
  • 搜索：按名称/路径/现状摘要过滤；任一后代命中则分组强制展开（不污染用户自己的展开记忆）；搜索框旁给出「N 个匹配」计数——搜不到时用户能立刻分辨「没有匹配」和「搜索坏了」。
  • 行菜单（⋯ 或右键）：打开详情 / 置顶 / 重命名 / 移动到分组… / 从侧边栏移除（不删数据）。菜单由侧边栏统一渲染一份（行上不各自挂浮层），点外/⟲Esc 关。
  • 键盘：↑↓ 在可见行间移动焦点（可见序 = 渲染序，同一份扁平序）、Enter 打开、Esc 关菜单/返回。

4 · 目录详情与看板

  • 顶栏：← + 目录名 + 路径（mono）+ 现状摘要（summary）+ 等待徽标 + 动作（＋新任务等）。
  • 本机队列列（字段即真实模型）：待领取（status:pending 且无 deletedAt，正序 = 领取优先级，列内可拖拽排序——对应 nx-kv localtask reorder）｜进行中（topic.waiting=true 时出现：回填等待卡 + waitingUntil 实时倒计时）｜已领取（consumed，倒序，卡片带 roundSummary）｜归档（软删 deletedAt，默认折叠，可恢复/彻底删）。迁出记录内联回它原来所在的那一列。
  • 云端清单列：待办（open）｜已完成（done，带完成结果）｜冻结（freeze）。按 topic === 目录名 过滤，可切「全部」。
  • 卡片解剖：任务文本（默认 4 行截断，超长时给「展开全文 / 收起」，悬停 title 始终保留全文）+ meta 行（#id、创建时间、来源徽标、迁移徽标）+ roundSummary 块；右上角只留一个 ⋯，其余操作进菜单（与侧边栏行菜单同构）。
  • 空态：本机空 =「队列为空，投一条任务或从云端迁入」；云端未登录 =「云端清单需登录」＋ 就地登录按钮；云端已登录但该目录无任务 =「云端暂无此目录的任务」。
  • 等待回填闭环：「进行中」列的回填卡点「去回填」→ 输入回执 → 写入该任务 roundSummary 并解除 waiting（agent 可继续）。这是本机队列的人机接力口，必须闭环，不能只给提示。
  • 现状摘要可编辑：顶栏那一句 summary 点击即改（真实实现走 localtask add --summary），它是「这个目录现在什么状况」的唯一出处。

5 · 本地 ⇄ 云端迁移（并列关系）

心智模型：本机队列 = 本机（这台机器的 agent 队列）；云端清单 = 云主机（跨机器共享的工作空间，按 groupId）。 两者是同一目录的并列任务来源，任务可以在之间迁移，就像把工作从本地机器挪到云主机。

1发起三个入口：拖卡片跨栏 / 卡片 ⋯→迁移到云端(本机) / 列头 ⋯→批量迁移。
2确认对话框写清映射：源 → 目标（text 原样带过去，云端 topic=目录名 / bucket=open；本机则新增到待领取首位）。目标端已有同内容 ×N 时列出并可选「合并到已有条目」。拖拽落点即确认，不弹此框。
3执行本机：localtask 原条目标记迁出（tombstone）；云端：todo add 新条目（徽标「来自本机」）。反向对称。
4回执toast 告知 + 撤销；tombstone 卡保留跳转/删除入口，让「任务去哪了」永远可追溯。
  • Tombstone 规则：迁移不物理删除——原位置留虚线灰卡「已迁移 → 云端清单 · 时间」，内联在它迁移前所在的那一列，可 ⇥ 跳到目标或 ✕ 移除；云端侧卡片带来源徽标。保证两侧历史都对得上。
  • 同内容规则：清单页允许同内容并存（同内容×N），所以迁移到目标端若已有同内容，确认框会把它们列出来；本机→云端可选择「合并（不新增）」，云端→本机默认追加一条并带来源标记，避免悄悄吞掉一条。
  • 未登录态：云端栏显示登录 CTA；迁移入口置灰并说明原因。
  • 失败与原子性：迁移遵循「先写目标端、成功才改源端」——目标端不可达时源端保持原样（不产生迁出记录），任务留在原地可重试；同时云端栏整体进入错误态并说明「本机队列不受影响」，避免用户误以为任务丢了。
  • 落地注意：现阶段迁移 = 面板侧组合既有命令（localtask 删除/标记 + todo add），非原子；后续可加 nx-kv task move 同构 CLI 命令（面板每个按钮都有同构 CLI 是本仓库约定）。

--danger破坏性
  • 侧边栏展开 264px / rail 52px；列宽 216px；圆角 8/5；字号 13 基准、11 meta。
  • 本机栏用纸底、云端栏顶部一层 --cloud-bg 渐变区分；语义色只出现在徽标/描边/空态，不做大面积色块。

7.3 API 与 CLI 契约

动作面板 API同构 CLI（面板每个按钮都有同构命令是本仓库约定）
读本机队列GET /api/localtasks（已有）nx-kv localtask list（已有）
读/写云端清单/api/todo/*（已有）nx-kv todo *（已有）
迁移POST /api/task/move（新增）body：{from:'local'|'cloud', dirKey?, id?, topic?, text, to:'local'|'cloud', merge?} → 返回 {ok, targetId, tombstoneId}nx-kv task move --to cloud --cwd <dir> --id <n> / nx-kv task move --to local --topic <dir> --text <text>
撤销迁移POST /api/task/move --undo（同一端点的反向参数）nx-kv task move --undo --id <n>
回填复用现有 wait 通道nx-kv localtask wait（已有）
调整领取优先级拖拽排序落到既有 reorder 接口nx-kv localtask reorder --id <n> --beforeId/--afterId（已有）

原子性做法：/api/task/move 在一次请求里完成「先写目标端、成功才改源端」——目标端写失败就直接返回错误，源端不动、不留迁出记录；成功后再把源端标成 migratedTo。撤销 = 带 --undo 的反向 move（目标端那条按返回的 targetId 精确删，不按文本匹配——同内容 ×N 时按文本删会误伤）。
