# B01 · 概念与寻址

## 词表

| 词 | 含义 |
| --- | --- |
| **主题 topic** | 「工作目录 cwd + 项目组」派生出的一个队列；`--cwd` / `--key` 定位，缺省取进程当前目录 |
| **任务 task** | 主题内的一条活，用 `id`（即 seq，主题内自增）寻址 |
| **项目组 board** | 领域分组（CLI 命令名就叫 `board`）；一个仓库可归多组，这是唯一的分组路径（没有标签） |
| **仓库 repo** | 本机登记的一行事实：name/path/desc/type/remote + 全局唯一 `key` |
| **参考仓库 ref repo** | `type=ref` 的仓库：远程 clone 下来的，统一放 gitRepoRoot，用于「看别人怎么实现」 |
| **文档库 refs** | 库内文档 = 正文 + 归属（仓库 / 组 / 组内某仓库）+ 一行 desc；`refId` 形如 `ref_<16hex>` |
| **附件 attachment** | 落在本机附件仓的文件，正文里以 `fileId` 引用，读的是本地绝对路径 |

## 寻址规则

- 主题内任务：`--id <n>`；
- 跨主题引用：`"<topicKey>:<id>"`（DAG 依赖 `--block-by`、任务链等）；
- 仓库 / 组：`id`、`key`、绝对路径、名字 都能定位（定位顺序 id → key → 路径 → 名字）；
- 文档：只认 `refId`（`ref:<id>` 或裸 id）——**ref 不是文件，没有路径**；
  「读文件」只有附件，「读文档」一律 `docs get --ref`。

## 主题是怎么派生的（为什么「任务不在这个队列」）

主题 key = 由**完整 cwd + 项目组**派生。所以：

- 同一个项目在两个目录下 = 两个队列，互相看不到；
- `--cwd` 填错（例如填了自己的目录）→ 任务排进没人看的队列；
- 面板与 CLI 读同一份 SQLite（`~/.nx-kv/nxkv.db`），不存在「同步」动作。

## 数据在哪

- 任务 / 主题 / 文档 / 仓库登记 / 附件索引：SQLite `~/.nx-kv/nxkv.db`
- 附件实体与文档导出目录：`~/.nx-kv/`（详见 `nx-kv health`）
- 全部本机，不需要登录，不访问任何后端。
