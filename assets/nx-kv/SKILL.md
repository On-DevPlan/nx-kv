# nx-kv — 本机任务队列 + 仓库上下文

本 skill **只讲怎么用**（不讲怎么开发）。分两个序列：

| 序列 | 是什么 | 何时读 |
| --- | --- | --- |
| **A（SOP）** | 5 个**专项**场景的标准动作，照着做就行 | **先看 A**——绝大多数请求都在这 |
| **B（知识）** | 概念 / 寻址 / CLI 参数 / 数据结构 | **只有 A 覆盖不到**时才翻 |

## 一句话定调（三条硬规矩）

1. **领活的标准动作是 `localtask get`**——它把任务正文、项目组上下文、附件本地路径、
   收尾要求都封装好了。**不要**先 `localtask list` / `show` 翻一遍再决定要不要领。
2. **`timeout` 是业务结果不是错误**（exit 0）：说明暂时没活，收尾即可，别重试。
3. **读交付内容不要用 `--json`**：交付的 `instruction` 是引擎封装好的 context 原文，
   JSON 会把它转义成一行。默认输出就是逐字原文。

## A 序列：5 个专项场景

| 你要做的事 | 动作（一句话） | ref |
| --- | --- | --- |
| **① 领取任务**（领 → 读 → 干 → 回填 → 按反馈派生下一轮） | `nx-kv localtask get`（默认输出即逐字 context） | [[A01-领取任务]] |
| **② 提交任务**（把上下文 + 工程知识 + 关键路径写成自包含任务） | 提炼 → 写文件 → `localtask add --file … --cwd …` | [[A02-提交任务]] |
| **③ 文档（ref）管理**（三层宿主、可绑定列表、写一篇能照做的安装文档） | `docs ref add` / `docs bind` / `docs link` | [[A03-文档与归属]] |
| **④ 仓库与项目组管理**（远程仓库 git 到指定位置、绑定关系） | `setting set --gitRepoRoot` → `repo clone` / `repo ref clone` → `board assign` / `repo bind` | [[A04-仓库与项目组]] |
| **⑤ 任务链成块 + 反馈识别 + 回写 topic 的 ref** | `localtask chain` 认链尖 → 合成现状 → `docs set` / `docs bind` | [[A05-任务链与反馈汇总]] |

> A 序列内部还有常用分支：领指定编号（`show` → `reorder` → `get`）、阻塞等人回填
> （`get --timeout 60`）、时间目标（`timegoal check`）、完成回填（`done --summary`）、
> 用户提意见（`reopen` 派生下一轮）都在 [[A01-领取任务]] 里。

## 边界

- git 的状态 / diff / push 一律用 git 自己，不经过本 skill（`repo ref sync` 只做 ff-only 同步）。
- 全部数据在本机 SQLite（`~/.nx-kv/nxkv.db`），**不需要登录、不访问后端**。
- 面板上的操作（拖拽布局、点菜单、编排工具栏）不在本 skill 范围——本 skill 只讲 CLI 与数据口径。
