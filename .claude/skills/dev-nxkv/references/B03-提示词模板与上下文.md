## 一、交付 = 一份共享 ctx × 八个段落

```
compose({ plugins, orderIds, seed, mode })
  └─ orderIds = resolveOrderIds(plugins, settings['prompt.pluginOrder'])
     ├─ 第一趟：按序 Object.assign(ctx, await plugin.get('data'))   # 段级键互斥由 assertPluginList 保证
     ├─ 第二趟：按序 renderInstruction(plugin.get(), ctx)           # 模板 trim 为空 → 该段不出
     └─ mode='xml' 包 <nx-kv.xxx> 标签；mode='plain' 直接拼文本
```

| 段落 id | 标签 | 内容 | 何时出现 | 写回 ctx |
|---|---|---|---|---|
| `context` | `<nx-kv.context>` | 仓库 / 组 / 参考仓库 / 其余组 | 登记了仓库就有（组材料只进组任务） | `repo` `group` `refRepos` `groups` |
| `attachment` | `<nx-kv.attachment>` | 附件清单 + 取用方式 + 文档原文 | 任务带附件时 | `attach` |
| `timecheck` | `<nx-kv.timecheck>` | 时间目标检查指令 | 带时间目标时 | 只读（`writes=[]`） |
| `goalhint` | `<nx-kv.goalhint>` | 时间目标上下文（可算的秒数/人话） | 带时间目标时 | 只读 |
| `doneguard` | `<nx-kv.doneguard>` | 未到点不许 done 的拦截文案 | 只在 done 被拦截时出现 | 只读 |
| `ext` | `<nx-kv.ext>` | 同主题还有多少待领取 | 队列非空时 | `ext` |
| `ack` | `<nx-kv.ack>` | 完成回填指令 | 总有 | 只读 |
| `getloop` | `<nx-kv.getloop>` | 持续 get 指令 | 项目开了持续 get | `getloop` |

代码：类在 `src/modules/promptplug/plugins/`（`context.ts` / `attachment.ts` / `readonly-blocks.ts` /
`ext.ts` / `getloop.ts`），基类 `base.ts`，编排 `compose.ts`，装配 `factory.ts`。

> **只读段不是「无变量」**：`writes=[]` 只表示不回写 ctx；`dataSchema` 仍声明了
> `goal.*` / `task.*` 作为模板可见变量（`readonly-blocks.ts` 四个类都如此）。

## 二、ctx 从哪来（seed + 各段 data()）

| ctx 片段 | 来源 | 主要字段 |
|---|---|---|
| `task` | compose 的 **seed**（`wait.ts` 组） | `id` / `text`（交付前重排：最新轮置顶） |
| `cwd` / `source` / `summary` / `name` / `params` | seed | `params` 是**平面扩展**（`{{k}}` 或 `{{params.k}}`），内建键不被覆盖 |
| `goal` | seed（`wait.ts` + timegoal 插件算出人话字段） | `goalKey` / `durationHuman` / `remainingSec` / `check` / `statusLine` / `extra` |
| `repo` / `group` / `refRepos` / `groups` | `context` 插件的 `data()`（内部调 `deliveryCtxOf`） | `intro` / `docs` / `desc` / `peers` / `refRepos` / `note` |
| `attach` | `attachment` 插件的 `data()`（宿主用 `attachTemplateCtx` 构造后注入） | `count` / `inlineCount` / `areaCount` / `list[]`（按 kind 给子对象） |
| `ext` | `ext` 插件的 `data()`（宿主用 `pendingQueueInfo` 取，失败 → null） | `topic` / `count` / `list[]` |
| `getloop` | `getloop` 插件的 `data()`（宿主先渲染项目级收尾指令） | `text` / `waitMinutes` |

**规矩**：ctx 只放**数据**，成文措辞归模板；服务端不拼多行文本（列表一律结构化，模板自己 `{{#each}}` 组织行）。

## 三、模板语法与 helper

- 区块：`{{#if x}}…{{else}}…{{/if}}`、`{{#each list}}…{{/each}}`；
  **旧语法 `{{#section}}` / 反向区块 `{{^x}}` 已废弃**（保存时会被 `validateTemplate` 拒）。
- 占位符：`{{a.b.c}}`；未知变量**渲染成空串、不报错** → 只能靠 `localtask preview` 看结果。
- helper（`TEMPLATE_HELPERS`，共 25 个）：
  `eq ne gt gte lt lte between`（比较）、`and or not`（逻辑）、
  `add sub mul div mod round floor ceil percent ratio clamp`（数值）、
  `includes length default`（字符串）、`formatDuration`（秒→人话）。
  helper 自身异常会退化成可见兜底，不拖垮整份渲染。

## 四、模板存哪、谁能用

**提示词段落模板**：settings 表键 `lt.blockTemplates`，形状 `{ [segId]: { active, list } }`，
`list` 条目 `{ id, name, template, builtin }`。

| 概念 | 落点 | 说明 |
|---|---|---|
| 出厂快照 | `src/modules/promptplug/Template/blockTemplates.json` | 代码里**没有** `DEFAULT_*` 模板常量；正文唯一真相是这个 JSON |
| 首启/升级落库 | `ensure.ts`（`BUNDLE_VERSION` 落后才写） | 只刷 builtin 文本；用户条目、`active`、`list` 顺序不动 |
| 内置不可改 | `localtask/repo/settings.ts` 的 `setLtSettings` | 写路径把 patch 里的 builtin 条目**替换回库内现值**（不是靠前端禁用） |
| 生效项 | `active` 指向本条 `list` 里的 id | 指向空模板 = 配置错误，`ensure` 会自愈回 builtin |
| 顺序 | settings 键 `prompt.pluginOrder` | 数组：**恰含全部段落 id 各一次**；运行期 order 位 = 下标 × 10 |

> 另一个「templates 表（category / vars_schema / scope…）」是**任务模板**体系
> （新建任务正文骨架、增强模板等），与提示词段落模板不是同一份数据，别混。

## 五、变量知识化：只有一份

| 位置 | 作用 | 谁维护 |
|---|---|---|
| 各插件的 `dataSchema`（zod `strictObject`） | ctx 形状 + 变量目录的唯一声明 | 改 ctx 的人 |
| `GET /api/prompt/registry` 的 `fields`（`schema-bridge` → `uiDescriptor` 派生） | 设置面板「可使用参数」、CLI/HTTP 校验、模板白名单同源 | 自动 |

> 没有第二份手写表（旧 `page/settings/prompt-template-params.ts` 已随 S3 删除）。
> 新增变量只改 `dataSchema` + `data()`，前端自动出现。

## 六、失败时的行为（不静默）

| 情况 | 行为 |
|---|---|
| 模板语法错 / 旧语法 | `validateTemplate` 拒绝**保存**；存量脏数据由 `ensure` 自愈回 builtin |
| 生效模板被清空 | 保存被拒（S1 起空模板是配置错误，不是「该段关闭」的手段） |
| `data()` 返回与 schema 不符 | `get('data')` 的 safeParse 抛错（`<id>: data() 返回与 schema 不符——…`）→ **整次交付失败** |
| 渲染抛错 | 同上，**不回落内置、不给空串**（静默降级比失败更贵，方案 §6） |
| 变量名写错 | **静默渲染成空**（Handlebars 语义）——只能靠 `preview` 发现 |
| 段落数据为空 | 该段整个不输出（`null` 段 / 模板 trim 为空）；不闸就会印空标签（`组定位：`这种） |

排查入口：`node bin/kv.mjs localtask preview --id <id>`（零副作用，能看到分段与告警）。
