# v20：删除旧任务模板表

- date: 2026-11-27
- version: 20
- migration: `src/core/db/migrations/v20.sql`（仅注释）+ `v20-data.ts`
- tables: 删除 templates
- producers: src/core/db/migrations/v20-data.ts
- consumers: src/modules/plugin/repo/legacy.ts、packages/plugin-task-template/src/server/templates.ts

## 背景

v19 已把旧 `templates` 的用户行暂存到 `plugin_legacy_data`，并建立插件宿主表。旧内置实现（`src/modules/templates`、`seed-templates.ts`、宿主前端模板页）已经删除；任务模板由 `packages/plugin-task-template` 接管。

## 决策

v20 删除 `templates` 表：

1. `v20.sql` 只放注释，不做 DDL/DML——`migrator` 先执行 SQL 再调用 `v20-data.ts`，若在 SQL 里 DROP 会早于补拷。
2. `v20-data.ts` 先补拷 `templates` 中尚未进入 staging 的 `builtin=0` 用户行（按模板 id 合并），再 `DROP TABLE templates`。
3. `plugin_legacy_data` 保留到 task-template 插件首次激活完成导入；导入按模板 id 幂等，成功后宿主删除对应 staging 行。
4. 升级前 `bootstrap.ts` 的 `VACUUM INTO` 备份仍是唯一回滚依据；备份失败则中止升级。

## 口径

- 旧内置模板（`builtin=1`）不迁移，内置正文由插件包 `src/server/builtin-body.ts` 声明。
- 旧 `scope` 原样保存在插件表，由插件内部过滤；宿主 UI 不再暴露旧 scope 概念。
- 入口 id 稳定：内置 `task-template:ref`；用户模板 `task-template:<旧 id>`，避免草稿/可见性引用漂移。

## 被否决

- 保留 `templates` 表作历史归档：会让宿主同时存在两套模板数据结构，插件边界失效。
- 在 v19 里一次性 DROP：v19 与 v20 之间旧代码仍可能写入，会丢最后一刻的用户模板。
