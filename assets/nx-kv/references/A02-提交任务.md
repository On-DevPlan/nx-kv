# A02 · 提交任务（把本对话的需求交给别的目录）

你发的是**任务**，不是对话记录——接收方看不到本对话，文本必须自己站得住。

## 四步

1. **总结上下文**：聊了什么、定了什么决策、涉及哪些文件/路径/约定。只挑与需求相关的，
不搬流水账。会话很长要做整体交接时，先分层（旧对话给结构化摘要 + 最近对话逐字保留）。

2. **提炼需求**：目标一句 + 验收标准 + 约束。有歧义**先问用户**；提炼出来的表述
（非用户原话）**先给用户过目**再提交。

3. **写成自包含任务文本**（单段，①②③ 编号，≤20000 字）：

```
① 目标：做什么、做到什么程度算完成
② 背景：相关文件/目录（写全路径）、已定的技术决策、必须遵守的约束
③ 注意：不要做什么、有哪些坑
```

4. **投递**

```bash
# 投到目标目录的队列（--cwd = 接收方 agent 的工作目录，不是你的）
nx-kv localtask add "<任务文本>" --cwd "<目标目录>" --json

# 顺带刷新该目录的现状展示（接收方领取时会看到）
nx-kv localtask add "<任务文本>" --cwd "<目标目录>" --summary "<该目录现状>" --json

# 不限定接收方 → 全局池（忽略 --cwd，谁闲谁领，返回 source:"global"）
nx-kv localtask add --global "<任务文本>" --json

# 带时间目标：领取即计时，未到点不许标完成
nx-kv localtask add "<任务文本>" --cwd "<目标目录>" --duration 2h --goal-prompt "<附加要求>" --json
```

返回 `{ status:"ok", task:{id,…}, queued|delivered }`。`queued:true` = 已入队：目标目录
正在 wait/get 的 agent 约 0.5 秒内取走，没人等就排队。**记下 `task.id`**，向用户报告
「已提交到哪个目录（或全局池）、第几号」。

## 用户看完结果要改 → 重开，不要新开

```bash
nx-kv localtask reopen --id <n> --text "<改后的正文>" --json
```

已领取/已完成的任务不会再被派发；不重开就等于需求没提。细则见 [[A03-完成与重开]]。

## 偏差

| 偏差 | 正确做法 |
| --- | --- |
| `--cwd` 填成自己的目录 | 填**接收方**目录；主题按「完整 cwd + 项目组」派生，同名目录也不共用队列 |
| 任务文本写「如上所述」「刚才那个」 | 自包含：路径写全、不引用本对话 |
| 大需求塞成一条 | 拆成多条可独立完成的单元；顺序重要时 `reorder` 校正 |
| 有依赖的步骤走 `--global` | 全局池不保顺序，必须 `--cwd` 投到同一目录队列 |
| 提交完自己去 `get` | 那是接收方的事；要跟进等它 `reopen` 回来 |
