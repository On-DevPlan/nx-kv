# A11 · SOP · 校准 dev skill（本手册自己）

> 命中信号：「SOP 里的路径找不到」「这条命令跑不出」「数字过期了」「要加一条新 SOP」。
> 代码是唯一真相。校准的唯一方法：**现读现写**——把 SOP 里的断言逐条对着真实输出核，
> 不确定的一律跑命令，不背旧文档（#201：schema 一天从 8 变 10，写死数字必腐）。

## ① 前置（拿到全部「事实源」）

```powershell
node bin/kv.mjs routes                                      # 命令表（条数以输出为准）
node bin/kv.mjs routes --module <id>                        # 某模块有哪些入口
grep -n CURRENT_SCHEMA_VERSION src/core/db/version.ts       # schema 版本
ls src/core/db/migrations/*.sql                             # 迁移到尾号
ls src/modules/                                             # 现存模块（历史模块会被删）
pnpm run                                                    # 全部脚本
git log --oneline -10 -- .claude/skills/dev-nxkv            # 本 skill 最近被谁改过、为什么
```

## ② 判定：什么信号要校准

| 信号 | 动作 |
|---|---|
| SOP 里的路径 `Test-Path` 为假 | 用 `A08-排障与定位.md` 定位新路径，改写那条 SOP |
| SOP 里的命令跑不出 | 对照 `routes` / `pnpm run` 输出改命令 |
| 写死了数字（版本号 / 条数 / 表数） | 改成「跑命令现读」的表达，删掉具体数值 |
| 同一场景反复出现而没有 SOP | 按本文 §③ 加新条目 |
| 触发词跟不上用户的说法 | 改 SKILL.md frontmatter 的 description（触发靠用户原话，不靠自述） |
| 结构性不对（如「按层拆但需求天然跨层，命中率低」） | 重排序列与路由——2026-11-15 改成 A（SOP）+ B（知识）即范例 |

## ③ 动作

1. **改内容**：断言全部可核对（路径存在、命令可解析、数字现读）。
2. **路由同步**：每条 reference 必须被 SKILL.md 的场景表引用（孤儿文件 = lint 失败）；SKILL.md 只做路由，不写知识。
3. **新增条目**：
   - 文件名 `<序列><两位序号>-<动作>.md`，序列只有 `A`（标准 SOP，任务的第一跳）/ `B`（相关知识，被多条 A 引用的查表）；
   - **A 序列**：四段骨架 **① 前置 / ② 动作（或判定）/ 自检 / 失败分支**，至少一条可执行命令；
     判断标准：用户的任务单能**直接命中**它 → 它是 A。
   - **B 序列**：不是动作，是**可查的知识**——至少一张表 + 至少一条 grep / 命令线索；
     判断标准：它只被别的条目**引用**（讲口径、概念、契约、规则、红线）→ 它是 B。
4. **A 与 B 的分工红线**：A 是端到端入口，B 单点维护知识细节——A 里**引用** B，不复制其内容
   （防膨胀：#202 之前本 skill 曾膨胀到 2735 行纯知识，被门禁拦回）。
   **B 里不要贴大段样板代码**：写成「照抄 `src/…/x.ts`」+ 一句口径，样板只留一份真身。

## ④ 自检

```powershell
pnpm check:skill      # 骨架 / 路由↔文件 / 路径存在 / 命令可解析
pnpm lint             # 全量门禁（check-skill-sop 是其中一道）
```

| 检查 | 判据 |
|---|---|
| 骨架完整 | 每条 **A** 都有四段；每条 **B** 都有表 + grep/命令线索 |
| 路由闭合 | 无孤儿、无死链 |
| 路径与命令真实 | lint 输出的核对计数非零且无报错 |

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| lint 报「孤儿文件」 | 新 SOP 没进 SKILL.md 场景表 | 补路由或删文件 |
| lint 报「路径不存在」 | SOP 里写了旧路径 | 定位真实路径改写，别删断言了事 |
| lint 报「命令不存在」 | cli 声明变了或命令拼错 | 对照 `routes` 输出改 |
| lint 报「缺小节」 | A 的四段骨架不全 | 补 ①前置 / 动作 / 自检 / 失败分支 |
| lint 报「不含可执行命令」 | A 写成了知识文档 | 要么改成动作序列（A），要么降级成 B（表 + grep 线索） |
| lint 报「没有一张表」 | B 写成了散文 | 改成可查的表（口径 / 定位 / 症状对照） |
| lint 报「没有 grep / 命令线索」 | B 没说怎么找到它 | 补「查它用这几条」的命令块 |

## ⑥ 反模式

- 往 **A** 序列塞纯知识（没有动作序列 = 门禁会拦）；知识归 **B**，且要可查。
- 把「怎么改代码」写进 `assets/nx-kv/`（那是给使用者的说明书；两边职责见 `A07-发版.md`）。
- 凭记忆写路径与数字。
- 重排结构时顺手删掉已校准的断言（结构与内容是两回事，分开动）。
