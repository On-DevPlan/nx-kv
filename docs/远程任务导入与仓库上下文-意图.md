## 簇 A · 本地任务从远程导入（远程 #73 + #74）

### A1 — 导入入口与子弹窗（#73）

- 面板的**全局任务池**（看板里的「全局任务」行）与**队列面板**（主题队列上方）各加一个
  「从远程导入」按钮。
- 点开 → **子弹窗**：
  - 列出远程**当前工作空间**的全部未完成任务（`todo:open`）；
  - 顶部一个**主题筛选**下拉（远程 `todo:topics`），默认「全部主题」；
  - 每条一个**勾选框**（单条勾选，默认不勾），让用户自己安排要导哪几条；
  - 底部「导入 N 条」。
- 导入去向：当前打开的队列（主题队列）或**全局池**（在全局池那一行点导入时）。

### A2 — 导入完成即回填远程（#74）

- 导入成功后，把远程那几条**标记为已完成**（`todo:done`），note 里写明「被本地哪个队列领走了」。
- 本地给出提示：**「本地的某一个队列领取了这个任务」**（带队列名与条数）。
- 顺序：**先落本地，再标远程完成**。反过来会丢任务（远程已完成、本地没加上）。

### 边界

- 远程不可达 / 未登录 → 弹窗里明说原因，不静默失败。
- 远程那条找不到（被别的 agent 领走了）→ 该条如实报「远程已不存在」，其余照导。
- 导入**不删**远程任务（只标完成）——远程的历史仍然可查。
- 一条远程任务只导一次；已完成的远程任务不会出现在列表里。

## 簇 B · 仓库上下文从 nx-rh 迁到 nx-kv（远程 #72）

### B1 — 仓库上下文成为本地任务管理的上下文

- nx-kv 新增**仓库上下文**模块（本地 store，`~/.nx-kv/repos.json`）：
  - `repos`：仓库登记（name / path / tags / desc / notes）——从 nx-rh 原样迁 15 条；
  - `boards`：看板 ↔ 仓库归属（有序）——从 nx-rh 原样迁 4 块（nx系列 / fr常用 / 远程打字 / 完整测试）。
- **用起来**（这才是目的，不是单纯搬家）：
  - 本地任务的**主题视图**带上匹配到的仓库上下文（目录路径对得上已登记仓库时）；
  - `localtask wait` 返回时**一并带上**仓库上下文 → agent 领到任务就知道它属于哪个仓库、
    有哪些标签与描述、周围关联着哪些看板；
  - 面板上目录行显示仓库上下文（名字 / 标签 / 所属看板 = 周围联系）。

### B2 — 删掉 nx-rh 的仓库模块

- 删 `nx-rh/src/modules/repos/`（service / boards / index / view 全部）；
- `runtime/registry.js` 注销它的命令；
- `modules/system/index.js` 的总览里去掉 `repos` 字段；
- store 的 `repos` / `boards` 字段清掉（数据已迁走，字段不再有意义）；
- **数据先迁走再删代码**（顺序不能反）。

### 边界

- 仓库路径是**本机事实** → 落本地，不上远程 KV（已确认）。
- nx-rh 保留 worktrees / skills / env / settings；**worktrees 与 skills 不依赖 repos**（已核实）。
- 仓库 id 保持不变 → 看板的 `repoIds` 引用不用改。
