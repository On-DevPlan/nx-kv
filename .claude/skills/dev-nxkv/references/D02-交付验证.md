# D02 · 跨层 · 交付验证

> 序列 D（跨层）。只认跑出来的结果。「应该没问题」不算证据；汇报要贴命令与关键输出。

## ① 前置（确认此刻的基线）

```powershell
git status --short                 # 有哪些文件被改（并行会话可能也有改动）
git branch --show-current
git log --oneline -3
node bin/kv.mjs db status          # 动过库才跑：确认库版本与路径
```

记下这三样：改了哪些文件、当前分支、基线提交。后面汇报要用，排查「改动没生效」也靠它。

## ② 动作：按顺序跑固定检查项

```powershell
pnpm lint          # eslint + check-tdz --all + check-schema-decisions + check-lines + check-skill-sop
pnpm typecheck     # pnpm gen + tsc -b（strict，node + web 两套）
pnpm test:unit     # tests/unit/*.test.mjs
pnpm test:smoke    # tests/smoke.mjs（假后端 + 临时配置）
pnpm build         # gen + tsc + vite build + link-local
pnpm test          # 上面全部合一（最终以它为准）
```

- `pnpm lint` 是五道门禁的合体，**任何一道失败 = lint 失败**：
  - `eslint`：分层依赖、页面不裸调 `api()`
  - `check-tdz`：TDZ 全量扫描（视图文件用 `--all` 自动发现）
  - `check-schema-decisions`：每张 `CREATE/DROP TABLE` 必须有 `@decision` 且文件存在
  - `check-lines`：≤500 干净；601–1000 必须登记 `scripts/line-lint-registry.json`（只许降不许升）；>1000 禁止
  - `check-skill-sop`：`pnpm check:skill`（本 skill 的骨架/路由/路径/命令）
- 改了 action 声明 → `pnpm gen` 之后**重启 serve**，否则跑的还是旧路由。

**2.1 按改动面追加**（对应序列）

| 改了什么 | 追加命令 | 对应 SOP |
|---|---|---|
| schema / migration | `pnpm test:db`；`db migrate --dry-run` → `db backup` → `db migrate` → `db verify` | A01 |
| 业务规则 / 事务 | 目标域的 `tests/unit/<域>-*.test.mjs` + 真跑一次命令 | B02 |
| 提示词 / 模板 | `localtask preview --id <id>` + 一次真实 `localtask get`（**默认输出**，别用 `--json` 读原文） | B03 |
| 依赖 / 编排 | `tests/unit/workflow-*.test.mjs` + `localtask chain/list --json` 核对 | B04 |
| 内置技能 | `node bin/kv.mjs skill get <name>` 输出核对 + `pnpm check:skill` | B05 |
| 面板 / 交互 | `pnpm build` 后开 serve 走一遍，带 `?cb=1` 绕缓存；复杂交互用隔离探针 | C01 / C02 |
| CLI 输出格式 | 真跑一次，同时看默认输出与 `--json` 形状 | B01 |

面板改动的最小实测流程：独立 `NX_KV_HOME` / `NX_KV_LOCALTASK_STORE` + 临时端口 `serve --port 7878` + Playwright（`channel:'chrome'`），绝不碰用户真实队列。

## ③ 自检（每条都要有结果，不接受「通过」）

| 项 | 判据 |
|---|---|
| lint | 退出码 0；无 `no-restricted-imports`、无行数超限、无缺 `@decision`、skill 骨架完整 |
| typecheck | 退出码 0；没有新增 `any` 逃逸 |
| test:unit | 全绿；新增行为有对应测试 |
| test:smoke | 全绿。若失败，先在**基线**（`git stash`）复跑同一用例，确认不是本次引入 |
| build | 产物生成；`dist` 里能搜到改动后的字符串 |
| 真实调用 | 命令返回符合预期；错误路径返回结构化错误而不是崩溃 |

## ④ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 只有某一个 smoke 用例失败 | 可能是存量失败 | 基线复跑同一用例；同样失败则记为存量，与本次无关 |
| `check-lines` 报超限 | 单文件过大 | 拆文件，不要往 registry 里加豁免 |
| `check-tdz` 报未定义 | 视图文件循环引用 | 调整导入顺序/模块边界，别用 `var` 绕过 |
| `check-skill-sop` 报骨架缺失 | 新增/改了 SOP 但少一节 | 补齐四段（前置/动作/自检/失败分支） |
| typecheck 报 `Object is possibly 'undefined'` | 没做空值收窄 | 先 `const x = …; if (!x) return;` 再访问 |
| build 成功但页面没变 | 缓存 / 旧 serve 实例 | `?cb=1`；确认访问的是新进程 |
| 测试写到了真实库 | 没用 `test-store.mjs` | 立刻 `db backup` 检查污染，再改测试 |

## ⑤ 汇报（六问，缺一不可）

1. **改动文件清单**与每处作用。
2. **数据模型变化**：表/列/设置键，是否有迁移，旧数据怎么办。
3. **入口变化**：CLI 命令、HTTP 路由、面板位置。
4. **验证命令与真实结果**（贴关键行）。
5. **渲染 / 数据库证据**（如果适用）：预览输出、`db verify` 结论。
6. **未做事项 / 已知风险 / 需要确认的决策**。

## ⑥ 提交

- Conventional Commits（`feat(scope): …` / `fix(scope): …` / `docs(scope): …`），正文用中文写「为什么」。
- 并行会话可能也在改：**只 `git add` 本次改的文件**，不要 `git add -A`。
- 推之前 `git fetch origin main` + `git ls-remote` 核对远端指针；rebase 后用显式 sha 推送。
