# T01 · 加一条命令（action）

> 新增能力、或改现有命令的入参与行为。**改行为先在原文件改，不要复制第二条路径。**

## ① 前置（先跑，拿事实）

```powershell
node bin/kv.mjs routes --module <模块>           # 现有入口，确认 cli 路径不重复
ls src/modules/<模块>/actions/                    # 命名与骨架
cat src/modules/<模块>/actions/<最相近的>.ts      # 照抄这一份，不要照抄本文
cat src/modules/<模块>/index.ts                   # 模块怎么装配（模板形态下一般不用改）
```

**定落点**（按业务对象，不按 UI 页面）：

| 改的东西属于 | 模块 |
|---|---|
| 仓库、项目组（`board`）、参考仓库 | `repos` |
| 任务、队列、领取/完成/重开/等待 | `localtask` |
| 文档（refs）、正文、绑定 | `docs` |
| 附件、mdfile、文件夹 | `file` |
| 任务模板、提示词模板 | `templates` |
| 全局设置 | `setting` |
| 库诊断、备份、迁移 | `db`（纯 CLI，`http: null`） |
| 内置技能安装/输出 | `bundled` |
| 时间目标 | `tasktool` |
| 平台级（bootstrap/health/routes/contract） | `system` |

## ② 动作

**1. 建文件** `src/modules/<模块>/actions/<cli首词>-<动词>.ts`

命名照现有文件：`board-list.ts`、`localtask-preview.ts`、`setting-set.ts`。一段式命令用 `<动词>.ts`（`system/health.ts`）。

**2. 填骨架**（字段顺序与真实文件保持一致）：

```ts
// <module>.<verb> —— 一句话作用（review 的人先看这行）
import { z } from 'zod';
import { action } from '../../../runtime/action-decorator.js';
import { ActionBase, type ActionInput } from '../../../runtime/action-base.js';
import * as service from '../service.js';

/** 入参契约（CLI 与 HTTP 共用同一份）。`.describe()` 就是 help 文本。 */
const input = z.object({
  cwd: z.string().optional().describe('目标目录，缺省 = 进程当前目录'),
});

export class XxxAction extends ActionBase<typeof input> {
  @action({
    id: '<module>.<verb>',        // 全局唯一
    cli: ['<首词>', '<动词>'],     // 必须有；不得与 routes 里已有路径重复
    http: ['POST', '/api/xxx'],   // 纯 CLI 写 null
    summary: '一句话（出现在 help）',
    input,
    // 需要人类可读输出时加：render: (d) => service.renderXxx(d)
  })
  override async run(ctx: ActionInput<this['_input']>) {
    return service.doSomething(ctx);   // run 只做编排，业务在 service
  }
}
```

说明：
- **不要**自己处理 `--json` / `--xml`——那是 `src/runtime/cli.ts` 的全局开关（`splitGlobals`），返回对象即被序列化。
- `render` 只在**默认输出**要好看时才加；不加就走 JSON 打印。
- `id` 与 `cli` 都由 `src/runtime/registry.ts` 在启动时自检重复，重复会直接启动失败。

**3. 业务进 service，SQL 进 repo**

```powershell
cat src/modules/<模块>/service.ts          # 现有函数风格
ls src/modules/<模块>/repo/                # SQL 只在 repo/*.ts
```

- 业务规则、事务边界、错误语义在 `service.ts`（用 `core/errors.ts` 的 `badInput` 等）。
- 多表写入必须包在 `txw(conn => …)` 里，回调内**不 await** 非同步 IO。
- 时间统一 `nowMs()`（`src/core/db/time.ts`），不写 `Date.now()`。

**4. 生成清单**

```powershell
pnpm gen        # = gen:actions + gen:api；刷新 _manifest.generated.ts 与前端 typed client
```

**5. 立刻验证一次**

```powershell
node bin/kv.mjs routes --module <模块>        # 新命令必须出现在输出里
node bin/kv.mjs <首词> <动词> --json          # 真跑一次，看返回形状
```

**6. 要面板入口** → 走 `T03-加面板页面.md`。

## ③ 自检（全部通过才算完）

| 检查 | 命令 | 通过判据 |
|---|---|---|
| 注册成功 | `node bin/kv.mjs routes --module <模块>` | 新 cli 与 http 都在 |
| 全局唯一 | 同上 + 看启动日志 | 无「重复命令 / 重复路由」报错 |
| 类型 | `pnpm typecheck` | 退出码 0 |
| 契约 | `pnpm test:unit -- tests/unit/registry.test.mjs` | 通过（它校验模块↔视图↔`/api` 字面量） |
| 行为 | 真跑一次 | 返回符合预期，错误路径返回结构化错误 |

## ④ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 启动报「命令重复」 | `cli` 与既有路径撞了 | `node bin/kv.mjs routes` 找出占用者，改名或复用 |
| 面板请求新接口 404 | serve 的路由在**进程启动时**加载 | 重启 `nx-kv serve`（纯前端改动才只需刷新） |
| `pnpm typecheck` 报找不到模块 | 写了 `.ts` 后缀 | import 一律写 `.js` 后缀（见 SKILL 门禁 1） |
| 前端调新接口类型报错 | 没跑 `pnpm gen` | 跑 `pnpm gen` 再 typecheck |
| `run` 里写业务导致难测 | 逻辑压在 action 层 | 挪进 `service.ts`，action 只编排 |

## ⑤ 反模式（见到就改）

- 一个文件里塞多条 action（模板形态固定一条一文件，`gen:actions` 只认这种）。
- `run` 里直接拼 SQL。
- 为了「以后可能用到」加可选参数却不写 `.describe()`——help 会变成空白说明。
