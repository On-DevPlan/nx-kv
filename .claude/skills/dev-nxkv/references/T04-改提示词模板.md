# T04 · 改提示词 / 模板

> 交付给 agent 的提示词只有一条链：**一份共享 ctx + Handlebars 模板字符串 + 薄编排**。
> 禁止自研解析器、区块对象、每块独立变量域、服务端预拼列表文本。

## ① 前置（先跑，拿事实）

```powershell
grep -n "export" src/core/instruction-template.ts            # renderInstruction / validateTemplate / TEMPLATE_HELPERS
grep -n "DEFAULT_.*_TEMPLATE" src/shared/prompt-blocks.ts    # 内置默认模板（逐块）
grep -n "renderWarnings" src/modules/tasktool/wait.ts         # 运行期回落在哪收集
sed -n '280,300p' src/modules/localtask/repo/settings.ts      # 保存期校验在哪拒绝
node bin/kv.mjs localtask config --json                       # 当前模板设置
node bin/kv.mjs localtask preview --id <id> --cwd <目录>        # 当前真实渲染结果
```

## ② 先判定：改哪一层

| 现象 | 改这里 | 是否要迁移 |
|---|---|---|
| 所有用户的默认措辞、默认区块结构 | `src/shared/prompt-blocks.ts` 的 `DEFAULT_*_TEMPLATE` | 否（新库新装即生效；老库沿用已存设置） |
| 本机队列的区块开关 / 模板正文 | `localtask config` / 设置页（落 `settings` 表） | 否 |
| 任务正文模板（标题、验收、约束的骨架） | `templates` 表（`templates` 模块） | 否 |
| 渲染时上下文缺字段 | `src/modules/tasktool/`（ctx 组装处） | 否 |

**两件事必须分清**：任务正文模板（`templates` 表）≠ 提示词区块模板（`settings` 里的 per-block template）。不要合成一个表单。

## ③ 动作

1. 改模板字符串（Handlebars）。可用 helper 见 `TEMPLATE_HELPERS`，不要自己造语法。
2. 单块长度上限 `MAX_BLOCK_TEMPLATE_LEN`、模板数上限 `MAX_PROMPT_TEMPLATES`——超了会被拒，不要绕过。
3. **保存期校验不许去掉**：写入前必须走 `validateTemplate()`（`HB.precompile`），语法错误直接拒绝并报「模板名 + 区块名」。
4. **运行期必须能回落**：模板坏了不许阻断领取——回落到该块的内置模板，并把原因写进 `renderWarnings`（实现见 `src/modules/tasktool/wait.ts`）。
5. 改的是渲染函数本身 → 保持纯函数，入参 `(template, ctx)`，不读全局状态。

## ④ 自检（两层都要有证据）

**层一 · 保存期**

```powershell
# 故意提交坏语法，必须被拒
node bin/kv.mjs localtask config --set '<坏模板>'   # 或用设置页提交
```

通过判据：返回错误含模板名 + 区块名；库里**没有**存进坏模板。

**层二 · 运行期**

```powershell
node bin/kv.mjs localtask preview --id <id> --cwd <目录>        # 预览：看真实渲染
node bin/kv.mjs localtask get --cwd <目录>                       # 真领一次，看交付载荷
```

⚠️ **读交付内容用默认输出**，不要用 `--json` 再解析（#130）：JSON 里换行已转义，你读到的是 `\n` 字面量。需要机器可读又要原样区块时用 `--xml`（#128）。

通过判据：
- 目标区块渲染出预期内容；
- 手改一个坏模板后领取**不报错**，载荷里出现 `renderWarnings` 且该块仍有内容。

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 领取载荷里没有提示词整块 | 该模板未绑定 / `position != 0` | 检查绑定关系（主篇才自动内嵌） |
| 区块渲染成空白 | 变量名不在 ctx | `preview` 的 trace 看可用变量名；补 ctx 或改模板 |
| 保存时报「模板语法错误」但看不出哪 | 报错被 `try/catch` 吞了 | 直接跑 `validateTemplate` 拿原始错误 |
| 运行期静默用旧内容 | 回落生效了但没看 `renderWarnings` | 把 `renderWarnings` 打出来，别只看正文 |
| 改了模板没生效 | serve 进程内缓存 / 设置没落库 | 重启 serve；`localtask config --json` 确认库里的值 |
| `--json` 读出来的正文全是 `\n` | 拿 JSON 解析器读交付原文 | 改默认输出或 `--xml`（#128/#130） |

## ⑥ 反模式

- 在服务端把列表拼成一段文本塞进模板（应由模板 `{{#each}}` 渲染）。
- 为某一块单独造一套变量作用域。
- 为了让测试通过而放宽 `validateTemplate`。
- 在模板里写业务判断（判断进 ctx 组装，模板只做呈现）。
