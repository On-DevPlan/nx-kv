# D03 · 跨层 · 排障（症状 → 判定 → 处置）

> 序列 D（跨层）。顺序固定：**进程 → 接口 → 前端 → 库**。跳步会浪费时间（比如接口 404 时去翻 React 代码）。

## ① 前置：四步定位（顺序不许跳）

```powershell
# 1 进程：serve 在不在、端口对不对
node bin/kv.mjs serve --port 7878 --no-open     # 前台起一份，看启动日志

# 2 接口：不经前端，直接问后端
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:7878/api/health

# 3 前端：浏览器控制台（pageerror / console.error）与 network 面板
#    探针里用 page.on('pageerror') 收集，别只看截图

# 4 库：本机 SQLite 是否健康
node bin/kv.mjs db status
node bin/kv.mjs db verify
node scripts/db-inspect.mjs --tables
```

## ② 动作：进程与接口（→ B）

| 症状 | 判定 | 处置 |
|---|---|---|
| 面板打不开 / 连接被拒 | `curl /api/health` 报连接失败 | 进程没起或端口不对；`serve --port <N>` 换端口 |
| 端口被占 | 启动日志报 `EADDRINUSE` | `serve --port` 换一个；或结束占用进程 |
| **新加的接口 404** | `node bin/kv.mjs routes --http "POST /api/xxx"` 有，但 curl 404 | **路由在进程启动时编译**：重启 serve（纯前端改动才只需刷新） |
| 命令不认识 | `node bin/kv.mjs <cmd>` 报 unknown | 没跑 `pnpm gen`，或跑的是 `~/.claude` 里的旧安装 |
| 跨域失败（页面与 API 不同源） | 控制台报 CORS | 走同源 `serve`；CORS 配置在 `src/runtime/cors.ts` |
| SSE 断流 | network 里 event-stream 反复重连 | 服务端 `src/runtime/server.ts` 的 SSE 分支；先确认代理没缓冲 |

## ③ 动作：前端与面板（→ C）

| 症状 | 判定 | 处置 |
|---|---|---|
| 白屏 | 控制台有 `pageerror` | 按报错栈定位；若是 `Rendered more hooks than previous render` → 早退写在了 hook 之前，把 return 挪到所有 hook 之后 |
| 侧栏树整块空白 | `curl /api/repos` 与 `/api/boards` **分别**看 | 任一失败会让整棵树空掉（#194）；修读取路径，不要让一份失败抹掉另一份 |
| 同一页面裂出两个页签 | 打开→复制地址→刷新 | `panelOf` 与 `reverse` 不互逆；让 `format(panelOf(route).config) === hash` |
| 浮窗关掉后 reload 复活 | localStorage 里的 workspace JSON | 空 tabset 要剪枝；`Model.fromJson` 内部 tidy 只能救一半，存盘前也要剪 |
| 改了面板 config 界面不变 | 模型里已是新值，界面还是旧的 | `TabContentRenderer` 是 `React.memo`，只认 tabNode 身份/redraw revision；用 `PanelHost` 的 `configSig` 订阅强制重绘 |
| 按住快捷键触发几十次 | 没过滤 `e.repeat` / 没节流 | 走 `src/web/frontend/components/md/doc-keys.ts` 的判定 + 闸门（#189） |
| 改了代码看不出变化 | 访问带 `?cb=1` 仍无变化 | 没 `pnpm build`，或浏览器加载的是旧 serve 实例 |
| 页面里有多个 `.mdw` 抓错元素 | 探针断言全量而非取第一个 | 逐场景清 `localStorage('nx-kv-ui.workspace')` 并 **reload**（同页改 hash 不重载） |

## ④ 动作：自动化探针（面板行为的唯一可靠证据）

| 症状 | 判定 | 处置 |
|---|---|---|
| 菜单项点不动（30s 超时） | 元素是 `<button role="menuitem">` 且 portal 到 body | 用 `dispatchEvent('click')` 直接派发，React 合成事件照常触发 |
| `page.fill()` 改不了 contentEditable | 值只在 DOM 上变了、React 没收到 onChange | `click` → `Control+A` → `keyboard.type` |
| 探针把真实队列搞脏 | 没设隔离 store | `NX_KV_LOCALTASK_STORE` / `NX_KV_HOME` 指向 `temp/` |
| 探针结果读不全 | 一次 `console.log` 打对象被截断 | 页面内先 `JSON.stringify` 成单行再输出，或写文件再读 |

## ⑤ 动作：数据与测试（→ A）

| 症状 | 判定 | 处置 |
|---|---|---|
| 外键约束「没生效」 | `PRAGMA foreign_keys` | 每个连接都要 `foreign_keys=ON`（`src/core/db/driver.ts`），少设就是静默脏数据 |
| 备份拿到不一致快照 | 直接复制了 `.db` | WAL 下必须 `db backup`（`VACUUM INTO`） |
| `缺少迁移边 a → b` | `db migrate --dry-run` | 在 `migrations/index.ts` 的 `DIRECT_EDGES` 登记 |
| 升级后关联数据丢了 | 查 `task_attach` / `ref_attach` 行数 | `DROP TABLE` 会级联；照 `v10.sql` 的 TEMP 快照方案 |
| 单测单独跑过、并发跑挂 | `pnpm test:unit` 才挂 | 临时库隔离、端口不要 `base+1000` 越界；逐文件跑定位 |
| 事务内偶发卡死 | 回调里有 `await` 非同步 IO | `tx` 回调保持同步 |
| `check-lines` 拦住提交 | 文件超 500/1000 行 | 拆文件；registry 只许降不许升 |
| 只有某个 smoke 失败 | 基线 `git stash` 后复跑同一用例 | 同样失败 = 存量问题，记录而不是硬改 |

## ⑥ 自检：修完怎么确认

```powershell
# 1 原始症状的可复现步骤，重跑一次应当不再出现
# 2 相关门禁跑一遍
pnpm lint
pnpm typecheck
node --import tsx --test tests/unit/<相关>.test.mjs
# 3 若是数据问题，再验一次库
node bin/kv.mjs db verify
```

| 检查 | 判据 |
|---|---|
| 症状消失 | 原始复现路径走通，且**不是**靠清缓存/重启掩盖（要能说出根因） |
| 没有连带损伤 | lint / typecheck 通过；相邻功能仍可用 |
| 根因可复述 | 能一句话说清「哪个环节的什么假设不成立」 |
| 已回写 | 新症状补进本表；若根因是某条 SOP 步骤错了，改那条 SOP |

## ⑦ 失败分支：定位不到时

```powershell
node bin/kv.mjs routes --http "<方法 + 路径>"     # 路由 → 命令 id
node bin/kv.mjs routes --module <id>              # 模块 → 全部入口
grep -rn "<业务名词>" src/ --include=*.ts --include=*.tsx | head -20
```

拿到命令 id 后按 `D01-定位代码.md` 的判定链继续往下钻。若三条命令都无所获，说明现象与代码没有直接词面关联——改从「谁调用它」反查：先找到入口 action，再顺着 `service.ts` 往下读。
