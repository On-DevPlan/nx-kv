## 一、交付 = 一份共享 ctx × 八个区块

```
composeSystemBlocks(segments, { ctx, templates, mode })
  └─ 按 BLOCK_DEFS 的固定顺序，逐块渲染「当前生效的那条模板」
     ├─ 模板取自 templates 表（用户在面板改的运行时数据）
     ├─ 坏模板 → 回落该块内置模板 + 记 warning（领取照常成功）
     └─ mode='xml' 包 <nx-kv.xxx> 标签；mode='plain' 直接拼文本
```

| 区块 id | 标签 | 内容 | 何时出现 |
|---|---|---|---|
| `context` | `<nx-kv.context>` | 仓库 / 组 / 参考仓库 / 其余组 | 登记了仓库就有（组材料只进组任务） |
| `attachment` | `<nx-kv.attachment>` | 附件清单 + 取用方式 + 文档原文 | 任务带附件时 |
| `timecheck` | `<nx-kv.timecheck>` | 时间目标检查指令 | 带时间目标时 |
| `goalhint` | `<nx-kv.goalhint>` | 时间目标上下文（可算的秒数/人话） | 带时间目标时 |
| `doneguard` | `<nx-kv.doneguard>` | 未到点不许 done 的拦截文案 | 只在 done 被拦截时出现 |
| `ext` | `<nx-kv.ext>` | 同主题还有多少待领取 | 队列非空时 |
| `ack` | `<nx-kv.ack>` | 完成回填指令 | 总有 |
| `getloop` | `<nx-kv.getloop>` | 持续 get 指令 | 项目开了持续 get |

代码：`src/shared/prompt-blocks.ts`（`BLOCK_DEFS`）、`src/modules/tasktool/system-blocks.ts`（装配）。

## 二、ctx 从哪来（一份共享 ctx）

| ctx 片段 | 装配位置 | 主要字段 |
|---|---|---|
| `task` | `wait.ts` 的 `baseCtx` | `id` / `text`（交付前重排：最新轮置顶） |
| `goal` | `wait.ts` + `plugins/goal-template.ts` | `goalKey` / `durationHuman` / `remainingSec` / `check` / `statusLine` / `extra` |
| `repo` / `group` / `refRepos` / `groups` | `delivery-template.ts` 的 `deliveryCtxOf` | `intro` / `docs` / `desc` / `peers` / `refRepos` / `note` |
| `attach` | `attach-template.ts` 的 `attachTemplateCtx` | `count` / `inlineCount` / `areaCount` / `list[]`（按 kind 给子对象） |
| `source` / `summary` / `cwd` / `name` / `params` | `buildDeliveryCtx` | 外部参数是**平面扩展**（`{{k}}` 或 `{{params.k}}`），内建键不被覆盖 |

**规矩**：ctx 只放**数据**，成文措辞归模板；服务端不拼多行文本（列表一律结构化，模板自己 `{{#each}}` 组织行）。

## 三、模板语法与 helper

- 区块：`{{#if x}}…{{else}}…{{/if}}`、`{{#each list}}…{{/each}}`；
  **旧语法 `{{#section}}` / 反向区块 `{{^x}}` 已废弃**（保存时会被 `validateTemplate` 拒）。
- 占位符：`{{a.b.c}}`；未知变量**渲染成空串、不报错** → 只能靠 `localtask preview` 看结果。
- helper（`TEMPLATE_HELPERS`，共 25 个）：
  `eq ne gt gte lt lte between`（比较）、`and or not`（逻辑）、
  `add sub mul div mod round floor ceil percent ratio clamp`（数值）、
  `includes length default`（字符串）、`formatDuration`（秒→人话）。
  helper 自身异常会退化成可见兜底，不拖垮整份渲染。

## 四、模板存哪、谁能用

`templates` 表（**运行时数据，不是代码**）：

| 列 | 含义 |
|---|---|
| `category` | 面板 tab：`newtask` / `delivery` / `enhance` / `context` |
| `body` | 模板原文（占位符保留） |
| `vars_schema` | **声明**这条模板接受哪些变量（前端据此渲染表单，不用猜） |
| `vars` | 用户填的值 |
| `scope` | 可见域：`*` / `topic:<key>` / `repo:<key>` / `group:<key>` |
| `origin_topic` | 创建来源主题（决定谁能**编辑**） |
| `is_default` / `enabled` / `sort_order` | 默认条目 / 启用 / 排序 |

- **可见（use）** 比 **可编辑（edit）** 宽：能看见的未必能改。
- 作用域判定是纯函数：`src/modules/templates/scope.ts`（前后端共用）。

## 五、变量知识化：两处，缺一不可

| 位置 | 作用 | 谁维护 |
|---|---|---|
| 模板的 `vars_schema` | 声明变量名 / 类型 / 说明 → 前端渲染表单 | 写模板的人 |
| `src/web/frontend/page/settings/prompt-template-params.ts` 的 `BLOCK_PARAMS` | 设置面板的**变量速查表**（只读） | 改 ctx 的人 |

> 新增 ctx 变量时**两处都要动**：只做前者，模板能跑但用户不知道有哪些变量；
> 只做后者，模板引用不到，等于没加。（这块的手写漂移风险见 `A02` §⑤ 的体检结论。）

## 六、失败时的行为（不静默）

| 情况 | 行为 |
|---|---|
| 模板语法错 / 旧语法 | `validateTemplate` 拒绝保存；运行期遇到则**该块回落内置模板** + 记 warning（领取照常成功） |
| 变量名写错 | **静默渲染成空**（Handlebars 语义）——只能靠 `preview` 发现 |
| 区块数据为空 | 由模板的 `{{#if}}` 闸门整段不出现；不闸就印空标签（`组定位：`这种） |
| helper 自身异常 | 退化成可见兜底，不拖垮整份渲染 |

排查入口：`node bin/kv.mjs localtask preview --id <id>`（零副作用，能看到分段与告警）。
