## 一、目录与命名

| 路径 | 放什么 | 跑法 |
|---|---|---|
| `tests/unit/<域>-*.test.mjs` | 单测（139 个文件，按域分前缀：`db-` / `docs-` / `localtask-` / `attach-` / `repos-` …） | `pnpm test:unit` |
| `tests/smoke.mjs` + `tests/smoke/` | 冒烟（假后端 + 临时配置，跑真命令） | `pnpm test:smoke` |

## 二、夹具：只允许临时库（硬保险）

```js
import { createTestStore } from '../support/test-store.mjs';
const store = await createTestStore();     // 建临时库（schema 就绪）
try {
  store.db.run('INSERT INTO …');
  // …
} finally {
  store.reset();                             // 先 closeDb 再删目录（Windows 少这一步必报 EBUSY）
}
```

- `createTestStore()` **只允许在系统临时目录建库**——路径不在 `tmpdir()` 下直接抛错，
  绝不放行（防止手滑把测试数据写进用户真实库）。
- 需要**域级隔离**（老 JSON 时代的环境变量）时，各域单测自己设：

  ```js
  beforeEach(() => {
    dir = mkdtempSync(join(tmpdir(), 'nx-kv-<域>-'));
    process.env.NX_KV_LOCALTASK_STORE = join(dir, 'localtasks.json');
    process.env.NX_KV_REPOS_STORE = join(dir, 'repos.json');
    process.env.NX_KV_DOCS_DIR = join(dir, 'docs');
  });
  ```

- 其它可用环境变量（`src/core/paths.ts` 是唯一权威）：
  `NX_KV_HOME`（整个用户目录）、`NX_KV_DB`（库文件）、`NX_KV_STORE` / `NX_KV_ATTACHMENTS`、
  `NX_KV_DOCS_DIR`、`NX_KV_BACKUPS`、`NX_KV_ASSETS`（内置 skill 假资产树）。

## 三、断言风格

```js
import { test, beforeEach } from 'node:test';
import assert from 'node:assert/strict';
```

- 单测只测**一条口径**（一个 `test()` 一件事），标题写清「什么时候该怎样」；
- 断言用 `assert.equal` / `assert.deepEqual` / `assert.rejects(() => …, /报错文案/)`；
- 迁移类单测要**造旧版本库**再升（照 `tests/unit/attachment-folder.test.mjs` 的 v9→v10 写法），
  并断言「行数一条不少、约束真的生效」。

## 四、前端怎么测

前端纯函数（口径类）可以直接被 node 测——用 `.js` 后缀引 `.ts` 源文件（loader 解析到同名 TS）：

```js
import { attachBodyOf } from '../../src/web/frontend/components/md/attach-common.js';
```

- 能被 node 解析的是**纯函数**（口径 / 归一 / 渲染函数）；
- 真正要验交互 → 走 Playwright 探针（隔离库 + 临时端口，坑位见 `B05-前端面板地图.md`）。

## 五、跑哪条

```bash
pnpm test:unit          # 全量单测（约 40 秒）
pnpm test:smoke        # 冒烟
pnpm test:db           # 迁移 / 边界
node --import tsx --test tests/unit/<域>-<主题>.test.mjs   # 单跑一条（改了哪跑哪）
```

## 六、已知噪音与坑

| 现象 | 原因 | 处置 |
|---|---|---|
| `ExperimentalWarning: SQLite is an experimental feature` | 本机 Node ≥ 22.5 的 `node:sqlite` 警告 | 已知噪音；CI（Node 22）不出现。若某条用例断言 stderr 必须干净而失败，看它是不是在裸 `node` 下跑的（用 `pnpm test:unit` 走同一条链路） |
| 单跑通过、全量并行时卡住 | 并行执行下的资源争用（本机同时跑着多个 serve 更容易） | 单独跑那条文件定位；不要靠「重跑就好」交付 |
| `rmSync` 报 EBUSY（Windows） | 连接还开着 | 先 `closeDb()` 再删；用夹具的 `reset()` |
| 测试跑出真实库 | 没用夹具 / 忘了设隔离 env | 立刻 `node bin/kv.mjs db backup` 检查污染，再改测试 |
| 用例之间互相影响 | 没在 `beforeEach` 里重建临时目录 | 每条用例自己的 `dir`，`finally` 里 `reset()` |
