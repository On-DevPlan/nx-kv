# T02 · 加表 / 加字段 / 加设置键

> 动 schema 的唯一入口。**已发布的 `vN.sql` 一个字都不能改**——只能加新迁移。

## ① 前置（先跑，拿事实）

```powershell
grep -n CURRENT_SCHEMA_VERSION src/core/db/version.ts    # 当前版本 N
ls src/core/db/migrations/*.sql                          # 到 vN.sql 为止
cat src/core/db/migrations/v10.sql                       # 最近一次的写法（尤其 DROP/RENAME 的 12-step）
sed -n '52,62p' src/core/db/migrations/index.ts          # DIRECT_EDGES 登记格式
node bin/kv.mjs db status                                # 库版本 / 待迁移步数
node scripts/db-inspect.mjs --tables                     # 现有表与行数
ls docs/decisions/ | tail -5                             # 决策文件命名
```

## ② 先判定：该不该建表

| 数据特征 | 放哪 | 动作 |
|---|---|---|
| 有查询条件、外键、唯一约束、事务 | 新表 / 新列 | 走本文全流程 |
| 全局偏好、全局开关 | `settings` 表（k/v，JSON 值） | 不加宽表，加键即可 → 跳到 §④ |
| 队列级 / 仓库级旋钮 | `topics.ext` / `repos.ext` | 随行走，不进 `settings` |
| 附属信息、永不进 WHERE | `<table>.ext`（键名 `ext_` 前缀） | 不需要迁移 |
| 任务正文模板 | `templates` 表 | 与提示词模板严格分开 |
| 凭据、密钥 | `config.json` | **绝不进库** |

判定后仍要建表 → 继续。

## ③ 动作（建表 / 改列）

**1. 写迁移** `src/core/db/migrations/v<N+1>.sql`

首行写清「为什么」：

```sql
-- schema v<N+1>：<一句话>
--
-- 口径：<这段设计约束是什么，后来的人靠这行判断能不能改>
--
-- @decision docs/decisions/<日期>-<slug>.md
CREATE TABLE IF NOT EXISTS xxx (
  id         TEXT PRIMARY KEY,
  ...
  deleted_at INTEGER,              -- 软删：新增查询一律带 deleted_at IS NULL
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

**2. 每个 `CREATE TABLE` / `DROP TABLE` 前一行都要 `@decision`**，且文件真实存在（`check-schema-decisions` 会逐条核对，少一个就 lint 失败）：

```powershell
# 先建文件，再写注释——顺序反了会被门禁抓
mkdir docs/decisions -Force
```

决策文件骨架：

```markdown
# <标题>

## 背景
<不做会怎样>

## 决定
<选了什么：表/列/类型/约束>

## 取舍
<没选的那条路，以及为什么不行>

## 影响
<旧数据怎么办、谁要改、回滚方式>
```

**3. 登记迁移边** `src/core/db/migrations/index.ts` 的 `DIRECT_EDGES`：

```ts
{ from: <N>, to: <N+1>, file: 'v<N+1>.sql', title: '<中文标题>' },
```

有数据回填（旧行要补值）时，加 `apply: migrateXxx` 并写在同目录 `v<N+1>-data.ts`。

**4. 升级版本号** `src/core/db/version.ts`：`CURRENT_SCHEMA_VERSION = <N+1>`。

**5. 重建表时的死规矩**（SQLite 不能 `ALTER … CHECK`，只能重建）：

```
TEMP 快照 → 建 _new 表 → 按显式列名 INSERT SELECT → DROP 旧表 → RENAME
→ 重建索引 → 回填关联表
```

`v10.sql` 是可直接照抄的完整范例（含 `task_attach` / `ref_attach` 的级联处理）。

## ④ 动作（只加设置键）

```powershell
cat src/modules/setting/actions/setting-set.ts     # 键怎么声明
grep -n "ext_" src/modules/localtask/repo/topics.ts | head
```

1. 在 `setting-set.ts` 的 zod 契约里加字段 + `.describe()`（help 文本）。
2. 在 service 端加默认值与兼容旧值（旧键读到要能迁移）。
3. 配置类**不需要迁移**——`settings` 是 k/v。

## ⑤ 自检

```powershell
pnpm check:schema                                  # 决策文件门禁
pnpm test:db                                       # 迁移 + 边界用例
node bin/kv.mjs db migrate --dry-run               # 看将执行哪几步
node bin/kv.mjs db backup                          # 动真实库前先备份
node bin/kv.mjs db migrate
node bin/kv.mjs db verify                          # 结构 + 数据一致性
```

| 检查 | 通过判据 |
|---|---|
| 迁移边完整 | `db migrate --dry-run` 能规划出 N → N+1 |
| 旧库能升 | 用 `tests/support/test-store.mjs` 造一个 vN 库跑升级 |
| 新库能建 | 空目录 `db status` 后直接落到 N+1 |
| 幂等 | 连跑两次 `db migrate`，第二次应「无待迁移」 |
| 软删 | 新增查询都带 `deleted_at IS NULL` |

## ⑥ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| `缺少迁移边 a → b` | 没登记 `DIRECT_EDGES` | 按 §③.3 补一行；跨多版允许由已有边组合 |
| `check-schema-decisions` 报缺文件 | `@decision` 指向的文件不存在 | 建文件；路径与注释**逐字一致** |
| 升级后关联数据少了 | `DROP TABLE` 级联删了 `task_attach` | 照 `v10.sql`：先 TEMP 快照、DROP 前清空、重建后按显式列名回填 |
| 升级后外键失效 | 连接没开 `foreign_keys=ON` | 见 `src/core/db/driver.ts`，每个连接都要设 |
| 备份拿到坏快照 | WAL 下直接复制 `.db` | 一律 `db backup`（内部 `VACUUM INTO`） |
| 旧库报 CHECK 约束失败 | 旧数据有非法值 | 迁移里先清洗再重建，别放宽约束将就 |

## ⑦ 反模式

- 改已发布的 `vN.sql`（历史用户升级路径会断）。
- `PRAGMA foreign_keys=OFF` 绕过约束——静默产出脏数据。
- 为了「省一次迁移」把新列塞进 `ext` JSON——进 WHERE 的字段必须在真列上。
- 用 `Date.now()` 自己填时间戳，而不是 `nowMs()`。
