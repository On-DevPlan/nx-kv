# A03 · 表结构 · 加一种附件类型（kind）

> 序列 A（数据层）牵头，实为 **A → B → C** 的跨层改动：先定库里的数据形状，
> 再让资源登记与提示词模板认识它，最后让附件区把它显示出来。
> **已发布的 `vN.sql` 一个字都不能改**——只能加新迁移。
> 范例：`folder`（#127，本机文件夹路径指针）。本文按它逐层展开，路径全部可核对。

## ① 前置（先跑，拿事实）

```powershell
grep -n CURRENT_SCHEMA_VERSION src/core/db/version.ts      # 当前版本 N
cat src/core/db/migrations/v10.sql                           # 扩 CHECK 的 12-step 范例
sed -n '52,62p' src/core/db/migrations/index.ts              # DIRECT_EDGES / VERSION_NOTES 登记格式
grep -rn "kind IN" src/core/db/migrations/v10.sql            # attachments 的 kind CHECK 在哪
grep -rn "folder" src/core/attachmentdb/folder.ts           # 登记函数范例
grep -rn "folder" src/modules/tasktool/attach-template.ts   # 模板 ctx 序列化
grep -rn "folder" src/web/frontend/components/md/attach-common.ts   # 面板口径
node bin/kv.mjs db status                                   # 库版本 / 待迁移步数
```

**先判定新类型属于哪一类**——这一步决定要不要动 schema、以及它落在哪一层：

| 新类型的语义 | 落点 | 要迁移吗 |
|---|---|---|
| 指向本机某个位置（目录 / 外部文件），只存指针、不存字节 | 新 `kind`（`attachments.kind`）+ `storage='external'` | **要**（扩 CHECK） |
| 本机附件仓里的一份字节 | 现有 `file`（上传落仓） | 不要 |
| 指向库内实体（任务 / 文档） | 现有 `task` / `ref` | 不要 |
| 只是一个链接 | 现有 `url` | 不要 |
| 自带专属字段（指纹、内容、行列） | 新 `kind` + 专属列 | **要**（重建表 + 加列） |

判定为「要迁移」→ 继续 §③；否则跳到 §④（资源与模板）与 §⑤（附件区与相关功能）。

## ② 动作 · 第 1 层：库（迁移）

**1. 先写决策文件**（门禁要求每个 `CREATE/DROP TABLE` 上方都有 `@decision`，文件必须真实存在）：

```powershell
# 文件名：docs/decisions/<日期>-<slug>.md（日期前缀要与正文 date: 一致）
```

正文固定字段（`scripts/check-schema-decisions.mjs` 逐条核对）：

```markdown
# <日期> · <一句话标题>

- date: 2026-11-14
- status: 已实施
- decision: <attachments.kind 增加第 N 个值 X。它是什么、存什么、不存什么>
- tables: attachments（重建，仅扩 kind 的 CHECK）
- drops: attachments, _v10_task_attach, _v10_ref_attach
- producers: `localtask attach --<kind> <值>`、`docs attach --<kind> <值>`
- consumers: 交付模板 `attach.list[].<kind>.*`、附件清单渲染、设置面板模板变量表
- migration: `src/core/db/migrations/v10.sql`（9 → 10）
```

`drops:` 里必须列出被 DROP 的表（TEMP 快照表也写上并注明用途），否则门禁报错。

**2. 写迁移** `src/core/db/migrations/v<N+1>.sql`。SQLite **不能 ALTER 既有 CHECK**，
只能按 v5/v10 的 12-step 重建（照抄 `src/core/db/migrations/v10.sql`）：

```
PRAGMA defer_foreign_keys = ON
→ TEMP 快照 task_attach / ref_attach
→ CREATE TABLE attachments_new（CHECK 里加上新 kind）
→ INSERT SELECT 按**显式列名**搬数据
→ DROP TABLE attachments
→ ALTER TABLE attachments_new RENAME TO attachments
→ 重建原有索引 + 新增该 kind 的部分唯一索引
→ 清空关系表 → 按显式列名回填 → DROP 快照表
```

坑位（DROP 会**级联删**关系表的行，`defer_foreign_keys` 只推迟校验、不推迟级联）：
**先快照 → DROP 前清空 → 重建后回填**，顺序反了就是「升级后附件关联全丢」。

**3. 登记迁移边** `src/core/db/migrations/index.ts`：

```ts
// DIRECT_EDGES
{ from: <N>, to: <N+1>, file: 'v<N+1>.sql', title: '<中文标题>' },
// VERSION_NOTES
<N+1>: 'docs/decisions/versions/<日期>-v<N+1>.md',
```

**4. 升级版本号** `src/core/db/version.ts`：`CURRENT_SCHEMA_VERSION = <N+1>`，
并在文件顶部的版本注释里补一段「这一版加了什么、为什么」。

**5. 写版本说明** `docs/decisions/versions/<日期>-v<N+1>.md`（门禁要求每个版本都有）。

## ③ 动作 · 第 2 层：资源登记 + 提示词模板（序列化 + 知识化）

**1. 登记函数** `src/core/attachmentdb/<kind>.ts`（范例 `src/core/attachmentdb/folder.ts`）：

- `normalize<Kind>Path()`：规范化（绝对路径、去尾斜杠、身份种子大小写不敏感）；
- `<kind>AttachmentId()`：稳定 id（同一路径幂等 → 同一 id）；
- `register<Kind>()`：upsert 一行（`kind` / `storage='external'` / `size=0` / `hash=''`），
  并处理唯一索引撞车（Windows 大小写差异）；
- `ensure<Kind>Attachment()`：正文里出现 `nxkv://<kind>/<id>` 时的校验入口。

**2. 正文引用解析与分派**：

- `src/core/attachmentdb/ids.ts`：加 `nxkv://<kind>/<id>` 的正则与 kind 归一；
- `src/core/attachmentdb/resources.ts`：`ensure` 按 kind 分派到上面那个函数；
- `src/core/attachmentdb.ts`：把新函数导出（公共出口只此一处）。

**3. 视图模型** `src/modules/tasktool/attach-resource.ts`：
`KIND_LABEL` 加显示名、`baseKind()` 认这个 kind、kind 分支给 `locator` / `usage` / `cmd` /
`exists` / `missing`——**usage 是给 agent 的取用说明，要写清怎么用这个类型**。

**4. 模板 ctx 序列化** `src/modules/tasktool/attach-template.ts`：
为该 kind 生成专属子对象（如 `folder = { absPath, exists, missing, readCmd }`），
并在条目上补 `usage` / `cmd` / `locator` / `path`。

**5. 默认模板** `src/shared/prompt-blocks.ts` 的 `DEFAULT_ATTACH_TEMPLATE`：
清单行加一个 `{{#if <kind>}}…{{/if}}` 分支，把该类型的**关键值**交给 agent
（路径指针类给绝对路径，不要给一个打不开的链接）。

**6. 知识化**（容易漏，用户就不知道能写什么）：
`src/web/frontend/page/settings/prompt-template-params.ts` 的 `BLOCK_PARAMS.attachment`
加一个分组（如「文件夹型（kind=folder）· folder 子对象」），逐条列出变量名 + 一句含义。
`kind` / `kindLabel` 两行的取值清单也要同步补上。

> 序列化（ctx 里有这个子对象）与知识化（变量表里列得出来）**必须都做**：
> 只做前者，模板能跑但用户不知道有哪些变量；只做后者，模板引用了不存在的字段。

## ④ 动作 · 第 3 层：附件区（前端）与相关功能

**1. 命令入口**（一条 action 一个文件，契约内联 zod）：

- `src/modules/localtask/actions/localtask-attach.ts`：加 `--<kind>` 入参 + summary + render 文案；
- `src/modules/docs/actions/doc-attach.ts`：文档侧同一个入参；
- 服务端登记分支：`src/modules/tasktool/attach.ts`（任务侧）与 `src/modules/docs/attach.ts`
  （文档侧）——两边共用同一个 `register<Kind>()`；
- CLI 清单渲染：`src/modules/localtask/action-render.ts`（显示名 + 定位串）。

**2. 附件区（前端）**：

- `src/web/frontend/components/md/attach-common.ts`：
  `AttachAllow` 加来源档、`badgeOf()` 加显示名、`attachBodyOf()` 给这个来源发对字段名、
  `normAttachment()` 给它正确的 `href`（路径指针类**留空**，别编一个会 404 的链接）；
- `src/web/frontend/components/md/attach-modal.tsx`：「添加附件」弹窗加入口
  （浏览器拿不到目录的**绝对路径** → 用路径输入框，不是目录选择器）；
- `src/web/frontend/components/md/attach-area.tsx`：附件区条目加展示（徽标 + 关键值）；
- `src/web/frontend/modules/md/styles/chrome.css`：徽标样式（字多了要 nowrap，别折行）。

**3. 消费侧说明与文档**：

- `assets/nx-kv/references/`：把新命令/新类型写进给 agent 的说明书（见 `B05-改内置技能.md`）；
- `README.md` / `docs/` / `CHANGELOG.md`：对外可见的变更（见 `B05-改内置技能.md`）。

**4. 单测**（每种类型四件套，见 `tests/unit/attachment-folder.test.mjs`）：
迁移不丢数据 + CHECK 生效、登记幂等、正文引用能解析、模板 ctx 与**绝对路径交付**；
前端再加一条请求体字段名用例（`tests/unit/attach-folder-panel.test.mjs`）。


```bash
# 端到端：新类型真的能被登记、列出、读出来

node bin/kv.mjs localtask attachments --id 12
node bin/kv.mjs localtask preview --id 12                            # 交付文本里该类型的段落
node bin/kv.mjs file content att_folder_xxxxxxxxxxxxxxxx              # 该类型自己的取用命令
```

| 检查 | 通过判据 |
|---|---|
| 迁移 | 旧库能 N → N+1；附件与关系表行数**一条不少**；连跑两次幂等 |
| 登记 | 同一路径重复登记只多一行；显示名与关键值对得上 |
| 提示词 | `preview` 里该类型有独立分支，**关键值（路径/内容）真的给了 agent** |
| 知识化 | 设置面板的变量表里能查到该类型的全部变量 |
| 附件区 | 徽标显示名对、行里有该类型的关键值、路径指针类没有假链接 |
| 回归 | 原有 5 种类型的交付文本与附件区显示**没变** |

## ⑥ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 升级后附件关联全丢 | `DROP TABLE attachments` 级联删了 `task_attach` / `ref_attach` | 照 `v10.sql`：先 TEMP 快照、DROP 前清空、重建后按显式列名回填 |
| 旧库报 CHECK 约束失败 | 既有 CHECK 里没有新 kind | SQLite 不能 ALTER CHECK → 12-step 重建，别放宽约束将就 |
| `check-schema-decisions` 报错 | `@decision` 文件不存在 / `drops:` 漏表 / 版本说明缺失 | 照门禁注释逐条补；文件里的 `date:` 与文件名日期前缀要一致 |
| 正文里的引用解析不出来 | `ids.ts` 的正则与 `resources.ts` 的分派没接上 | 两条都要改；`ensure` 必须先确认行存在才认这条引用 |
| 模板里该类型整段消失 | ctx 没给子对象，或默认模板没加 `{{#if}}` 分支 | 先看 `attach-template.ts` 的序列化，再看 `prompt-blocks.ts` 的模板 |
| 用户说「模板里没这个变量」 | 只做了序列化、没做知识化 | `prompt-template-params.ts` 的分组补上 |
| 附件区把路径指针显示成打不开的链接 | 沿用了 `file` 的 `contentUrl` | 路径指针类 `href` 留空 |
| 面板里选不了目录 | 浏览器拿不到目录绝对路径 | 用路径输入框（事实如此，不是实现偷懒） |
| 徽标文字折行 | 徽标固定宽度 + 三个中文字 | `min-width` + `white-space:nowrap` |
| CLI 显示「附件」而不是新类型 | 渲染分支漏了这个 kind | 补 `action-render.ts` 与 action 的 render 文案 |

## ⑦ 反模式

- 改已发布的 `vN.sql`（历史用户升级路径会断）。
- 用 `PRAGMA foreign_keys=OFF` 绕过约束——静默产出脏数据。
- 为省一次迁移把新 kind 塞进 `meta` JSON——kind 进 CHECK 才有约束力。
- 只加一行 DB 就收工：**类型是四层改动**（库 → 登记/模板 → 面板 → 说明书/测试）。
- 只做模板序列化、不做变量表知识化（用户不知道能写什么）。
- 给路径指针类编一个 `href`（点开必然 404）。

## ⑧ 总结反思（这条 SOP 的来路）

- **一次「加附件类型」的改动会横跨四层**：A 库（CHECK/索引）→ B 资源登记 + 提示词模板（序列化 +
  知识化）→ C 附件区（入口 + 展示 + 样式）→ 说明书与测试。漏掉任何一层，用户看到的都是
  「这功能没有」，而不是「这功能少一块」。所以按 A → B → C 顺序做，别跳层。
- **路径指针类（mdfile / folder）有共同口径**：只存规范化绝对路径 + 展示名；
  `storage='external'`、`size=0`、`hash=''`；模板给**绝对路径 + usage**，不给打不开的链接；
  幂等靠「路径 → 稳定 id」+ 部分唯一索引（大小写不敏感）。
- **浏览器给不了目录的绝对路径**：面板用路径输入框是产品事实，不是偷懒——把这句话写进
  说明书与 UI 提示，别让用户以为是 bug。
- **CHECK 扩不了就重建**：12-step 重建 + 关系表快照回填，是每次扩 kind 都要走的路；
  「DROP 会级联删关系行」是最容易漏的一环。
- **提示词变量要两处都改**：ctx 序列化（能跑）与设置面板变量表（能被用）缺一不可。
- **每种类型都要有单测四件套**：迁移不丢数据、CHECK 生效、登记幂等、正文引用能解析 +
  模板真的把关键值交给 agent；前端再补一条「请求体字段名对不对」。
