# v19：内部插件宿主表 + 旧任务模板暂存

- date: 2026-11-27
- version: 19
- migration: `src/core/db/migrations/v19.sql` + `v19-data.ts`
- tables: plugin_state / plugin_entry_visibility / plugin_legacy_data / plugin_storage_migrations
- producers: src/modules/plugin/host.ts、packages/plugin-task-template/src/server/index.ts
- consumers: src/modules/plugin/repo/state.ts、visibility.ts、legacy.ts、migrations.ts、packages/plugin-task-template/src/server/templates.ts

## 背景

任务模板从宿主内置模块改为内部插件包 `@nx-kv/plugin-task-template`。插件需要：

- 宿主级全局开关（一个地方统一配置）；
- 每个 topic / repo / group 的入口可见性与顺序；
- 插件自己的表结构版本账本；
- 旧 `templates` 用户行的迁移通道。

## 决策

新增四张宿主级表：

| 表 | 职责 |
| --- | --- |
| `plugin_state` | 插件全局开关；缺行 = manifest `defaultEnabled` |
| `plugin_entry_visibility` | `scope_key`（topic:/repo:/group:）→ 入口可见性/排序；缺行 = 可见（opt-out） |
| `plugin_legacy_data` | 旧内置能力迁移暂存；task-template 从此消费 v18 `templates` 用户行 |
| `plugin_storage_migrations` | 插件自有表结构版本；宿主只记版本号，不认识插件表 |

## 口径

- **内置行不迁**：`templates.builtin=1` 由插件包代码声明的内置入口接管；只迁 `category='newtask' AND builtin=0 AND deleted_at IS NULL`。
- **templates 暂不删除**：v19 只暂存；v20 在旧内置实现删除后补拷最后一刻用户行并 DROP，避免 v19/v20 之间旧代码写入的数据丢失。
- **插件存储仍走 nxkv.db**：v1 插件由插件包 `migrateStorage(db, fromVersion)` 创建自己的命名表，保持 single-writer 与现有 VACUUM 备份体系；外部不可信插件后续再接独立 DB / worker。
- **失败隔离**：单插件入口/草稿失败只跳过该插件并记 warning，不影响其他插件与任务交付。

## 被否决

- 直接让宿主认识 `plugin_task_templates`：破坏插件自封闭，新增插件必须改宿主迁移。
- 每个 topic 改插件开关：用户要的是「全局开关 + 每 topic 入口可见性」，两者分开才能表达「插件启用但某主题不显示某入口」。
- v19 直接 DROP templates：旧前端/旧服务仍在运行时会立刻读不到表，且无法补拷最后一刻数据。
