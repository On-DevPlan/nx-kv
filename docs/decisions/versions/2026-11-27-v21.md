# v21：每个 scope 可指定「新建页」默认入口

- date: 2026-11-27
- version: 21
- migration: `src/core/db/migrations/v21.sql`
- tables: `plugin_entry_visibility` 增加 `is_default`

## 背景

v19 的 `plugin_entry_visibility` 只记录「哪些入口可见 + 顺序」；点击「＋ 新建页」时,
默认触发哪个入口完全由插件自己声明（task-template 的 `default: true`），
主题级无法选择。不同插件都会注册列表项后，默认行为需要在**当前 scope** 里显式配置。

## 决策

1. 在 `plugin_entry_visibility` 上加 `is_default INTEGER NOT NULL DEFAULT 0`；
   每个 `scope_key` 最多一行 `is_default=1`（写入时先清后设，由宿主保证）。
2. 缺行 / 没有 `is_default=1` = 跟随插件声明的默认入口（再回落首个草稿入口）。
3. 配置了默认但入口后来被隐藏时，`listEntries` 只在实际可见入口里取默认，
   `is_default` 行保留（重新勾选可见即恢复），不做隐式清理。
4. 默认入口可以是任意 `kind`（draft 或 panel）：面板入口点击后直接进插件页面。

## 口径

- 存储层只认 `scope_key`（`topic:` / `repo:` / `group:`），与可见性同一张表、同一个保存入口。
- `plugin set-visibility` 不动 `is_default`（避免只改可见性时误清默认）；
  `plugin set-default --scope <scopeKey> --entry <entryId>` 专门设默认，空 entryId = 跟随插件默认。

## 被否决

- 新开一张 `plugin_scope_default` 表：一个 scope 至多一个默认，独立表只是同一主键的重复。
- 把默认写进 `topics.ext` / `repos.ext`：scope 有三类宿主，且插件相关配置应聚在插件宿主表。
- 用 `settings` k/v 存：会让「入口配置」分散在两套读写路径，设置页语义也不同。
