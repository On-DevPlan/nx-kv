# A03 · 完成与「按反馈派生下一轮」（reopen）

## 三步

1. 干完 → `localtask done --id N --summary "…"`（summary 必须写：它是下一轮唯一的上文）。
2. 若返回 `blocked / goal_not_reached`（时间目标未到）→ **不要硬标**，派 sub agent 重提需求，
   等 `timegoal check` 的 `reached:true` 再 done。
3. 用户提修改意见 → `localtask reopen --id N …` 让系统**派生下一轮**，不要自己 `add` 一条新任务。

## 标完成

```bash
nx-kv localtask done --id <n> --summary "改了什么 / 关键决策 / 遗留问题" --json
```

`--summary` 记为该任务的终态 + timegoal 日志，也是**下一轮正文里的完成总结 callout**。
不要写「已完成」「搞定了」。

被时间目标挡住时返回业务结果（不是错误）：

```json
{ "status":"blocked", "reason":"goal_not_reached", "remainingSec":1830,
  "hint":"时间未到，不能标记完成——请派出 sub agent 重新提出新的需求；到点后…再来标完成" }
```

处理：按 hint 派 sub agent 重提需求，check 返回 `reached:true` 后再 done。

## `reopen` 到底是什么（**不是把 done 改回 pending**）

源码口径是 **T04 派生模型**：名字叫 reopen，行为是「按反馈**派生一条新任务**」，旧任务定格。

```bash
# 用户给了新诉求原文 → 新任务正文整篇替换（保住 frontmatter）
nx-kv localtask reopen --id <n> --text "<改后的正文>" --kind reopen --json
# 只想把反馈追加到正文末尾 → 系统自动带上上一轮的完成总结 callout
nx-kv localtask reopen --id <n> --feedback "<用户原话>" --kind reopen --json
# 划选评论（不增加轮次）
nx-kv localtask reopen --id <n> --feedback "<评论>" --kind comment --quote "<划选的原文>" --json
# 看整条派生链（根 → 当前尖）
nx-kv localtask chain --id <新任务 id> --json
```

| 对象 | 结果 |
| --- | --- |
| **旧任务（父）** | `done` **保持 done**（交付事实不消失）；若还是 `claimed`/`pending` → `cancelled` + `supersededBy` 指向新任务 |
| **新任务（子）** | **新编号**、`round = 父 + 1`、状态 `pending` 立即可领；时间目标/依赖/闸门跟着走（重新计时） |
| **正文** | 给 `--text` 就整篇替换；只给 `--feedback` 就 = 旧正文 + 第 N 轮完成总结 callout + 反馈段（reopen 逐行加粗，comment 不加粗） |
| **链** | `task_links(src=新, dst=旧, type=reopen\|comment)` 是唯一来源，`chain` 读它；`history[]` 已下线 |

两个容易踩的点：

- 对**已被取代的 cancelled 任务**再 reopen → 自动顺链走到当前尖，从尖上派生（不会让死记录复活）；
  手动作废（无 superseder）的 cancelled 会被拒绝，要继续请新建任务。
- `--feedback` 的 base 永远是**服务端最新正文**，连续评论不会「评论一次丢一次」。

所以：用户改意见 → `reopen`（命令负责建新号、串链、带总结），你随后 `get` 领到的就是
新编号的下一轮；**不要用原编号去 `done`/`update`**。

## 偏差

| 偏差 | 正确做法 |
| --- | --- |
| 以为 reopen 把 done 改回 pending、还用原编号继续 | 它是派生新编号；后续动作都用新 id |
| 用户提意见就自己 `add` 一条 | 用 `reopen`，链和完成总结才不会丢 |
| `done` 不写 summary | 必须写：下一轮正文会引用它 |
| 被 `blocked` 后硬改时间 / 绕过 | 按 hint 派 sub agent 重提需求 |
