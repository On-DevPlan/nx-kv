# 场景：领任务 · 确认意图 · 再解决

> 归属主文档 [[nx-kv]]。当你是**任务队列的消费端**——提交方把任务投到某个 `topic`，
> 你负责领任务、对齐意图、做完回填——读本文件。

关键在中间那几步「确认」：**不确认不动手**。任务往往模糊、多条、或覆盖多个主题，
先对齐能避免大段返工。

## 何时进入

- 用户让你「领取 / 看一下 / 处理」某个主题的任务
- 用户提到「发布的任务」「任务队列」「todo 清单」「待办」
- 你被分配了清单上的任务，需要消费
- 用户要求「先确认意图再执行」「把任务聚类成文档」

不确定是否该进入时，**倾向进入**——这比跳过确认直接开干安全得多。

## 两条行为准则（必读，覆盖全流程）

> 遇到相应场景**主动先问用户**再行动，不要沉默地自行处理。

### 1. 清理 / 覆盖上下文时，先问用户

删除、改写、合并、丢弃任何上下文信息（任务文本、topic 提示词、之前的状态、用户给的背景）
之前，主动向用户确认：**是要丢弃、改写还是补充？**

沉默的清理 = 信息丢失 + 用户不知情。

### 2. 先自己查到底，摸不到底再问

拿到需求 → **先别问、自己去摸** → 摸不到底再问。

**第一步：在当前目录穷尽调查。** 翻代码、读文档、读配置、查 git 历史、看相关任务、
跑命令验证、读测试、用 grep/find 搜。

- 当前目录**能回答的，不许问用户**
- 不许「凭常识猜默认值」「还没查就先问」「查到一半就问」、把能查到的推给用户

**第二步：确实超出当前目录能力，才问用户。** 确认无法解决后，告诉用户
「**我已经查过 X、Y、Z，缺的是 W，请提供**」——把已查证据一起摆出来。

真的需要外部资源的：配置项 / 凭据 / 外部 prompt / 别的项目文件 / 用户主观偏好 / 业务决策。

> 反例：任务说「线上如何访问」，直接问「线上地址是？」。正确做法是先看 `deploy.yml` /
> `docker-compose` / `README` / `docs`，能推断就推断，推断不出再问并摆已查证据。

## 前置依赖

- **动手前必须调用** `superpowers:writing-plans`
- 时机：**Step 7 确认主题意图之后、Step 8 开始解决之前**
- 把已确认的意图作为 spec 交给它，产出实现计划（存 `docs/superpowers/plans/YYYY-MM-DD-<feature>-indent.md`），**按计划**再解决
- 任务拆分、写法、执行交接都以 `superpowers:writing-plans` 为准，本文件不重复

## 核心流程（8 步）

```mermaid
flowchart LR
  A[1 确认登录与工作空间] --> B[2 取该 topic 全部待办]
  B --> C[3 读上下文提示词 + 润色]
  C --> D[4 不立即执行 → 摆给用户确认/补充]
  D --> E{多条任务?}
  E -- 是 --> F[5 按主题聚类]
  F --> G[6 生成意图文档]
  G --> H[7 确认主题意图 + writing-plans]
  E -- 否 --> H
  H --> I[8 解决 + done 回填]
```

### Step 1 — 先确认登录与工作空间

```bash
nx-kv auth status --json     # loggedIn / groupId
nx-kv group current          # 当前在哪个空间
```

**先确认空间对不对**：数据按 `groupId` 隔离，在错的空间里会「什么都查不到」——
而那不是「没有任务」，是「看错地方了」。这一步不花什么时间，却能避免整轮白干。

### Step 2 — 一次拿全该 topic 的待办

```bash
nx-kv todo list --status open --topic <topic> --json
```

**不要「拉全量再自己过滤」**：`--topic` 已经做了，而全量里还混着别的主题和已完成历史
（done 里有重复 id 和长 note，会白占大量上下文）。

> ⚠️ **禁止** `nx-kv todo list --json | ...按 topic 过滤...` 这套自己过滤的做法。

### Step 3 — 读上下文提示词 + 润色

**探索整个项目时派一个 subagent 收集上下文**，比你自己逐个文件翻更省上下文：

- 读该 topic 的提示词：`nx-kv prompt get <topic> --json`（`{topic, prompt, hasPrompt}`）
  —— 它是 topic 级的共享背景（项目约定、技术栈、注意事项），**不是可选项**：缺了它，任务往往只是「半句话需求」
- 读任务文本，把含糊措辞、缺的信息、明显的错误标出来
- 把每条任务**改写成清晰的表述**（可执行、有边界、可验收），但**不改原意**
- 可选：让 subagent 一并返回相关的、可作为依据的 skill 条目

### Step 4 — 不要立即执行，先摆给用户确认

拿到任务**先停下来**。直接开干是这里最常见的错误。

把润色后的任务清单摆给用户：

- 每条确认「你理解得对不对」
- 让用户补充缺失的背景、约束、优先级
- 合并 / 删除过时任务在这里一并敲定

### Step 5 — 按主题聚类

若有多条任务，按**主题**聚类（如「CLI 重构」「测试补全」「文档」各成一簇）。
一条任务只属一簇，簇名即主题意图。

### Step 6 — 生成意图文档

把聚类结果写成结构化文档（如 `.claude/repo/_self/<主题>-意图.md` 或
`docs/superpowers/specs/` 下的设计文档）：

- 每个主题：任务列表、目标、上下文/提示词摘要、边界、验收标准
- 文档既是 Step 7 确认的载体，也是后续执行的依据

### Step 7 — 确认主题意图 → 交给 writing-plans

把文档 / 聚类结果交给用户确认每个主题的意图与优先级。**用户拍板后才算对齐。**

对齐后**立即调用 `superpowers:writing-plans`**，把已确认的意图作为 spec 产出实现计划。
计划落地后才进 Step 8。

### Step 8 — 按计划解决 → **完成即回填 `todo done`**

按主题逐簇解决。**每解决完一条，立即回填**——这是收单闭环的最后一步，
漏掉会让任务一直挂在 open 队列：

```bash
nx-kv todo done <id> --result "改了什么 / 怎么验证 / 遗留问题"
```

- 领取时（Step 2）**记下每条任务的 `<id>`**，回填时用同一个
- `--result` 写清楚，供下次查阅、也供提交方确认
- 同主题多条任务**逐条解决、逐条回填**，不要攒到最后一次填

> ⚠️ 回填前确认 id 没歧义。done 里会积累同 id 的多条，报「命中 N 条」时用 `--topic` 或 `--pick` 选准
> —— 详见主文档的「id 不是唯一键」一节。

## 稳定契约（可依赖）

| 契约 | 内容 |
| --- | --- |
| `--json` | 单个 JSON 值到 stdout；无多余文本 |
| 退出码 | `0` 成功；`1` 失败（含需消歧的情况） |
| 错误码 | `code` 可取 `INVALID_INPUT` / `NOT_FOUND` / `CONFLICT` / `EXTERNAL`，优先用它分支 |
| 错误文本 | 含「未登录」「不存在」「用法:」等稳定锚点，可作兜底判断 |
| 幂等 | 重复 `topic add`、删除不存在的主题都不报错 |
| 状态冲突 | 已完成再 `done`、已冻结再 `freeze` → `CONFLICT` + exit 1；语义是「已经是你要的」，跳过即可 |

**一次拿齐上下文**：`nx-kv bootstrap --json` 返回版本、登录态、当前工作空间、
工作空间列表与完整命令表，省去多次往返。

## 安全边界

- **不要**往别的 topic 写任务来「提醒自己」——那是污染别人的队列
- **不要**在没有消歧的情况下对 `done` 里的 id 做删除
- 切换工作空间前先确认，别在别人的空间里写数据
- `--password` 写在命令行里会进 shell 历史；交互式输入更安全

## 避坑

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| 直接动手不先确认意图 | 任务文本常是半句话，盲目执行必返工 | 走 Step 4：润色 → 摆给用户 → 用户补充 |
| `todo list --json` 再自己过滤 topic | 多写一坨过滤逻辑、易错，还把 done 的历史噪音拉进来 | `todo list --status open --topic <t>` 一步到位 |
| 拿待办时用了不带 `--status open` 的 `list` | done 数组带出重复 id 历史 + 长 note，上下文被大量占用 | 领取待办一律 `--status open --topic <t>`；要看完成历史才用全量 |
| 解决完不回填 `done` | 任务一直挂 open，队列失真、提交方不知完成 | 解决一条立即回填，`--result` 写明结果 |
| 回填用错 id | 报了别的任务的完成 | 用 Step 2 拿到的 open 里的那个 id；有歧义时加 `--topic`/`--pick` |
| 未登录就调 todo | 报「未登录」exit 1 | 先 `nx-kv auth login <email>` |
| 沉默清理上下文（丢弃/改写/合并任务文本、prompt、用户背景而不告知） | 信息丢失、用户不知情、难以回滚 | 删除或改写前先问：丢弃 / 改写 / 补充？ |
| 需要外部资源就直接问（或凭「常识」猜默认值） | 下游全错、用户反复回答、推进变慢 | 先在当前目录穷尽调查，超出能力再问，且必须带「我已查过哪里、缺什么」 |
