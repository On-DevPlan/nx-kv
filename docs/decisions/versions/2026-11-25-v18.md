## 问题

存量数据里存在「活任务挂在软删队列上」的幽灵形态：任务 `status='pending'`（没跑完的活），
但它所在的队列 `deleted_at` 非空——侧栏/目录列表看不见这个队列，agent 按任何 cwd
都领不到任务，任务成了不可寻址的死数据。

来源（考古）：历史版本的 `prune --all-finished` 清理过当时已完成的队列（软删，tasks
保留），任务后来经 reopen / 状态回退变回 pending；以及旧模型分支的清理没带 pending 守卫。

## 裁决

**恢复队列，不删任务。**

- 待领（`status='pending'`）= 没跑完的活，必须恢复可见：队列去掉 `deleted_at`，
  任务回到「可寻址、可领取」状态。目录即使已不存在，任务内容自包含，agent 仍可按
  cwd 显式领取；UI 的 `cwdExists=false` 幽灵标志本来就有，用户自行决定清或留。
- `done` / `cancelled` → 不动：已完成的任务挂死队列只是历史记录，恢复反而让幽灵
  队列重新出现在侧栏。

## 防回归（代码同步）

`pruneTopics` 的旧模型分支（`isLegacy = !t.cwd`）补 pending 守卫——此前它没有
`!hasPending`，带待领任务的旧模型队列会被清成幽灵（prune 的其它分支
missing-dir / isFinished 本来就有守卫）。

## 实现

纯数据 UPDATE（v18.sql，无 DDL）：

```sql
UPDATE topics SET deleted_at = NULL, updated_at = <now>
 WHERE deleted_at IS NOT NULL
   AND EXISTS (SELECT 1 FROM tasks
                WHERE tasks.repo_topic_id = topics.id
                  AND tasks.deleted_at IS NULL
                  AND tasks.status = 'pending');
```
