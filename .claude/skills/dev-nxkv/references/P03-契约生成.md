# P03 · 原语 · 契约生成（gen / Dart 包 / guard）

> 被 `R01-加一种资源类型.md`、`R02-加或改命令与业务规则.md`、`R06-发版.md` 引用。
> 契约生成物入库、随版可见（端侧靠 git sha 锁版本，不需要单独发布流程）。

## ① 前置（先跑，拿事实）

```powershell
pnpm run                              # gen / gen:dart / gen:api 的定义在 scripts 里
ls contract/                          # contract.json + dart 包
git status --short contract/          # 生成物有没有未提交的差异
```

## ② 动作

```powershell
pnpm gen          # = gen:actions + gen:api：刷新 _manifest.generated.ts 与前端 typed client
pnpm gen:dart     # 写 contract/contract.json + contract/dart/**（版本号嵌在契约快照里）
```

- 只有声明了 output 的 zod action 进契约——**不对外就不在契约里**。
- `pnpm gen:dart --check` 只比对不写；不一致就 exit 1（CI / guard 用这条）。
- 改了 action 声明 → gen 之后**重启 serve**，否则跑的还是旧路由（路由在进程启动时编译）。
- `.github/workflows/contract-guard.yml` 守四条底线：
  1. 声明改了却没重新生成 → 红；
  2. 生成包必须自包含可解析（pubspec 缺 `environment` 会被 pub 判成 legacy 包，报错完全不指向真因）；
  3. `.dart_tool` / `pubspec.lock` 不许入库；
  4. 契约变了 → 在汇报/PR 描述里点名让 Dart 端 bump。

## ③ 自检

```powershell
pnpm gen:dart --check                 # 无差异输出（退出码 0）
git status --short contract/          # 生成的变更随本次任务一起提交
pnpm typecheck                        # 前端 typed client 与声明一致
```

## ④ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| contract guard 红 | 只跑了 `pnpm gen` 没跑 `gen:dart` | 补 `pnpm gen:dart` 再提交 |
| 前端调接口类型报错 | 没跑 `pnpm gen` | 跑 gen 再 typecheck |
| Dart 包被判 legacy / 不支持 null safety | pubspec 缺 `environment` | 恢复 environment 字段，不许删 |
| 面板请求新接口 404 | 路由进程启动时编译 | 重启 `node bin/kv.mjs serve` |
| `gen:dart` 拒绝生成 | 没有任何 action 声明 output | 确认哪些 action 要对外（声明 output） |

## ⑤ 反模式

- 手改 `contract/` 下任何生成物（`--check` 会红，且下次生成直接覆盖）。
- 把不该对外的 action 声明了 output（契约面积无谓变大）。
- 把 `.dart_tool` / `pubspec.lock` 提交进库。
