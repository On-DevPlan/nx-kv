# T06 · 改内置技能 / 用户文档

> 两个 skill 别混：`assets/nx-kv/` 是**给使用者（agent）的说明书**，随包发布；
> `.claude/skills/dev-nxkv/` 是**给改代码的人的动作手册**。改错地方等于没改。

## ① 前置（先跑，拿事实）

```powershell
ls assets/                              # 现有内置技能目录（历史上曾有多个，已合并）
cat assets/groups.json                  # group → skills 别名表
ls assets/nx-kv/references/             # 消费侧的 SOP 文件
node bin/kv.mjs skill list              # 已装到本机的 skill
node bin/kv.mjs skill get nx-kv         # 安装时会输出什么（这一份才是用户看到的）
grep -rn "<改动的命令名>" assets/ | head -20   # 找出所有提及处，别只改一处
```

## ② 先判定：改哪一侧

| 改的东西 | 位置 |
|---|---|
| agent 怎么用这个工具（领任务、建组、传附件） | `assets/nx-kv/` |
| 开发者怎么改这个仓库（加表、加 action、跑门禁） | `.claude/skills/dev-nxkv/`（就是本 skill） |
| 用户读的安装/介绍文档 | `README.md`、`docs/` |
| 对外行为变更记录 | `CHANGELOG.md` |

一次行为改动**通常要同时动四处**：命令实现、`assets/`、`README.md`/`docs/`、`CHANGELOG.md`。

## ③ 动作

1. **改 SKILL.md 的 frontmatter**：

```yaml
---
name: nx-kv
description: <一句话定位> 覆盖：<场景列表>。触发词：<用户可能说的原话，逗号分隔>。
---
```

`description` 是唯一的触发依据。写「用户会怎么说」，不要写「本 skill 提供了……」这类自述。

2. **改正文/引用**：`assets/nx-kv/references/` 下一文件一个场景，SKILL.md 只做路由表。
3. **命令/参数变了 → 全量搜一遍**：

```powershell
grep -rn "localtask done" assets/ README.md docs/ | head
```

漏改某处，agent 会照旧文档调错参数。

4. **增删 skill 目录**（一般不需要，现在只有 `nx-kv` 一个）：同步 `assets/groups.json` 的 `group` 名与 `skills[]`，`skills` 不能为空。
5. **记一笔变更**：`CHANGELOG.md` 写「为什么」而不只是「改了什么」。

## ④ 自检

```powershell
node bin/kv.mjs skill get nx-kv | head -30                 # 输出的是新版
node --import tsx --test tests/unit/bundled-multiskill.test.mjs
node --import tsx --test tests/unit/bundled-*.test.mjs
```

| 检查 | 通过判据 |
|---|---|
| frontmatter 合法 | `name` / `description` 都在，description 含触发词 |
| 内容可达 | `skill get <name>` 能看到新增段落 |
| 分组正确 | `skill groups` 输出里 group 与 skills 对应 |
| 无漏改 | `grep` 找旧命令名应为 0 命中 |

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| `skill list` 里该 skill 消失 | 目录缺 `SKILL.md` 或 frontmatter 坏了 | 补文件；`name` 与目录名一致 |
| 分组降级成「每个目录各一组」 | `groups.json` 缺字段 / schema 错 | 按现有文件结构补全 |
| 测试改到了仓库里的 `assets/` | 没指伪资产树 | 用环境变量 `NX_KV_ASSETS` 指向临时目录 |
| agent 不触发 | description 写成了自述、缺触发词 | 换成用户原话式触发词 |
| `skill get` 输出旧内容 | 读到的是 `~/.claude/skills` 已装副本 | 重新 `skill install`，或直接看仓库里的 `assets/` |

## ⑥ 反模式

- 只在 `assets/` 改，不改 `README.md`/`docs/`（使用者看到两个版本）。
- 把开发手册写进 `assets/`（使用者不需要「怎么加迁移」）。
- description 写成一段产品介绍（触发靠关键词，不靠文采）。
- 在 `assets/` 里贴大段命令表——那是会腐烂的知识，改成「跑哪条命令查」。
