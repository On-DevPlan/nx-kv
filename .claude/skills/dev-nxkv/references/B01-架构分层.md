# B01 · 架构分层：代码放在哪、谁能 import 谁

> B 序列 · 架构之一。回答「这个改动该落在哪一层、依赖方向是什么、模块骨架长什么样」。
> action 的声明与注册见 [[B02-action注册全表]] 与 [[B03-action契约]]。

## 1. 依赖方向（单向，不可逆）

```text
bin/kv.mjs ─┐
src/index.js ─┼─→ runtime ─→ modules ─→ core
（包外垫片）   │              └→ shared ←─┘
web 前端 ─────┴─→ /api ─（HTTP）─→ runtime
              └→ shared（仅纯函数）
```

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 入口 | `bin/kv.mjs` | 注册 tsx loader → Node 版本硬拦 → 动态 import `src/runtime/cli.ts`。**直跑 TS 源码，不走 dist**（避免「改了忘 build」导致全局命令静默跑旧逻辑） | 写业务 |
| 包外垫片 | `src/index.js` | 唯一的 `.js`：注册 tsx 后转发 `src/index.ts`，让普通 Node `import('nx-kv')` 能跑 | — |
| 运行时 | `src/runtime/` | registry / cli / api / server / cors / spec / **模板契约层**（ModuleBase、ActionBase、@action、container）/ zod-bridge / codegen | 写业务 |
| 功能域 | `src/modules/<id>/` | action 声明 + 业务 + 仓储 | import 别的模块内部实现；import runtime **装配层** |
| 原语 | `src/core/` | db、errors、模板引擎、workflow、路径、配置等跨模块原语 | 依赖 modules / runtime / web / shared；**放业务** |
| 同构 | `src/shared/` | 前后端**同构**的纯函数/常量 | 依赖任何东西（含 `node:`、第三方包）；有状态 |
| 前端 | `src/web/frontend/` | 面板（全 TSX/TS） | import 后端模块（`client.generated.ts` 的 type-only 引用是唯一豁免） |

四条不可破的规则：

1. `runtime → modules` 允许；**反向禁止**。需要运行期数据（命令表）时，由 runtime 把表**传给**模块的纯函数（`src/core/command-table.ts` 快照格子）。
2. `modules/A → modules/B` 只能经 B 的 `service.ts` 导出面；禁止深入 `B/repo`、`B/actions` 内部。`system` 是唯一豁免（聚合模块）。
3. `core/` 只放原语，`shared/` 只放无副作用纯函数，**业务留在模块 service**。
4. 前端只消费 `/api/*`；前端不得 import 后端模块，跨端纯函数放 `src/shared/`。

### 全仓 TS 与 import 后缀约定

- 源码**只有** `.ts` / `.tsx`（`tsconfig.node.json` / `tsconfig.web.json` strict 全开，`allowJs`/`checkJs` 已移除）。唯一的 `.js` 是 `src/index.js` 垫片。
- **import 路径保留 `.js` / `.jsx` 后缀**（NodeNext + tsx loader / vite 的解析约定）：文件是 `service.ts`，import 写 `'../service.js'`；文件是 `App.tsx`，import 写 `'./App.jsx'`。**不要把 import 里的后缀改成 `.ts`**——`pnpm typecheck` / `pnpm dev` / 构建三条路径都按旧约定解析。
- node 侧出 `dist`（`tsc -b tsconfig.node.json`，供库消费）；bin 直跑源码。web 侧 `noEmit`，只查类型（产物归 vite build）。

### eslint 的强制方式与它的盲区

- `eslint.config.js` 用 `no-restricted-imports` 表达分层规则；`tests/unit/layering.test.mjs` 解析真实路径再比对层次，是第二道执行者。
- **模块互依禁列是枚举式**：当前只列了 `../repos/*`、`../skills/*`、`../github/*`、`../bundled/*`、`../system/*`、`../todo/*`、`../sessiontask/*`。其中 `skills` / `github` / `sessiontask` 已不存在（历史遗留），`setting` 未被列入。**新增模块必须手动补 `'../<新模块>/*'`，漏补不会报错。**
- **runtime 装配层禁列**（`RUNTIME_ASSEMBLY_BAN`）：模块不得 import `runtime/{cli,registry,server,api,spec,help,codegen}`（会成环）；但 runtime 的**模板契约层**（`types/module`、`action-base`、`action-decorator`、`container`）是模块按模板写就必须 import 的公共契约，不在禁列。
- 类型层检查归 `pnpm typecheck`（strict tsc）：TS/TSX 文件的 `no-undef` 已**关闭**（tsc 报 `Cannot find name`，且能认出类型位置上的 DOM 名字，比 lint 准）；前端全局面（window/document/fetch…）白名单仍开着，只兜存量 JS。
- `@typescript-eslint/no-explicit-any` 目前是 **warn**（迁移期宽容；从 legacy JS 迁来的 action 体与服务层绑定还没完全类型化，随服务层毕业逐步收紧）。
- 其他门禁脚本（都进 `pnpm lint`）：`check-tdz.mjs`（TDZ 全量扫描）、`check-schema-decisions.mjs`（schema 决策注释，见 [[A01-数据模型]] §2）、`check-lines.mjs`（行数门禁：≤500 干净，601–1000 须登记 `scripts/line-lint-registry.json` 且只许降，>1000 禁止）。

src/modules/<id>/

  actions/_manifest.generated.ts  codegen 产物：收进本目录所有 ActionBase 子类

  api/cli-tree.json            **codegen 产物**：CLI 命令树快照

  route-map.ts                 路由 ↔ 面板的纯映射外壳（归一入参 + 拼 PanelSpec；不引 React）

### TS 化：已完成（2026-11，plan/174 起）

骨架按 `nx-nx/templates/server-cli-web` 模板形态落地；**shared → core → 服务层 → 前端 → action 注册层**
全部毕业 TS，strict 全绿，`allowJs` 已移除。某文件「毕业」不再是一件事——新代码**直接写 TS**，
别再新增 `.js`/`.jsx`（唯一的例外是 `src/index.js` 垫片）。

- 门禁：`pnpm typecheck`（tsc -b，strict）+ `pnpm lint`（typescript-eslint + 三个检查脚本）+ `pnpm gen`（codegen 新鲜度）。
- 迁移器产物里的过渡形态（`const service: any = serviceNs`、`as any` 局部 cast）会随服务层
  类型化逐步清掉；新写的 action **不要模仿**这些 cast，直接走严格类型。

## 4. 模块骨架

### `index.ts`：只做元信息 + 装配

```ts
import { ModuleBase } from '../../runtime/types/module.js';
import { zodActionsOf, type ZodBoundAction } from '../../runtime/action-decorator.js';
import { container, type Container } from '../../runtime/container.js';
import { ACTIONS } from './actions/_manifest.generated.js';

export class DemoModule extends ModuleBase {
  override readonly id = 'demo';
  override readonly title = '演示';
  override readonly order = 100;

  // actions 在构造期组装（依赖要先就绪），故用确定赋值断言而非字段初始化器。
  override readonly actions: readonly ZodBoundAction[];

  constructor(c: Container = container) {
    super();
    this.actions = ACTIONS.flatMap((Cls) => zodActionsOf(c.create(Cls)));
  }
}
```

- 模块**不手工列举 action**：清单由 `pnpm gen`（gen:actions）扫 `actions/` 目录生成到
  `_manifest.generated.ts`。加一条 action = 新建一个文件 + 跑一次 `pnpm gen`，index.ts 零改动。
- `resource` / `resources` 只读字段声明 CRUD 完备性（见 [[B03-action契约]] §5）。
- **没有模块级 `view`**：视图归前端 `registry.ts`，`tests/unit/registry.test.mjs` 会断言后端不出现该字段。

### `actions/<名>.ts`：一条 action 一个文件

契约（zod schema）内联在 action 文件里（#178 起，不再有 `schemas.ts`），完整形状见
[[B03-action契约]]。要点：`@action({ id, cli, http, summary, input })` + `override run(ctx: ActionInput<this['_input']>)`。

### `service.ts`：业务与事务

- 事务用 `txw((conn) => { … })`；回调**同步**，里面不要 `await` 网络/文件 IO。
- 跨表写入、编号分配、依赖写入必须在同一事务。
- 抛错用 `src/core/errors.ts` 的 `badInput` / `notFound` / 等，保持 CLI 错误可读，并让 HTTP 错误码能映射到状态码。

### `repo/`：SQL 仓储

- `repo/open.ts` 统一提供 `db()` / `txw`；**SQL 只出现在 `repo/*.ts`**。
- 行 ↔ 领域对象映射集中在 `rows.ts`（例：`tasks.body` → JSON `text`、`from_src` → `from`）。
- 新查询默认过滤 `deleted_at IS NULL`。
- 时间戳统一 `core/db/time.ts` 的 `nowMs()`。

### 何时用 `ext` JSON

- 只放「展示附属信息」：icon、备注、原始远程列表、旧 id 取证等。
- **凡是要进 WHERE / 排序 / 唯一约束的字段，必须是真实列**（ext 无索引）。详见 [[A03-键与扩展位]]。

## 5. 新增一个模块的步骤

1. 建 `src/modules/<id>/index.ts`（ModuleBase 子类）、`service.ts`，需要持久化就建 `repo/`。
2. 建 `actions/<名>.ts`（一条 action 一个文件），跑 `pnpm gen` 生成 `_manifest.generated.ts`。
3. 在 `src/runtime/registry.ts` import 并加入 `MODULE_LIST`。
4. **在 `eslint.config.js` 的模块互依禁列里补 `'../<id>/*'`**（枚举式，漏补是静默的）。
5. 需要面板：在 `src/web/frontend/page/<id>/` 写视图，并登记到 `src/web/frontend/registry.ts`（见 [[D02-页面与组件关系]]）。
6. 加测试：`tests/unit/registry.test.mjs` 会校验两侧模块集合对齐、视图归属的模块已登记、视图文件存在、`/api` 字面量有对应路由；补该域单测。
7. 更新 `README.md` / `docs/` / `assets/`（若对使用者可见）。
8. 跑 `pnpm lint && pnpm typecheck && pnpm test:unit && pnpm build`。

## 6. `assets/`：用户侧 agent 的说明书

`assets/` 随包发布，由 `src/modules/bundled/` 的 `skill list/groups/install/get` 安装到 `~/.claude/skills`，或直接 `skill get` 吐全文：

```text
assets/
├── groups.json     # group 名 → skills[] + summary（别名表，不是第二事实源）
└── nx-kv/          # 每个目录一个 skill，必须有 SKILL.md
                    # 原 kv-get / kv-submit / kv-repo 三个 skill 已并入 nx-kv，不要再建
```

同步规则：

- 命令 / flag / 输出口径变了 → 改对应 `assets/<name>/SKILL.md` 与 `references/*.md`；`grep -rn "<命令名>" assets/` 找齐。
- 增删内置 skill → 建/删目录 + 同步 `groups.json`（group 名 kebab-case、`skills` 非空）。
- `groups.json` 缺失 / 错 schema 会降级成「每个目录各成一组」；测试 `bundled-multiskill.test.mjs` 用 `NX_KV_ASSETS` 指向伪资产树，**不要用测试改仓库里的 `assets/`**。
- assets 变化是对外行为，进 `CHANGELOG.md`。

## 7. 文件体量

`scripts/check-lines.mjs` 门禁（进 lint）：单文件 ≤500 干净；601–1000 是警告区，必须登记
`scripts/line-lint-registry.json`（登记值即上限，**只许降不许升**）；>1000 登记也不放行，必须拆分。
登记项随文件瘦身失效（≤600 后登记过期必须移除）。拆分按职责，不要按「代码行数」机械切。
