# kv-submit — 提炼需求，委托其它 agent（提交侧）

把「这个对话里的上下文 + 用户需求」变成一条**自包含**的任务，投进目标工作目录
的任务队列。在那边工作的 agent（正在 wait 的立刻收到；不在等的下次领取）接手
执行。**你发的是任务，不是对话记录**——接收方看不到你的对话，任务文本必须
自己站得住。

## 三步走（核心流程）

1. **总结上下文**：当前对话聊了什么、做了哪些决策、涉及哪些文件/路径/约定。
   只挑与需求相关的，不搬流水账。
2. **提炼用户需求**：把用户散落的表述收敛成一句明确的目标 + 验收标准；
   有歧义的先向用户确认，不要把猜测提交出去。
3. **打包提交**：写成自包含任务文本（模板见 [[submit-workflow]]），投给目标目录：

```bash
# 提交到目标目录的队列（务必加 --json；--cwd 是接收方 agent 的工作目录）
nx-kv localtask add "<任务文本>" --cwd "<目标工作目录>" --json

# 可选：顺带刷新该目录主题的现状展示（面板/弹窗顶部那句话）
nx-kv localtask add "<任务文本>" --cwd "<目标目录>" --summary "<该目录当前现状>" --json
```

返回 `{status:"ok", task:{id,text,...}, queued|delivered}`：

- `queued:true`（跨进程提交的常态）→ 已入队；目标目录里正在 wait 的 agent
  会在约 0.5 秒内取走，没人等就排在队列里等它下次领取。
- 记下 `task.id`，向用户报告「已提交到哪个目录、第几号任务」。

## 任务文本怎么写（一句话版）

接收方没有你的上下文，任务文本按这个顺序组织成一段（单行，用 ①②③ 编号，
总长 ≤20000 字）：

> 目标：做什么、做到什么程度算完成。
> 背景：相关文件/目录路径、已确定的技术决策、必须遵守的约束。
> 注意：不要做什么、有哪些坑（如果有的话）。

细节模板、多任务拆分、提交后的跟踪，读 [[submit-workflow]]。

## 硬规则

1. **`--cwd` 必须填接收方 agent 实际所在的目录**（目录名即主题；同名目录共用
   队列）。填错了任务就排到了没人看的队列——不确定就先问用户。
2. **任务文本自包含**：不写「如上所述」「刚才那个」，不引用本对话；路径写全。
3. **提交前把提炼结果给用户过目**（尤其需求是提炼出来的而非用户原话时），
   确认后再 `add`。
4. **大需求拆成多条按序提交**，每条一个可独立完成的单元；顺序重要时提交后用
   `localtask reorder` 校正优先级。

## 什么时候不用

| 场景 | 用哪个 |
| --- | --- |
| 你自己干完活、等用户在浏览器回填下一条 | kv-waittask（wait） |
| 主动领取排给**本目录**的任务 | kv-localget |
| 操作远程 KV 后端的 todo 清单（需登录） | nx-kv |
| 给**正在等待**的 agent 补一条任务 | 本 skill（add 到它的目录） |

## 与其它 skill 的分工

三者共享同一份本机任务存储与按目录划分的队列（`~/.nx-kv/localtasks.json`）：

- **kv-submit（本 skill）**：提交侧——总结上下文、提炼需求、投递到别的目录。
- **kv-waittask**：等待侧——目标目录的 agent 用 wait 阻塞接任务（人机接力）。
- **kv-localget**：领取侧——目标目录的 agent 主动领队列里的任务。
- **nx-kv**：远程 KV 后端的 todo 清单（需登录、按 groupId 隔离），与本机队列无关。

## 安装

```bash
nx-kv skill install kv-submit         # 装到 ~/.claude/skills/kv-submit
nx-kv skill list                       # 列出 nx-kv / kv-waittask / kv-submit / kv-localget
```
