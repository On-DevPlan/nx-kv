# A02 · 提交任务（把上下文 + 工程知识 + 关键路径写成一条自包含任务）

## 这一篇解决什么

「把这个活交给别的目录 / 别的 agent」→ 交出去的任务**自己站得住**：对方看不到本对话、
看不到你的窗口、不知道你刚才试过什么。

**你发的是任务，不是对话记录。**

## 四步

1. **总结上下文**：聊了什么、定了什么决策、涉及哪些文件/路径/约定。只挑与需求相关的，不搬流水账。
   会话很长要做整体交接时，先分层（旧对话给结构化摘要 + 最近对话逐字保留）。
2. **提炼需求**：目标一句 + 验收标准 + 约束。有歧义**先问用户**；提炼出来的表述（非用户原话）**先给用户过目**再提交。
3. **写成自包含任务文本**（单段，①②③ 编号，≤20000 字）：

   ```
   ① 目标：做什么、做到什么程度算完成
   ② 背景：相关文件/目录（写全路径）、已定的技术决策、必须遵守的约束
   ③ 注意：不要做什么、有哪些坑
   ```

   **②里要装的三样东西**（这是「自包含」的具体含义）：
   - **上下文**：这件事为什么存在、上一轮结论是什么；
   - **工程知识**：已经查过的源码位置（文件 + 函数名）、试过但行不通的路子；
   - **关键路径**：要改的绝对路径 / 关键文件清单，以及验证入口（跑哪条命令、看哪张表）。

4. **投递**（见下）——记下返回的 `task.id`，向用户报告「投到哪个目录、第几号」。

## 投递：三条路，按「谁该领」选

```bash
# ① 投到目标目录的队列（--cwd = 接收方 agent 的工作目录，不是你的）
nx-kv localtask add "<任务文本>" --cwd "<目标目录>" --json

# ② 不限定接收方 → 全局共享池（忽略 --cwd，谁闲谁领）
nx-kv localtask add "<任务文本>" --global --json

# ③ 挂到项目/组（任务才会出现在对应的组面板与项目上下文里）
nx-kv localtask add "<任务文本>" --project <仓库key> --board <组id> --json
```

返回 `{ status:"ok", task:{id,…}, queued|delivered }`：`queued:true` = 已入队（目标目录正在
wait/get 的 agent 约 0.5 秒内取走，没人等就排队）；`delivered` = 已经被领走。

**顺带刷新目录现状**（接收方领取时能看到）：加 `--summary "<该目录现状>"`。

## 多行 / 长文本：三种输入方式（别用引号硬拼）

正文天然是多行长文本。在终端里用引号硬拼极易踩转义坑——写文件更稳。

```bash
# ① 文件（推荐）：内容逐字成为任务正文，换行保留
nx-kv localtask add --file ./task.md --cwd "<目标目录>" --json

# ② 标准输入：管道进来
cat task.md | nx-kv localtask add --file - --cwd "<目标目录>" --json

# ③ 直接给字符串（短文本才用；注意 shell 的引号规则）
nx-kv localtask add "第一行
第二行" --cwd "<目标目录>" --json
```

**服务端（HTTP）**：POST `/api/localtasks`，body 里的 `text` 直接带 `\n` 即可（JSON 天生支持多行）；
`file` 字段也能给，但那是**服务端本机**的路径。**Web 面板**：任务编辑器是富文本区，多行直接敲。

三条路的口径一致：**正文逐字保留换行**。

## 附加开关（按需要挑）

```bash
# 带时间目标：领取即计时，未到点不许标完成
nx-kv localtask add "<任务文本>" --cwd "<目录>" --duration 2h --goal-prompt "<附加要求>" --json

# 依赖顺序：A 完了才允许领 B（DAG）
nx-kv localtask add "<B 的文本>" --cwd "<目录>" --block-by 12,13 --json

# 闸门：自身未完成时，它后面所有 pending 都不可领
nx-kv localtask add "<A 的文本>" --cwd "<目录>" --gate --json

# 派生自另一条（挂进任务链）
nx-kv localtask add "<文本>" --cwd "<目录>" --fork-of 42 --json
```

## 改一条还没被领的任务

```bash
nx-kv localtask update --id <n> --text "<改后的正文>" --json
nx-kv localtask update --id <n> --duration 90m --goal-prompt "<新要求>" --json
nx-kv localtask update --id <n> --clear-goal --json
```

**时间目标只能在未领取时改**——领取即计时，起表后声明是既成事实。
已领取 / 已完成的任务要改，走 [[A01-领取任务]] 的 `reopen`（派生下一轮）。

## 随任务带附件

```bash
nx-kv localtask attach --id <n> --path <本机文件>      # 图片/文件（存本机附件仓）
nx-kv localtask attach --id <n> --folder <本机目录>    # 文件夹（只登记路径指针，不复制内容）
nx-kv localtask attach --id <n> --mdfile <本机 md>    # 本地 md 指针
nx-kv localtask attach --id <n> --url <https://…>      # 外链
nx-kv localtask attach --id <n> --ref <refId>          # 引用库内文档
```

默认把链接**嵌进正文**；只想挂进附件区就用 `--no-embed`。

**面板里也能挂文件夹**（#133）：任务页 / 文档页 →「添加附件」弹窗 →
「添加文件夹（本机绝对路径，如 D:\repos\ref）」输入框 → 填目录 → 「添加」→「确认添加」。
浏览器拿不到目录的绝对路径，所以面板用**路径输入框**（不是目录选择器）：
只登记路径指针，目录内容不入库，交付时把绝对路径给 agent 去列目录。

## 头脑风暴：先存草稿，别进队列

```bash
nx-kv localtask add "<想法>" --cwd "<目录>" --json
nx-kv localtask plan --id <n> --to plan      # 转草稿：get/wait/队列/闸门都看不到它
```

草稿态仍然存库（不丢），但完全不参加派发。转回待领取用 `--to pending`。

## 用户看完结果要改 → 用 reopen 派生下一轮，不要自己 add

```bash
nx-kv localtask reopen --id <n> --feedback "<用户原话>" --json
```

`reopen` 会**派生一条新编号的 pending 任务**（带上一轮完成总结 + 本轮反馈），旧任务保持
done / 被取代。已领取/已完成的任务不会再被派发，不走 reopen 就等于需求没提。
细则见 [[A01-领取任务]]。

## 偏差与陷阱

| 偏差 | 正确做法 |
| --- | --- |
| `--cwd` 填成自己的目录 | 填**接收方**目录；主题按「完整 cwd + 项目组」派生，同名目录也不共用队列 |
| 任务文本写「如上所述」「刚才那个」 | 自包含：路径写全、不引用本对话 |
| 只写「做什么」不写「怎么验证」 | ②里带上关键路径与验证入口（跑哪条命令 / 看哪张表） |
| 长文本用引号硬拼 | `--file <文件>` 或 `--file -`（标准输入）；换行逐字保留 |
| 大需求塞成一条 | 拆成多条可独立完成的单元；顺序重要时 `reorder` 校正 |
| 有依赖的步骤走 `--global` | 全局池不保顺序，必须 `--cwd` 投到同一目录队列 |
| 提交完自己去 `get` | 那是接收方的事；要跟进等它 `reopen` 回来 |
| 已领取的任务想改时间目标 | `update` 改不了（已起表）；走 `reopen` 派生下一轮 |
| 想法直接 add 进队列 | add 完立刻 `plan --to plan`，别让人领到半成品 |
