# A08 · SOP · 排障与定位（现象 → 位置 → 修）

> 命中信号：「报错了」「白屏」「接口 404」「找不到代码在哪」「这块逻辑在哪」。
> 顺序固定：**进程 → 接口 → 前端 → 库**。跳步会浪费时间（比如接口 404 时去翻 React 代码）。
> 本文是「现象的分诊台」：定位到位置后，转到具体 R 条目去修。

## ③ 症状速查（症状 → 判定 → 去哪修）

### 进程与接口

| 症状 | 判定 | 去向 |
|---|---|---|
| 面板打不开 / 连接被拒 | `curl /api/health` 报连接失败 | 进程没起或端口不对；`serve --port <N>` 换端口 |
| 端口被占 | 启动日志报 `EADDRINUSE` | `serve --port` 换一个；或结束占用进程 |
| **新加的接口 404** | `routes --http "…"` 有，但 curl 404 | 路由在进程启动时编译 → **重启 serve**（`A07-发版.md`） |
| 命令不认识 | `node bin/kv.mjs <cmd>` 报 unknown | 没跑 `pnpm gen`，或跑的是 `~/.claude` 里的旧安装 |
| 跨域失败 | 控制台报 CORS | 走同源 `serve`；CORS 配置在 `src/runtime/cors.ts` |
| SSE 断流 | network 里 event-stream 反复重连 | `src/runtime/server.ts` 的 SSE 分支；先确认代理没缓冲 |

### 前端与面板（详细处置在 `A04-改面板交互.md` / `A05-加面板页面.md`）

| 症状 | 判定 | 去向 |
|---|---|---|
| 白屏 | 控制台有 `pageerror`；`Rendered more hooks…` = 早退在 hook 前 | `A04-改面板交互.md` §⑤ |
| 侧栏树整块空白 | `curl /api/repos` 与 `/api/boards` **分别**看；任一失败抹掉整棵树（#194） | 修读取路径，两份独立兜底 |
| 同一页面裂出两个页签 | `panelOf` 与 `reverse` 不互逆 | `A05-加面板页面.md` §④ |
| 浮窗关掉后 reload 复活 | localStorage workspace JSON 没剪枝空 tabset；`Model.fromJson` 只能救一半 | 存盘前剪枝（`A05-加面板页面.md`） |
| 改了面板 config 界面不变 | `TabContentRenderer` 是 `React.memo` | `A04-改面板交互.md` §⑤（`configSig` 订阅） |
| 改了代码看不出变化 | 没 build / 旧 serve / 浏览器缓存 | `?cb=1` + 重启 serve；仍不行看 `B05-前端面板地图.md` |

### 探针与数据

| 症状 | 去向 |
|---|---|
| 探针里菜单点不动 / contentEditable 改不了 / 结果读不全 / 把真实队列搞脏 | `B05-前端面板地图.md`（坑位表在那边单点维护） |
| 外键约束「没生效」 / 备份快照不一致 / 迁移边缺失 / 升级丢关联数据 | `B04-存储与迁移.md` §⑥ 与 `A09-查库与改数据.md` §⑤ |
| 单测单独跑过、并发跑挂 / 事务内偶发卡死 | `A09-查库与改数据.md` 与 `B02-命令与接口契约.md` §⑤ |
| `check-lines` 拦提交 / smoke 单例红 | `A07-发版.md` §④ |

## ④ 分层判定（放错层 = 返工）

| 改动性质 | 层 | 走哪条 SOP / 查哪篇知识 | 自检方式 |
|---|---|---|---|
| 纯粹的逻辑运算，Node 与浏览器都要用 | `src/shared/` | `A03-加或改命令与业务规则.md` | 零依赖、无 IO；单测直接 import |
| 数据库、文件、配置、错误类型等基础设施 | `src/core/` | `B04-存储与迁移.md` / `B02-命令与接口契约.md` | 不含业务名词 |
| 某个业务域的行为 | `src/modules/<id>/` | `A03-加或改命令与业务规则.md` | 只依赖 `core` + `shared`；跨模块只走对方 `service.ts` |
| 装配（注册、路由、CLI 解析、HTTP 分发） | `src/runtime/` | `B02-命令与接口契约.md` | 模块**不许** import 装配层（`eslint` 会拦） |
| 视图 | `src/web/frontend/` | `A04-改面板交互.md` | 只能 import `shared`，数据只走 `/api` |

```powershell
pnpm lint      # 放错层会直接报 no-restricted-imports
```

## ⑤ 自检：修完怎么确认

```powershell
# 1 原始症状的可复现步骤，重跑一次应当不再出现
pnpm lint
pnpm typecheck
node --import tsx --test tests/unit/<相关>.test.mjs
node bin/kv.mjs db verify        # 若是数据问题
```

| 检查 | 判据 |
|---|---|
| 症状消失 | 原始复现路径走通，且**不是**靠清缓存/重启掩盖（要能说出根因） |
| 没有连带损伤 | lint / typecheck 通过；相邻功能仍可用 |
| 根因可复述 | 能一句话说清「哪个环节的什么假设不成立」 |
| 已回写 | 新症状补进本文对应表；若根因是某条 SOP 步骤错了，按 `A11-校准skill.md` 改那条 SOP |

## ⑥ 失败分支：定位不到时

```powershell
node bin/kv.mjs routes | Select-String "<关键词>"       # 全量命令里按词过滤
git log --oneline -20 -- src/modules/<模块>             # 这块最近谁在改
```

| 症状 | 原因 | 处置 |
|---|---|---|
| `grep` 零命中 | 现象与代码没有词面关联（文案是拼接的 / 状态是派生的） | 先找入口 action，再顺 `service.ts` 往下读 |
| 找到的文件不存在 | 记的是旧路径 | 用 `ls` 重新确认；顺手按 `A11-校准skill.md` 修掉那条写错路径的 SOP |
| 同一行为找到两处实现 | 历史遗留 | 合并到 service，保留一条 |
| 改了不生效 | 改的是另一层（改了 `modules` 里的同名逻辑，但请求走的是 runtime 缓存） | 回到链 A 核对真实入口 |
| 三条命令都无所获 | 现象离代码太远 | 改从「谁调用它」反查：先找入口 action，再顺着 `service.ts` 往下读 |

**定位结果要回写**：如果某条 SOP 里的路径已不存在，就地修那条 SOP（`A11-校准skill.md`）——否则下一个人还要再找一遍。
