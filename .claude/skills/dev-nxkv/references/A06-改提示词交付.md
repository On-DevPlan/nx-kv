# A06 · SOP · 改提示词 / 交付模板

> 命中信号：「改交付文案」「模板变量不对」「预览渲染不对」「加一个模板变量」。
> **#152 起模板正文进代码**：一段 = 一个 `PromptPlugin` 子类，正文是该类的 `templates` 常量。
> 没有 JSON 快照、没有 DB seed、没有「保存期校验 + 用户条目」那一层——
> 所以这份 SOP 只剩「改哪个类的哪个常量 + 怎么验」。
> 体系总览与三种规范扩展方法见 `A02-提示词模板与扩展.md`。

## ① 前置（先跑，拿事实）

```bash
grep -rn "readonly label\|tag =\|group =" src/modules/promptplug/plugins/   # 有哪些段、各在哪条链
node bin/kv.mjs prompt registry --json      # 时机链 + 每段生效正文 + 变量目录（三端同源）
node bin/kv.mjs localtask preview --id <id> --cwd "<项目目录>"   # 当前真实渲染结果（零副作用）
node bin/kv.mjs localtask get --cwd "<项目目录>"                 # 真领一次，看交付原文
```

## ② 判定：改哪一层

| 现象 | 改这里 | 备注 |
|---|---|---|
| 所有用户看到的**措辞**（语气、多一句说明） | 该段的 `BUILTIN` 常量（`src/modules/promptplug/plugins/*.ts`） | 改代码 = 全用户生效，没有「只改本机」的通道 |
| 某段在某些数据下**不该出现** | 该段正文的 `{{#if}}` 闸门 | 空数据必须整段消失，不能印空标签 |
| 渲染时**缺字段** | 插件 `buildData()`（取数投影）+ `dataSchema`（声明） | 宿主取数走 `Supply`；本段模板只能用自己的字段（没有共享 ctx） |
| 变量表里**列不出**某变量 | 插件的 `dataSchema` 字段声明（→ `schema-bridge` → `fields`） | 数组元素用 `x[]` 记法展开 |
| 交付里**多一段** | 新插件类 + `registry.ts` 的 `PLUGIN_CLASSES` 一行 + factory 分支 | 见 A02「扩展 3」 |
| **任务正文骨架**（新建任务时那段 MD） | `templates` 模块（`templates` 表） | 与提示词段落是两套数据，别混 |

**两件事必须分清**：任务正文模板（`templates` 表，用户可改）≠ 提示词段落（代码里的 `templates` 常量，用户不可改）。

## ③ 动作

1. 打开该段所在插件类（附件 `plugins/attachment.ts` / 上下文 `plugins/context.ts` /
   只读四段各自一个文件：`plugins/ack.ts` / `timecheck.ts` / `goalhint.ts` / `doneguard.ts`
   （共享 shape 在 `plugins/goal-shape.ts`）；队列 `plugins/ext.ts` / 持续 get `plugins/getloop.ts`）。
2. 改 `const BUILTIN: TemplateText = { id, name, text }` 的 `text`——这就是生效正文（`templates[0]`）。
3. 语法只有 Handlebars 子集：`{{#if}}` / `{{else}}` / `{{#each}}` / `{{path.to.field}}` /
   25 个 helper（见 `src/core/instruction-template.ts` 的 `TEMPLATE_HELPERS`）。
   旧语法 `{{#section}}` / `{{^x}}` 会被 `validateTemplate` 拒（单测覆盖）。
4. **不要**给渲染加 try/catch 回落：坏模板 = 该次交付直接抛错，这是刻意设计
   （静默回落会让「少半段」无人知晓）。
5. 改完跑 `preview` 看真实输出；`prompt-golden` 会逐字比对，文案变了要
   `NX_KV_GOLDEN_WRITE=1` 重生成基线并 **review diff**。
6. 消费侧说明（agent 怎么看这段）在 `assets/nx-kv/references/`，同步更新。

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 改了类里的文案，交付没变 | 该类没登记进 `PLUGIN_CLASSES`，或 factory 没构造它 | 补登记 + 补 `buildPlugins` 分支；`assertRegistry()` 会拦 |
| 区块渲染成空白 | 变量名不在 ctx（未知变量渲染成空串，不报错） | 对照 `prompt registry` 的 fields；补 `buildData()` 投影 |
| 启动就报「模板不能为空」 | 某段 `templates[0].text` 被清空 | 空段 = 配置错误，补正文（不许「空模板 = 不输出」） |
| 报「buildData() 返回与 schema 不符」 | 宿主数据形状变了 / 字段漏声明 | 按报错里的路径补 `dataSchema`（附件 6 种 kind 是范例） |
| 交付里出现空标签（`组定位：`） | 字段存在但内容为空 | 给默认文案，或用 `{{#if}}` 整段闸掉 |
| `--json` 读出来的正文全是 `\n` | 用 JSON 解析器读交付原文 | 改默认输出或 `--xml`（#128/#130） |
| 设置页看不到「编辑正文」 | **设计如此**（#152 正文进代码） | 改类里的常量，重启 serve 后只读展示会跟着变 |

## ⑥ 反模式

- 在服务端把列表拼成一段文本塞进数据对象（应由模板 `{{#each}}` 渲染）。
- 让一段去引用另一段的字段（数据域是硬的：启动期就报错，不是渲染成空串）。
- 为了「让它先跑起来」放宽 schema（`z.looseObject({})` 就是这么把附件字段全弄丢的）。
- 在模板里写业务判断（判断进 `buildData()`，模板只做呈现）。
- 给运行期加回落 / 双层 try/catch（失败要响，不要静默降级）。
- 改 `settings` 里的运行时数据来「修」代码 bug（那是用户数据）。
