# A05 · 附件（图片 / 文档）

## 三步

1. 领取时先看 `instruction` 的附件清单，按给的本机绝对路径 `Read`。
2. 需要新增附件 → `localtask attach --id N --path F`（自动上传 + 写正文片段）。
3. 核对 `localtask attachments --id N --json` 的清单与本地路径。

## 读附件

任务正文用标准 markdown 引用附件，`( )` 里是**本机附件仓的 fileId**：

```
修一下首页 logo  ![设计稿](3f2a1b…9c)       ← 图片
补充材料见 [需求说明.docx](b71e…04.docx)     ← 其他文件
```

- 领取时 `instruction` 会给出**本机绝对路径**清单 → 直接 `Read`，不要拼 URL、不要重新下载；
- `http(s)://`、`./x.md` 这类普通链接**不是**附件；
- 清单若提示「本机附件仓没有这个文件」→ 就是没有，不要猜内容。

## 加附件

```bash
nx-kv file upload --path <本机文件> --json         # 落附件仓 → { fileId, markdown 片段 }
nx-kv localtask attach --id <n> --path <本机文件>   # 上传并追加到正文
nx-kv localtask attach --id <n> --fileId <fileId>   # 追加已上传的
nx-kv localtask attachments --id <n> --json         # 这条引用了哪些附件（含本地绝对路径）
```

- 上传即落盘，**没有「同步」这一步**；
- ⚠️ 追加会**改写正文**：同一条任务连续操作一律用 `--id` 定位，别拿正文当 key；
- 未被引用的上传用 `file orphans` 查看、`file prune` 回收。

## 偏差

| 偏差 | 正确做法 |
| --- | --- |
| 把 fileId 当 URL 拼地址 | 用 instruction 给的本地路径 Read |
| 手工把 fileId 写进正文 | 用 `attach`，它会写正确的 markdown 片段 |
| 附件缺失时凭上下文猜内容 | 明确告诉用户「附件没在本机仓」 |
