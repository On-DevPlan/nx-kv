# A07 · 任务链回顾与原始意图检索：找回「所有轮次的原始意图」做重评审

## 这一篇解决什么

一条任务链（反馈 fork / 评论 / 重开派生）走了很多轮之后，你想**找回所有轮次的原始意图**、
重新总结一遍、甚至和 agent 一起**重新评审**当初的方向。本篇给出检索工具（最新 N 条 / 关键字 /
整条链）与回顾 SOP。冲突 / 重复内容**以最新为准**（时间戳每行都带，可比对）。

## 一、检索工具（三把钥匙）

### 1）最新 N 条：`localtask tasks --limit`

```bash
nx-kv localtask tasks --cwd <目录> --limit 10          # 最新 10 条（按 createdAt 倒序）
nx-kv localtask tasks --key <主题键> --status done --limit 5   # 最近 5 条已完成
```

- 每行都带**时间戳**（createdAt / consumedAt / completedAt）、轮次（round）、本轮总结
  （roundSummary）——冲突时直接比时间，**最新的那条就是当前真相**。
- `--status` 过滤待领取 / 已领取 / 已完成 / 已取消。

### 2）关键字：`localtask tasks --q`

```bash
nx-kv localtask tasks --cwd <目录> --q "滚动"           # 标题或正文命中「滚动」的任务
nx-kv localtask tasks --cwd <目录> --q "登录" --limit 5  # 命中里再取最新 5 条
```

- 大小写不敏感；**同时搜标题与正文**（原始意图常埋在正文段落的措辞里）。
- 配合 `--limit`：命中的集合里取最新的几条。

### 3）整条链：`localtask chain --id`

```bash
nx-kv localtask chain --id 42 --cwd <目录>
nx-kv localtask chain --id 42 --json    # tree 字段 = 单向树（每节点带 createdAt / status / forkKind）
```

- 返回 `nodes`（根→…→自己→…→叶 平铺，每节点带时间 / forkKind：reopen=反馈、
  comment=评论）与 `tree`（单向树：每条任务至多一个来源，后代随时分叉）。
- **冲突裁决口径**：链上同一件事在多轮出现时，取 `createdAt` 最新的节点版本；
  树的分叉（在旧轮次上又反馈）= 两条并存的旁支，都以各自最新为准。

## 二、回顾 SOP（原始意图 → 重总结 → 重新评审）

1. **圈定范围**：`tasks --limit`（最近 N 条）+ `tasks --q <关键词>`（意图相关的历史轮）
   圈出要回顾的任务集合；`chain --id` 补全每条的派生脉络。
2. **收原始意图**：`localtask show --id <n>` 逐条读正文——重点读每轮的
   `> [!WARNING] 第 N 轮 · 验收反馈`（**用户原文在这里**）与
   `> [!NOTE] 第 N 轮 · 完成总结`（上轮 agent 做了什么）。
   > 提示词口径（为什么要读 WARNING 块）：新任务的库中正文 = 旧正文 + 程序生成的
   > 总结/反馈 callout，**用户原文只在 WARNING 块内**（默认逐行加粗）；
   > agent 在 get 时实际收到的提示词是交付重排后的版本（最新轮在前、历史轮压缩成一行）——
   > 要看「agent 视角」用 `localtask preview`，要确认「原始意图」就回 WARNING 块。
3. **重总结**：把各轮 WARNING 原文按时间排开，提炼「意图的演变」——哪些要求一直没变
   （主线）、哪些被中途推翻（以最新为准）、哪些是评论旁支（未进主线的补充）。
4. **重新评审**（和 agent 一起）：把重总结作为新一轮任务的正文起点——
   `localtask add --file <重总结.md> --cwd <目录>` 建评审任务，正文里逐条列
   「原始意图 → 现状 → 冲突裁决（取最新） → 建议路线」，让 agent 对照源码与链史给出
   评审意见，再由用户拍板。

## 三、纪律

- **冲突以最新为准**：同一要求在多轮出现时，`createdAt` 最新的一条是当前真相；
  历史轮次只做追溯，不作为执行依据。
- 链是**单向树**：每条任务至多一个来源（task_links 一父约束），分叉=旁支并存；
  回顾时按树读（`chain --json` 的 tree），不要把平铺 nodes 当执行顺序。
- 评审结论**落盘**：重总结写成一篇 ref 或新任务正文（见 [[A03-文档与归属]] /
  [[A02-提交任务]]），不要留在对话里——链是历史，评审结论要成为新的起点。

## 四、偏差 / 陷阱

| 偏差 | 后果 | 正确做法 |
| --- | --- | --- |
| 直接读 agent 交付文本（`preview` 输出）当原始意图 | 交付版已把历史轮压缩成一行、最新轮提前——**不是原文** | 原始意图回 `show --id` 的 `[!WARNING]` 块读 |
| 用平铺 `nodes` 当执行顺序 | 平铺序是「根→自己→后代」，旁支混在一条线上 | 按时间 + `tree` 的分叉读；冲突取 createdAt 最新 |
| `--q` 只搜标题 | 用户意图常写在正文段落里（措辞是判断依据） | `--q` 已包含正文全文匹配；命中后再 `show` 逐条读 |
| 没加 `--limit` 直接回顾 | 长链主题一次拉几百条，噪声淹没主线 | 先 `--limit 10` 看最新，再按需 `--q` 补历史 |
| 重总结只留对话 | 下一轮 agent 又要重读一遍链 | 结论落盘成 ref 或新任务正文（[[A02-提交任务]]） |

## 五、边界

- `tasks --q` 搜的是**这一个主题**；跨主题找东西用仓库页搜索或 `docs list`。
- `chain --json` 的节点不含正文全文——要读某轮原文用 `show --id`（链上每个节点都带 id）。
- 领取的标准动作仍是 `localtask get`（见 [[A01-领取任务]]）；本篇的检索是**回顾用**，
  不是领活入口。
