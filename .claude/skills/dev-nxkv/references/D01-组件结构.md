# D01 · web 端组件结构：有哪些件、各自负责什么

> D 序列 · web 端之一。回答「前端有哪些组件、各自管什么、改 UI 该动哪个文件」。
> 页面 ↔ 组件 ↔ API 的对应关系见 [[D02-页面与组件关系]]；后端侧见 [[C01-serve端]]。

## 1. 应用壳：Provider 组装

```text
main.jsx
  └─ <StrictMode>
       └─ <StoreProvider>       store.jsx      全局 UI 状态（bootstrap + 持久化的「选择」）
            └─ <ToastProvider>   components/toast/  页内轻提示
                 └─ <App />       App.jsx       应用壳 v2：FlexLayout 工作区 + hash 路由
```

- **没有顶栏**：全局动作（重置布局 / 设置）全部集中在侧边栏头部——侧边栏是工作区里的一块面板，可拖拽可浮出，动作跟着它走。
- **面板是一等公民**：目录、目录工作台、项目组、仓库管理、云端总览……都是工作区里的一块面板，可拖拽、可拆分、可拖出成浮窗；布局存 localStorage，重开还在。
- 路由与「选中的面板」**互为镜像**：
  - 路由变化 → 打开/聚焦对应面板；
  - 选中面板变化 → 地址跟着走（`history.replaceState`，不触发 hashchange）。
  - 所以**深链 = 一屏**：把地址发给别人，对方看到的布局与你一致。

## 2. 五个关键文件

| 文件 | 职责 | 关键点 |
|---|---|---|
| `App.jsx` | 应用壳：hash 路由解析、工作区模型、面板 ↔ 路由同步、轮询 | 路由用 `hash`：`#/dir/<key>`、`#/global`、`#/overview`、`#/group/<id>`、`#/doc?ref=…`、`#/templates/…`、`#/cloud`、`#/repos` |
| `app-context.jsx` | 运行时上下文（`useApp()`） | 提供 `rows`（队列）、`repoData`（仓库/看板）、`prefs`、`model`、`route`、`openPage`、`closePanel`、`shell`、`refreshLocal`、`refreshRepos`、`tpl` |
| `store.jsx` | 全局 UI 状态 | 只持久化「**选择**」（当前视图、主题筛选、多选勾选），**不持久化数据**——数据永远从 `/api` 拉 |
| `api/client.js` | API 客户端 | `api(path, {method, body, timeoutMs})`；响应包 `{ ok, data }` / `{ ok, error, code }`；失败抛 `Error` 且带 `.code` / `.details`；默认超时 30s |
| `route-map.js` | 路由 ↔ 面板的纯映射 | **不引 React**（`node --test` 解析不了 JSX），所以单测直接 import |

### 路由 ↔ 面板的恒等式（踩过坑）

`panelSpecOfRoute` 生成的 config 必须能从 `routeOfPanel` 写回的路由**逐字**复现——`openPanel` 按 `component + config` 去重，任何一边多一个字段都会裂出重复页签。

- 文档 `docId` 带 `rel:` / `path:` 前缀冒号，**整串 encode 会把 `:` 变成 `%3A`** → 只编码冒号后的路径段，前缀原样保留。
- 返回值是「已编码」的查询串片段——交给 `URLSearchParams` 会**二次编码**（`/` → `%2F` → `%252F`）。所以两个方向都在 `route-map.js` 内完成 encode/decode，调用方只做字符串拼接。

## 3. 布局与面板

| 位置 | 作用 |
|---|---|
| `workspace.js` | 工作区模型（FlexLayout model）的载入/保存、`openPanel` / `openFloatingPanel` / `openBesideMain`、`activeTab`、`configSig`、`pruneBlankTabsets`、`tabsetOfComponent`、`setTabsetAttrs`、`findOpenPanel` |
| `workspace/areas.js` / `layout.js` / `open.js` / `panels.js` | 布局区域划分、默认布局、开面板策略、面板辅助 |
| `panels.jsx` | **面板注册表** `PANELS`：`component` 字符串 → React 组件；另有 `PANEL_ORDER` 与 FlexLayout 的 `factory` |
| `registry.js` | **视图注册表** `VIEWS`：有哪些「视图」（页面级），带 `module` 归属字段供测试断言 |
| `prefs.js` | 侧栏排序 / 隐藏 / 折叠等**纯 UI 偏好**（localStorage） |

### 两个注册表的分工

| | `registry.js`（视图） | `panels.jsx`（面板） |
|---|---|---|
| 回答 | 「有哪些**视图**」 | 「工作区里能开哪些**面板**」 |
| 位置 | `src/web/frontend/registry.js` | `src/web/frontend/panels.jsx` |
| 归属字段 | `module`（消费哪个后端功能域，仅供测试断言不悬空；后端读不到） | — |

**后端模块对自己的视图一无所知**：历史上模块 `index.js` 里挂过 `view: () => import(...)`，那是把前端的文件布局写进后端声明，已整体移除。`tests/unit/registry.test.mjs` 会断言后端不出现模块级 `view`。

## 8. 前端三条硬约束

1. **只调 `/api/*`**；禁止 import 后端模块，只能用 `src/shared/` 的纯函数（`eslint.config.js` 会拦）。
2. **`no-undef` 是开着的**：漏 import 会让浏览器整页崩，lint 能点名。
3. **共享展示逻辑放 `modules/`**，页面组件放 `page/<name>/`；大组件按职责拆兄弟文件（不要单文件继续膨胀）。

## 9. 侧栏三态（`components/sidebar/side-state.js`）

| 状态 | weight | 约合宽度 @1440 |
|---|---|---|
| `expanded` | 16 | ≈ 229px |
| `collapsed` | 2.5 | ≈ 41px（整条可点展开） |
| `closed` | 1.2 | ≈ 20px（左缘只剩半圆弧把手） |

判定阈值（读回存量布局时按 weight 分档）：`< 2` → closed；`2 ~ 8` → collapsed；`≥ 8` → expanded。

**收起宽度是 tabset weight 的百分比，不是绝对像素**——旧实现拿「绝对像素 < 46」当判定，而 2.5% 在宽窗口下折算出来比 46px 还宽，判定永远不翻转，侧栏卡在「压窄的展开态」。现在：点击收起/展开/关闭直接翻状态并落模型；拖拽走**迟滞带**（< 46px 收起，≥ 120px 展开，中间保持现状防抖）；关闭态例外（只有 ≥ 120px 才翻回展开）。

## 10. 前端改动的验证要点

- **浏览器缓存会让「改了不生效」**：验证前用 `?cb=1` cache-buster，并重启 serve。
- 面板是构建产物：`src/web/public` 是 gitignore 的 vite 输出，改前端要 `pnpm build`。
- 端到端实测可用 `nx-kv-panel-probe` skill（独立 store 播种 + 临时端口 serve + Playwright 探针，**绝不碰用户真实队列数据**）。
- 工作区可能有多会话并行改前端文件：**提交前 `git status` 核对，只 `git add` 自己的文件清单，绝不 `git add -A`**。
