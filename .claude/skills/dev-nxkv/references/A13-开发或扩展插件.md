# A13 · SOP · 开发 / 扩展 pretask 插件

> 命中信号：「加一个插件」「开发插件」「插件包」「给插件加入口 / 页面 / 设置」「扩展 pretask」「插件生命周期」。
> 一句话：**插件包自注册（server 清单 + client `registerPlugin` + 自有表），宿主只做生命周期与调用**。
> 契约与口径查 `B09-插件架构与契约.md`；只改宿主页面/交互 → `A04-改面板交互.md`；
> 只加一条命令或业务规则 → `A03-加或改命令与业务规则.md`。

## ① 前置（先跑，拿事实）

```powershell
ls packages/
cat packages/plugin-dir-annotate/package.json
cat packages/plugin-dir-annotate/src/server/index.ts
cat packages/plugin-dir-annotate/src/client/index.tsx
cat packages/plugin-sdk/src/index.ts
cat scripts/build-plugins.mjs
cat scripts/check-plugin-isolation.mjs
pnpm gen:plugins
node bin/kv.mjs plugin list --json
```

## ② 判定：你要做哪一种

| 处境 | 去哪 |
|---|---|
| 全新插件（新目录批注式能力） | 本文 ③ 的 1→9 全流程 |
| 给现有插件加一种入口 / 页面 / RPC / 表 | 本文 ③ 的「扩展配方」表，按行改对应文件 |
| 只改「哪些入口显示 / 新建页默认触发谁」 | 不改插件：宿主已提供 `plugin set-visibility` / `plugin set-default`（见 `B09`） |
| 只改宿主插件加载或生命周期 | `src/modules/plugin/host.ts` + `B09` 的红线，不碰插件包 |

## ③ 动作：插件完整生命周期（新增一个插件 = 九步）

**1. 建包** `packages/plugin-<id>/`

最低集合（照抄 `packages/plugin-dir-annotate/`）：

| 文件 | 作用 |
|---|---|
| `package.json` | `name`、`private`、`type: module`、`main`、`exports`、**`nxkv` 清单**、`dependencies` 只有 SDK、`peerDependencies` 只有 React |
| `tsconfig.server.json` | server 产物（`dist/server`），只 include `packages/plugin-<id>/src/server` |
| `tsconfig.client.json` | client 类型检查（JSX） |
| `vite.config.ts` | IIFE + 共享 React 全局（照抄现有插件配置） |
| `packages/plugin-<id>/src/server/index.ts` | `definePlugin(...)` 默认导出 |
| `packages/plugin-<id>/src/client/index.tsx` | `window.NxkvPluginHost.registerPlugin('<id>', def)` |
| `packages/plugin-<id>/src/client/style.css` | 插件自有样式（`.<前缀>-*`，可复用宿主 CSS 变量） |

**2. 写 server 入口** `packages/plugin-<id>/src/server/index.ts`

- `definePlugin({ id, version, api:'^1', name, description, order, defaultEnabled, entries, buildDraft })`；
- 入口 id 必须 `<id>:<localId>`，`kind` 只能是 `draft` / `panel`；
- `kind:'panel'` 用 `ui.panel` + `panel.title`，`buildDraft` 直接抛错；
- 需要持久化再补 `storageVersion` + `migrateStorage`，需要接口再补 `rpc`（方法名 camelCase）。

**3. 写 client 入口** `packages/plugin-<id>/src/client/index.tsx`

- `registerPlugin('<id>', { api:'^1', components, pages, sidebar? })`；
- 下拉行组件放 `components['entry-row']`，参数页放 `components['entry-form']`，面板页放 `components['annotate'|...]`；
- 左下角设置页用 `sidebar: [{ id, label, icon, order, page }]` 自注册（照抄目录批注设置）。

**4. 插件自有存储**

- 表名 `plugin_<id>_*`，只在 `migrateStorage(db, from)` 里建；
- 只写自己的表；`tasks/topics/repos/docs/settings` 一律不碰；
- 版本号由宿主记进 `plugin_storage_migrations`，插件不自己改宿主表。

**5. 上下文与宿主能力**

- 页面通过 `api.ctx` 拿定位；缺信息用 `api.host.get('/api/plugins/context'|'/tree'|'/file')`（见 `B09`）；
- 组主题要列组内仓库时用 `context.repos`；repo 主题直接进目录；
- 目录/文件接口只对已登记仓库生效，路径越界会被拒。

**6. 生命周期接线（宿主已通用，不改插件专属代码）**

| 能力 | 入口 |
|---|---|
| 全局启用/停用 | 设置 → 插件（`plugin set --id <id> --enabled false`） |
| 本 scope 下拉可见性 | `plugin set-visibility --scopeKey topic:<key> --entries ...` |
| 「＋ 新建页」默认触发项 | `plugin set-default --scopeKey topic:<key> --entryId <id>:<entry>` |
| 插件页互切 | 宿主路由按 `pluginId/pageId/sessionId` 区分，插件无需登记 |

**7. 构建与注册**

```powershell
pnpm gen:plugins
pnpm run build:packages
pnpm run gen
```

- 内置插件**不进根 `dependencies`**：宿主按生成的 `{ name, dir }` 相对路径解析；server 由 Vite 打成
  单文件（SDK 内联），`npx nx-kv` 安装后就能直接加载；
- 插件包必须 `private: true`；根 `files` 必须带 `packages/`（插件产物随宿主包分发）；
- 根 `dependencies` 只保留 `tsx` 等运行时依赖；`@nx-kv/plugin-sdk` 只在 `devDependencies`（workspace:*）；
- `build:packages` 自动发现清单，**不要**在 `package.json` 里为单个插件加 build 脚本。

**8. 测试**

```powershell
node bin/kv.mjs plugin list --json
node bin/kv.mjs plugin entries --topic <topicKey> --json
node bin/kv.mjs plugin context --topicKey <topicKey> --json
node bin/kv.mjs plugin tree --repoKey <repoKey>
pnpm test:unit
```

- 宿主级行为照抄 `tests/unit/plugin-task-template.test.mjs`（`createTestStore` + host）；新增 `setDefaultEntry` 之类断言；
- 真机走查：`pnpm build` → `node bin/kv.mjs serve --port <port> --no-open` → 带 `?cb=1` 打开页面，硬刷新避免旧 chunk。

**9. 收尾门禁**

```powershell
pnpm lint
pnpm typecheck
pnpm build
pnpm run test:unit
pnpm run test:smoke
```

`pnpm lint` 里的 `check-plugin-isolation` 会拦：清单不一致、插件 import 宿主、宿主硬编码插件包名、清单路径出包、缺构建配置、根依赖漏声明。

## 扩展配方（已有插件加东西）

| 想加什么 | 动哪里 | 参考 |
|---|---|---|
| 一个新 draft 入口（带槽位） | server `entries()` 追加；正文用 `{{槽位}}` | `packages/plugin-task-template/src/server/index.ts` |
| 一个新 panel 入口 | server `entries()` 追加 `kind:'panel'` + client `ui.panel` 组件 | `packages/plugin-dir-annotate/src/server/index.ts` |
| 一个不进入口的插件页面 | client `components` + `pages`（可只从侧栏进） | 目录批注设置页 |
| 左下角设置页 | client `sidebar` 自注册 + 页面组件 | `packages/plugin-dir-annotate/src/client/SettingsPage.tsx` |
| 插件自有 RPC | server `rpc: { method(ctx, raw) }`；client `api.rpc('method', params)` | `packages/plugin-task-template/src/server/index.ts` |
| 插件自有表 / 升级 | `migrateStorage` + 提 `storageVersion` | `packages/plugin-task-template/src/server/storage.ts` |
| 用宿主的目录/文件能力 | client `api.host.get('/api/plugins/tree'|'/file')` | `packages/plugin-dir-annotate/src/client/AnnotatePage.tsx` |
| 迁移旧内置数据 | server `migrateLegacy(ctx, kind, payload)` | `packages/plugin-task-template/src/server/index.ts` |

## ④ 自检

| 检查 | 通过判据 |
|---|---|
| 自注册清单 | `pnpm gen:plugins` 输出包含新包；`plugin list --json` 里 `error` 为空 |
| 入口 | `plugin entries --topic <key> --json` 能看到新入口；`kind` 正确 |
| 默认行为 | 把默认设为新面板入口后，点「＋ 新建页」直接进插件页 |
| 插件页互切 | 左下角两个插件条目来回点，主面板标题与选中态都跟着换 |
| 插件设置 | 设置页保存后刷新仍在（落在插件自有表） |
| 边界门禁 | `pnpm lint` 的 `check-plugin-isolation` OK |
| 构建 | `pnpm build` 后重启 serve；浏览器带 `?cb=1` 验证 |

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 插件不出现 / `plugin list` 显示 error | 清单没生成、server 产物不存在、发布包没带 `packages/` | `pnpm gen:plugins` → `pnpm run build:packages` → 检查根 `files` 是否含 `packages/` |
| 下拉里没有入口 | `entries()` 返回空（ctx 没定位）、scope 隐藏、插件全局关闭 | `plugin list` / `plugin entries --all --json` / `plugin visibility` 逐层查 |
| 点开插件页空白「插件 UI 未注册」 | client bundle 没 build、`registerPlugin` 的 id 与 server id 不一致 | 重跑 `build:packages`、核对 id、硬刷新 |
| 点「＋ 新建页」没走默认入口 | 默认项被隐藏 / scopeKey 写错 | `plugin visibility --scopeKey ...` 看 `defaultEntryId` 与 `visible` |
| 两个插件页切不过去 | 路由判等漏了 `pluginId/pageId/sessionId` | 核对 `src/web/frontend/routes/route-eq.ts` 与 `App.tsx` 的 `routeSig` |
| 插件读目录报越界 | repoKey 不是已登记仓库 / 路径含 `..` / 软链 | 用 `plugin tree --repoKey <key>` 先验；不要绕开 host API 直接读盘 |
| lint 报「宿主硬编码插件包名」 | 宿主代码写死了 `@nx-kv/plugin-x` | 改用生成的包名清单；插件专属逻辑回到插件包 |
| lint 报「插件 import 了 xxx」 | 插件引用了宿主 src 或第三方包 | 只能依赖 SDK / React / node: / 包内相对路径 |

## ⑥ 反模式

- 在宿主里给某个插件写特判（包名、入口 id、专属 UI）——宿主只认 `nxkv` 清单与 SDK 契约。
- 把插件表格塞进宿主迁移——插件表归 `migrateStorage`，宿主只记版本号。
- 在根 `package.json` 给每个插件写一条 build 脚本——应当由 `scripts/build-plugins.mjs` 自动发现。
- 把内置插件写进根 `dependencies` 或单独发 npm——它们随宿主包分发，`npx nx-kv` 直接可用。
- 让宿主运行时 import `@nx-kv/plugin-sdk`——SDK 只在构建期与插件 server 打包时使用。
- 在下拉行里标「默认」——默认是**主题级**配置（新建页行为页），插件声明只是回落。
- 插件页绕过 `api.ctx` / `api.host.get` 去猜目录或直接读宿主库。
- 新增插件页面时去改宿主路由——`#/plugin/<id>/<page>` 是通用路由，插件只需自注册 components/pages。
