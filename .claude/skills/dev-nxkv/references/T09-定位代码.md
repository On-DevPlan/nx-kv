# T09 · 定位代码（从现象到文件）

> 不要背目录结构——用命令定位。四条链，按现象选一条。

## ① 前置：先拿两张表（10 秒）

```powershell
node bin/kv.mjs routes | Measure-Object -Line      # 有多少入口（别记数字）
ls src/modules/                                     # 现存模块（历史模块会被删）
ls src/web/frontend/page/                           # 现存页面
```

有了这两份清单，再决定走哪条链——**不要先猜文件路径**。

## ② 动作：选一条链

### 链 A · 从一个接口 / 命令行位置

```powershell
node bin/kv.mjs routes --http "POST /api/localtasks/preview"   # 路由 → 命令 id
node bin/kv.mjs routes --module localtask                       # 模块 → 全部入口
```

拿到 `id`（形如 `localtask.preview`）后：

```
src/modules/<模块>/actions/<cli首词>-<动词>.ts   ← 声明：id / cli / http / zod 契约 / render
        ↓ 方法体只做编排
src/modules/<模块>/service.ts                   ← 业务规则、事务边界、错误语义
        ↓
src/modules/<模块>/repo/*.ts                    ← SQL
        ↓
src/core/db/、src/core/*.ts                     ← 原语（db / 错误 / 时间 / 路径）
```

```powershell
grep -n "class .*Action" -A 20 src/modules/<模块>/actions/<文件>.ts
grep -n "export function" src/modules/<模块>/service.ts | head -20
ls src/modules/<模块>/repo/
```

### 链 B · 从一个页面 / 地址位置

```powershell
grep -n "view: '" src/web/frontend/routes/*.ts          # 全部 hash 视图声明
grep -rn "#/dir" src/web/frontend --include=*.ts --include=*.tsx | head
```

```
hash 一级段 → routes/<名>.ts 的 view + panelOf
        ↓ panel.component
src/web/frontend/panels.tsx 的 PANELS   ← 面板壳
        ↓ 渲染的组件
src/web/frontend/page/<name>/index.jsx  ← 页面
        ↓ 页面只调
src/web/frontend/page/<name>/api.ts     ← 本页 /api 调用
        ↓
src/web/frontend/registry.ts 的 VIEWS / components/
```

### 链 C · 从一张表 / 一个字段

```powershell
grep -rn "FROM <table>" src/modules --include=*.ts | head -10
grep -rn "<column>" src/modules --include=*.ts | head -10
grep -n "<table>" -A 20 src/core/db/migrations/*.sql | head -40
```

判定：读写这张表的 `repo/*.ts` 在哪、谁调它（`service.ts`）、哪个 action 暴露出来（`routes --module`）。

### 链 D · 从一段提示词 / 一句界面文案

```powershell
grep -rn "<文案片段>" src/shared src/modules src/web --include=*.ts --include=*.tsx | head
```

| 命中的位置 | 说明 |
|---|---|
| `src/shared/prompt-blocks.ts` | 内置默认提示词模板 |
| `src/core/instruction-template.ts` | 渲染引擎与 helper |
| `src/modules/tasktool/system-blocks.ts` | 区块装配 |
| `src/modules/localtask/repo/settings.ts` | 用户可编辑模板的存取与校验 |
| `page/<name>/index.jsx` | 界面文案 |

## ③ 动作：判定改动该放哪一层（放错层 = 返工）

| 改动性质 | 层 | 自检方式 |
|---|---|---|
| 纯粹的逻辑运算，Node 与浏览器都要用 | `src/shared/` | 零依赖、无 IO；单测直接 import |
| 数据库、文件、配置、错误类型等原语 | `src/core/` | 不含业务名词 |
| 某个业务域的行为 | `src/modules/<id>/` | 只依赖 `core` + `shared`；跨模块只走对方 `service.ts` |
| 装配（注册、路由、CLI 解析、HTTP 分发） | `src/runtime/` | 模块**不许** import 装配层（`eslint` 会拦） |
| 视图 | `src/web/frontend/` | 只能 import `shared`，数据只走 `/api` |

```powershell
pnpm lint      # 放错层会直接报 no-restricted-imports
```

## ④ 自检：定位结果核对

| 检查 | 判据 |
|---|---|
| 文件存在 | 你打算改的每个路径都 `Test-Path` 为真（别凭记忆写路径） |
| 唯一入口 | 同一行为只有一条实现路径；已有就改它，不新增第二条 |
| 分层合规 | `pnpm lint` 不报 `no-restricted-imports` |
| 调用链闭合 | 能从 action → service → repo 走通，中间没有断点 |
| 契约有测试 | 目标行为的既有用例在 `tests/unit/` 里能找到（找不到说明这是新行为） |

## ⑤ 失败分支：找不到时的兜底

```powershell
node bin/kv.mjs routes | Select-String "<关键词>"       # 全量命令里按词过滤
ls src/modules/                                        # 现存模块（别照旧记忆找已删模块）
git log --oneline -20 -- src/modules/<模块>             # 这块最近谁在改
```

**定位结果要回写**：如果某条 SOP 里的路径已不存在，就地修那条 SOP——否则下一个人还要再找一遍。
