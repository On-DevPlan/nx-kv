# A01 · 领取任务

## 标准动作：直接 get

```bash
nx-kv localtask get --json
# → { status:"ok", task:{ id, text, attachments? }, instruction:"…" }
# → { status:"timeout" }            没活（业务结果，exit 0）
```

**为什么不是先 list/show**：`get` 的返回里已经封装了这一轮需要的全部上下文——
任务正文、项目组上下文（组介绍 / 本项目位置 / 兄弟成员 / 绑定文档的 refId+desc）、
附件本地绝对路径、ack 收尾要求、任务级时间目标。先翻列表等于多花一次调用还看不到这些。

`list` / `show` 只在两种情况下用：① 需要**不领取地**看内容；② 校验某条任务是否存在/什么状态。

## 领到之后（同一步做完，不要拆开）

1. **读 `task.text`**：任务正文，必读。
2. **读 `instruction`**（有则必读）：它和正文一起构成这一轮的根指令。
3. **附件**：`instruction` 给的是本机绝对路径，直接 Read（见 [[A05-附件]]）。
4. 开始干活。

## 领取指定编号

`get` 是按队列顺序领的，没有 `--id`。要精确领某条，三步：

```bash
nx-kv localtask show  --id 42 --json                     # 1) 确认内容与状态
nx-kv localtask list  --json | grep '"position"'         # 2) 看队首是谁（可选）
nx-kv localtask reorder --id 42 --before-id <队首 id> --json   # 3) 提到最前
nx-kv localtask get --cwd "<该任务所在目录>" --json      # 4) 领走
```

- 目标任务可能属于**别的主题**（别的目录）：`get` 必须带那个目录的 `--cwd`，
  否则领到的是当前目录队列的队首。
- 只要「看」不要「领」，做完第 1 步就停。

## 常见偏差

| 偏差 | 正确做法 |
| --- | --- |
| 先 `localtask list` 把整队列打印给用户 | 直接 `get`；需要概览时才 `list` |
| 用 `show --id` 当领取 | `show` 是只读的，任务仍是 `pending` |
| `timeout` 当失败重试 | 它就是「暂时没活」，收尾 |
| 只读 `task.text` 不看 `instruction` | instruction 里的组上下文/附件/收尾要求都是硬约束 |
