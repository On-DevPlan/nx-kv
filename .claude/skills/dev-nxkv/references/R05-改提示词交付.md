# R05 · 需求 · 改提示词 / 交付模板

> 命中信号：「改交付文案」「模板变量不对」「预览渲染不对」「加一个模板变量」。
> 交付给 agent 的提示词只有一条链：**一份共享 ctx + Handlebars 模板字符串 + 薄编排**。
> 禁止自研解析器、区块对象、每块独立变量域、服务端预拼列表文本。
> 要加一种带专属变量的资源类型 → `R01-加一种资源类型.md`（序列化 + 知识化两处都要做）。

## ① 前置（先跑，拿事实）

```powershell
grep -n "export" src/core/instruction-template.ts            # renderInstruction / validateTemplate / TEMPLATE_HELPERS
node -e "console.log(JSON.parse(require('fs').readFileSync('src/modules/promptplug/Template/blockTemplates.json','utf8')).context.list[0].template)"   # 内置模板（唯一真相，出厂快照）
node bin/kv.mjs prompt registry --json                        # 8 段的生效模板 / 变量目录 / 顺序位（三端同源）
node bin/kv.mjs localtask config --json                       # 当前模板设置
node bin/kv.mjs localtask preview --id <id> --cwd <目录>        # 当前真实渲染结果
```

## ② 判定：改哪一层

| 现象 | 改这里 | 是否要迁移 |
|---|---|---|
| 所有用户的默认措辞、默认区块结构 | `src/modules/promptplug/Template/blockTemplates.json` + `template-bundle.ts` 的 `BUNDLE_VERSION` +1（升级只刷 builtin） | 否（ensure 首启/升级落库） |
| 本机队列的区块开关 / 模板正文 | `localtask config` / 设置页（落 `settings` 表） | 否 |
| 任务正文模板（标题、验收、约束的骨架） | `templates` 表（`templates` 模块） | 否 |
| 渲染时上下文缺字段 | 插件 `data()`（`src/modules/promptplug/plugins/*.ts`）或宿主取数（`tasktool/wait.ts` 构造注入） | 否 |
| 变量表里列不出某变量（知识化缺失） | 插件的 zod `dataSchema`（字段声明 → schema-bridge 派生 fields → prompt.registry） | 否 |

**两件事必须分清**：任务正文模板（`templates` 表）≠ 提示词区块模板（`settings` 里的 per-block template）。不要合成一个表单。

## ③ 动作

1. 改模板字符串（Handlebars）。可用 helper 见 `TEMPLATE_HELPERS`，不要自己造语法。
2. 单块长度上限 `MAX_BLOCK_TEMPLATE_LEN`、模板数上限 `MAX_PROMPT_TEMPLATES`——超了会被拒，不要绕过。
3. **保存期校验不许去掉**：写入前必须走 `validateTemplate()`（`HB.precompile`）+ 变量白名单（`undeclaredTemplateVars`，全局段集 + 点路径全路径命中 fields），语法/拼错变量直接拒绝并报「模板名 + 区块名」。
4. **运行期一条直线（S1 起不回落）**：坏模板在保存期拦下，运行期 `data()` / 渲染抛错 = 整次领取失败，不吞、不回落、不写 `renderWarnings` 兜底——静默回落会让「提示词少了半段」变成无人知晓的常态。
5. 改的是渲染函数本身 → 保持纯函数，入参 `(template, ctx)`，不读全局状态。
6. 改了 **`assets/` 里的消费侧说明**（agent 怎么看这段提示词）→ 按 `R06-发版.md` 的对外收口走。

## ④ 自检（两层都要有证据）

**层一 · 保存期**

```powershell
# 故意提交坏语法，必须被拒
node bin/kv.mjs localtask config --set '<坏模板>'   # 或用设置页提交
```

通过判据：返回错误含模板名 + 区块名；库里**没有**存进坏模板。

**层二 · 运行期**

```powershell
node bin/kv.mjs localtask preview --id <id> --cwd <目录>        # 预览：看真实渲染
node bin/kv.mjs localtask get --cwd <目录>                       # 真领一次，看交付载荷
```

⚠️ **读交付内容用默认输出**，不要用 `--json` 再解析（#130）：JSON 里换行已转义，你读到的是 `\n` 字面量。需要机器可读又要原样区块时用 `--xml`（#128）。

通过判据：
- 目标区块渲染出预期内容；
- 保存坏模板被拒（运行期没有回落出口，S1 起一条直线——不存在「领取不报错但出现 renderWarnings」的路径）。

## ⑤ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 领取载荷里没有提示词整块 | 该模板未绑定 / `position != 0` | 检查绑定关系（主篇才自动内嵌） |
| 区块渲染成空白 | 变量名不在 ctx | `prompt registry` 看该段 fields；补 data() 字段或改模板 |
| 保存时报「模板语法错误」但看不出哪 | 报错被 `try/catch` 吞了 | 直接跑 `validateTemplate` 拿原始错误 |
| 保存时报「未声明的变量」 | 白名单拦截拼错的段名/字段名（全局段集 + fields 全路径） | 对照 `prompt registry` 的 fields 改模板 |
| 改了出厂快照没生效 | `BUNDLE_VERSION` 没加 1 → ensure 判定已最新零写 | bump `template-bundle.ts` 的 `BUNDLE_VERSION`，重启一次（升级只刷 builtin） |
| 改了模板没生效 | serve 进程内缓存 / 设置没落库 | 重启 serve；`localtask config --json` 确认库里的值 |
| `--json` 读出来的正文全是 `\n` | 拿 JSON 解析器读交付原文 | 改默认输出或 `--xml`（#128/#130） |

## ⑥ 反模式

- 在服务端把列表拼成一段文本塞进模板（应由模板 `{{#each}}` 渲染）。
- 为某一块单独造一套变量作用域（ctx 全共享是既有语义；白名单用全局段集，见方案 §4.2）。
- 为了让测试通过而放宽 `validateTemplate` / 白名单校验。
- 在模板里写业务判断（判断进插件 `data()`，模板只做呈现）。
- 给运行期加回落 / 双层 try/catch（保存期校验是唯一防线；运行期抛错即失败）。
