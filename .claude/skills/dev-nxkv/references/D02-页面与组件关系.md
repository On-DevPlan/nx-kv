# D02 · 页面与组件关系：谁调什么 API、谁是谁的子件

> D 序列 · web 端之二。回答「这个页面由哪些组件拼成、点哪个按钮打哪条 API、改动落在哪」。
> 组件本身的职责见 [[D01-组件结构]]；action 全表见 [[B02-action注册全表]]。

## 1. 三张注册表的分工（先记住这条）

| 表 | 位置 | 回答 |
|---|---|---|
| **action 表** | `src/modules/<id>/index.js` | 后端有哪些能力（CLI ↔ HTTP 一一对应） |
| **视图注册表** | `src/web/frontend/registry.js` | 有哪些**视图**（页面级），各自消费哪个后端域 |
| **面板注册表** | `src/web/frontend/panels.jsx` | 工作区里能开哪些**面板**（面板 = 一块可拖拽的工作区区域） |

视图与面板**不是一一对应**：一个视图可以被多个面板复用（例：`page/dir/index.jsx` 同时是 `dir` 面板与 `global` 面板的实现）；面板还包含不属于任何视图的容器（`sidebar`、`welcome`、`compose`）。

后端模块对自己的视图一无所知——视图只归前端管。

## 3. 页面 → API 对照

后端每条路由都在 [[B02-action注册全表]] 里；这里只列**前端页面实际调用的**。

### 3.1 `page/dir/`（目录工作台 · localtask 域）

| API | 用途 |
|---|---|
| `GET /api/localtasks` | 队列清单（侧栏与各面板共用一份，App 层 15s 轮询） |
| `GET /api/localtasks/item` | 单条任务详情 |
| `GET /api/localtasks/chain` | 派生链 |
| `POST /api/localtasks/clone` / `fork` | 克隆 / 派生 |
| `POST /api/localtasks/preview` | 预览交付提示词 |
| `POST /api/localtasks/reopen` | 重开（派生新任务） |
| `PATCH /api/localtasks/reorder` | 队列内重排 |
| `DELETE /api/localtasks/item` · `items` | 单条 / 批量软删 |
| `POST /api/localtasks/items/cancel` · `close` | 批量取消 / 关闭 |
| `POST /api/localtasks/tasks/restore` | 恢复软删任务 |
| `GET /api/localtasks/attachments` · `timegoal-log` | 附件清单 / 时间目标日志 |
| `POST /api/localtasks/attach` · `DELETE /api/localtasks/attach` · `PATCH /api/localtasks/attach-note` | 附件挂载 / 摘除 / 改说明（在 `components/md` 里） |

### 3.2 `page/doc/`（文档页 · docs 域）

| API | 用途 |
|---|---|
| `GET /api/docs/item?ref=` | 读正文（**真相在磁盘**，刷新即重读） |
| `PATCH /api/docs/item` | 写正文（写回来源文件） |
| `GET /api/docs/index` | 文档索引（快搜） |
| `GET /api/docs/attachments?ref=` | 文档附件 |
| `POST /api/docs/attach` · `DELETE /api/docs/attach` | 文档附件挂载 / 摘除 |
| `POST /api/docs/link` | 双链解析与登记 |
| `GET /api/repos/docs?id=` · `GET /api/boards/:id` | 归属侧的文档集与组信息 |

### 3.3 `page/group/`（项目组 · repos + localtask 域）

| API | 用途 |
|---|---|
| `PATCH /api/localtasks/reorder` | 待领取行拖动排序（**按 topic**，故只允许拖到同一成员队列的落点） |

组内任务横跨多个成员队列；任务正文头部带 frontmatter（`board` / `project`），提交时自动写入。

### 3.4 `page/overview/`（全部目录总览）

| API | 用途 |
|---|---|
| `DELETE /api/localtasks/items` | 底部批量删除（跨目录逐个调，仍是软删除） |

口径：只显示**未完成**的任务（待领取 + 在干）；已交付/已取消不再占屏。组任务也进总览，行上带「组」tag。

### 3.5 `page/repos/`（仓库管理 · repos 域）

| API | 用途 |
|---|---|
| `GET /api/repos` · `GET/PATCH/DELETE /api/repos/:id` | 仓库增删改查 |
| `POST /api/repos/detect` · `/api/repos/clone` · `/api/repos/open` | 探测 / 克隆 / 打开目录 |
| `GET /api/repos/remote/list?id=` · `GET /api/repos/remote/check?id=` · `POST /api/repos/remote/pick` | remote 对齐 |
| `POST /api/repos/ref/clone` · `/api/repos/ref/sync` · `/api/repos/ref/note` · `GET /api/repos/ref/check` | 参考仓库操作 |
| `POST /api/repos/bind` | 绑定参考（**加入分组是复制，不是移动**） |
| `GET /api/repos/export` · `POST /api/repos/import` · `POST /api/repos/import/diff` | 导出 / 导入 / 预演 diff |
| `GET /api/boards` · `GET/PATCH/DELETE /api/boards/:id` · `POST /api/boards/{assign,rekey,prune,import}` · `GET /api/boards/export` | 分组（项目组）管理 |
| `GET /api/docs` · `GET /api/docs/item` | 文档检索弹窗 |
| `GET /api/setting` · `POST /api/setting` | 偏好（如持续 get） |

### 3.6 `page/cloud/`（云端总览 · todo 域）

| API | 用途 |
|---|---|
| `GET /api/todo` · `GET/POST/PATCH/DELETE /api/todo/item` | 清单条目 CRUD |
| `POST /api/todo/done` · `freeze` · `unfreeze` · `archive` | 状态流转（三个桶：待办 / 已完成 / 冻结） |
| `GET/POST /api/group` · `GET/POST/DELETE /api/groups` · `GET /api/groups/:id/members` | 云端工作空间（**与项目组不是一回事**） |
| `GET /api/file` | 附件上传（`components/cloud/upload.js`） |
| `POST /api/auth/login` · `logout` | 登录态 |

### 3.7 `page/dag/`（编排面板 · localtask 域）

| API | 用途 |
|---|---|
| `GET /api/localtasks/item` | 读任务与依赖，投影成 DAG 节点 |

### 3.8 `page/settings/`（设置 · 多域）

| API | 用途 |
|---|---|
| `GET/POST /api/setting` | 全局偏好（含 `appendMode`） |
| `GET/PATCH /api/localtasks/setting` | 区块模板列表与生效项（`lt.blockTemplates`） |
| `GET /api/localtasks` · `GET /api/repos` · `GET /api/boards` | 各分区的可选项 |

### 3.9 `page/refs/`（文档列表 · repos 域）

| API | 用途 |
|---|---|
| `GET /api/repos/docs?id=` · `GET /api/boards/:id` | 主篇 + 补充篇 + 登记的 reference 三段 |

### 3.10 `page/progress/`（进程面板 · localtask 域）

| API | 用途 |
|---|---|
| `DELETE /api/localtasks/items` | 多选批量软删 |

## 5. 两条存储路径（别混）

| | 任务草稿 | 文档正文 |
|---|---|---|
| 位置 | `modules/md/doc-store.js`（**会话内存**） | 磁盘（`~/.nx-kv/docs/` 或外部绑定路径） |
| 读 | 会话内 | `GET /api/docs/item` |
| 写 | 会话内 | `PATCH /api/docs/item`（写回来源文件） |
| 刷新后 | 丢 | 重新读盘（与 Obsidian 心智一致） |

## 6. 双链与文档跳转

- 双链（两对方括号包裹地址）的点击 → 在工作区开**目标文档**的页签（`openPanel` 按 `component + config` 去重，同一文档反复点只聚焦已开的页签）。
- 解析规则与后端共用 `src/shared/wikilink.js`（同构纯函数）。
- 外部绑定（`path:`）也可写：登记在册 = 我的文档集，保存直接写回来源文件（后端再校验一次绑定闭包）；只有目录绑定（`dir`）仍是只读清单。
- `page/doc/index.jsx` 导出 `useWikiNav`，被 `page/repos/` 与 `page/refs/` 复用。

## 7. 改前端时该落在哪

| 改什么 | 落在哪 |
|---|---|
| 某个页面的版式 / 交互 | `page/<name>/index.jsx` 或其兄弟 section 文件 |
| 可复用的展示件 | `components/<group>/` |
| 可复用的**逻辑**（非组件） | `modules/<name>/` |
| 面板的寻址 / 标题 / 参数 | `panels.jsx` 的 `PANELS` |
| 视图归属（哪个后端域） | `registry.js` 的 `VIEWS` |
| 路由 ↔ 面板的互译 | `route-map.js`（纯函数，不引 React） |
| 工具栏按钮的编排 / 显隐 | `components/tool-acts/modules.js`（判定只此一处，栏渲染与编排面板共用） |
| 状态色调 / 文案 | `components/status-tag/model.js`（全应用唯一口径） |
| 弹窗 / 轻提示 | `components/popup/` · `components/toast/`（**全站唯一出处**） |
| 新样式 | `style-v2.css` / `styles-v2/`（v1 `style.css` 只存量维护） |

## 8. 前端改动的固定验证

1. `pnpm lint`（含前端 `no-undef`）→ `pnpm test:unit` → `pnpm build` → `pnpm test:smoke`。
2. **实际打开面板验证**：`pnpm build` 后 `nx-kv serve`，访问本地端口；必要时用浏览器检查布局与交互。
3. **cache-buster**：验证前端改动用 `?cb=1`——浏览器缓存会让「改了不生效」。
4. **别碰用户真实队列**：端到端实测用 `nx-kv-panel-probe` skill（独立 store 播种 + 临时端口 + Playwright 探针）。
5. **提交前核对 `git status`**：工作区可能有多会话并行改前端文件；只 `git add` 自己的文件清单，绝不 `git add -A`。
