# nx-kv — 本机任务队列 + 仓库上下文

本 skill **只讲怎么用**（不讲怎么开发）。分两个序列：

| 序列 | 是什么 | 何时读 |
| --- | --- | --- |
| **A（SOP）** | 常见 case 的标准动作，照着做就行 | **先看 A**——绝大多数请求都在这 |
| **B（知识）** | 概念 / 寻址 / CLI 参数 / 数据结构 | **只有 A 覆盖不到**时才翻 |

## 一句话定调（三条硬规矩）

1. **领活的标准动作是 `localtask get`**——它把任务正文、项目组上下文、附件本地路径、
   收尾要求都封装好了。**不要**先 `localtask list` / `show` 翻一遍再决定要不要领；
   翻列表只在你需要「不领取地看一眼」时用。
2. **`timeout` 是业务结果不是错误**（exit 0）：说明暂时没活，收尾即可，别重试。
3. **领到的 `instruction` 有则必读**：组上下文 / 附件 / 时间目标 / 收尾要求都是硬约束。

## A 序列：按 case 走

| 你要做的事 | 动作 | ref |
| --- | --- | --- |
| 领活（不知道有什么，直接领） | `nx-kv localtask get --json` | [[A01-领取任务]] |
| **领取指定编号**的任务 | `show --id N` 确认 → `reorder` 提到队首 → `get` 领走 | [[A01-领取任务]] |
| 阻塞等人回填（本轮最后一步） | `nx-kv localtask get --timeout 60 --json`（项目开了「持续 get」可省参数） | [[A04-阻塞等待与时间目标]] |
| 干完标完成 | `nx-kv localtask done --id N --summary "…"` | [[A03-完成与重开]] |
| 用户提修改意见 | `nx-kv localtask reopen --id N …` 派生下一轮（生成新编号，别自己 add） | [[A03-完成与重开]] |
| 把本对话的需求交给别的目录 | 提炼 → 自包含任务文本 → `localtask add --cwd …` | [[A02-提交任务]] |
| 任务带图片/文档附件 | 读 `instruction` 给的本机绝对路径；要加附件用 `attach` | [[A05-附件]] |
| 「这组仓库是什么、怎么配合」 | `board list --json` → 出关系报告 | [[A06-仓库与项目组]] |
| 调研开源实现 | `repo ref clone` → **真读**关键文件再下结论 | [[A07-参考仓库克隆与强制读]] |

> 多任务场景：**只有当你需要「不领取地看内容」或「校验某条是否已存在」时**才 `list` / `show`；
> 其余一律直接 `get`。

## B 序列：A 覆盖不到才查

| 要查的 | ref |
| --- | --- |
| 主题 / 任务 / ref / 项目组 / key 这些词到底指什么、怎么寻址 | [[B01-概念与寻址]] |
| 具体子命令、参数、退出码、JSON 形状、避坑 | [[B02-CLI速查]] |

典型触发：用户问「主题是怎么派生的」「任务编号能跨目录用吗」「这条命令有没有 --json」
「为什么我的任务不在这个队列里」——这类**知识性问题**才翻 B。

## 边界

- 提交任务给**别的**目录 → 本 skill A02（原 kv-submit）；领活/完成/重开 → A01/A03（原 kv-get）；
  项目组与参考仓库 → A06/A07（原 kv-repo）。
- 登记/扫描/增删仓库与项目组 → [[B02-CLI速查]] 的 `repo` / `board` 段。
- git 的状态 / diff / push 一律用 git 自己，不经过本 skill。
- 全部数据在本机 SQLite（`~/.nx-kv/nxkv.db`），**不需要登录、不访问后端**。
