# A04 · 仓库与项目组管理：登记、克隆到指定位置、绑定

## 这一篇解决什么

「把这个远程仓库拉到本机某个位置并登记」「把它挂进某个项目组」「参考仓库放在哪、怎么更新」。

## 一、先分清三种「仓库」

| 类型 | 干什么用 | 落点 | key |
| --- | --- | --- | --- |
| **开发仓库** dev | 你自己改代码的地方 | `gitDevRoot`（或你给的路径） | `github.com/owner/repo` |
| **参考仓库** ref | 拿来看实现 / 抄做法（只读参考） | `gitRepoRoot` | 同上 |
| **项目组** group | 一组仓库的命名空间 | 不落盘（只是关系） | `board/<名>`（历史数据 `group/<名>`） |

**参考仓库与开发仓库在底层只有一个 kind 的差异**（#132）——文档宿主、绑定、ext 结构都一样：
参考仓库一样能提交文档、一样能在右侧栏当文档列表的主题（见 [[A03-文档与归属]] §四）。

## 二、五步把远程仓库落到指定位置

1. **定存储根**：`setting set --gitRepoRoot`（参考仓库落点）/ `--gitDevRoot`（开发仓库落点）——不设会直接报错。
2. **克隆或登记**：`repo clone --remote …`（开发仓库）/ `repo ref clone --url …`（参考仓库）/ `repo ref add --path …`（已有 checkout）。
3. **对齐身份**：key 默认跟随 remote 归一化；要固化就 `--key`（或 `repo key set --follow` 恢复跟随）。
4. **挂进关系**：`board assign`（仓库↔组）/ `repo bind`（参考仓库↔组或仓库）。
5. **写清角色**：`board note`（组内角色）/ `repo ref note`（参考它的什么）。

## 三、把远程仓库 git 到指定位置（细账）

### 1）先定存储根（**不设就报错**，绝不默默落进 homedir）

```bash
nx-kv setting set --gitRepoRoot "D:\\repos\\ref"    # 参考仓库统一落点（建议非 C 盘）
nx-kv setting set --gitDevRoot "D:\\repos\\dev"     # 开发仓库统一落点
nx-kv setting get                                     # 看当前设置
```

### 2）克隆

```bash
# 开发仓库（落 gitDevRoot）
nx-kv repo clone --remote https://github.com/owner/repo --type dev --json

# 参考仓库（落 gitRepoRoot；也可顺手挂组 / 绑当前仓库）
nx-kv repo ref clone --url https://github.com/owner/repo --board <组id> --bind <仓库key> --json

# 已经有 checkout 了：只登记，不克隆（remote 缺省读 origin）
nx-kv repo ref add --path "D:\\repos\\ref\\owner\\repo" --json
```

`repo ref clone` 的关键约定：
- `--depth 1` 浅克隆（只读参考通常够用）；
- `--no-bind` 只落盘不绑定；
- 目标目录已存在同源目录时会**报错**（让你改用 `repo ref add` 登记），不会覆盖。

### 3）已有目录要登记 / 要补远程地址

```bash
nx-kv repo detect --path "D:\\work\\myrepo"          # 只读：探测这个目录的 git remote
nx-kv repo add --path "D:\\work\\myrepo" --name myrepo --key github.com/owner/repo --json
nx-kv repo remote --id <仓库key> --url https://github.com/owner/repo --json
```

**key 的三种口径**：跟随 remote 归一化（默认）/ 显式 `--key`（自定义身份，`--key-custom` 固化）/
`nx-kv repo key set --id <key> --follow` 恢复跟随。key 是全局身份，改它会连锁影响关系表。

### 4）远程地址对不上时

```bash
nx-kv repo remote list --id <仓库key> --json     # 列出全部候选 remote，标出当前采纳的
nx-kv repo remote pick --id <仓库key> --url <要采纳的那条> --json
nx-kv repo remote check --id <仓库key> --json    # 存在 / 不存在 / 不可达，三种结论分清
nx-kv repo key refresh --json                    # 扫 remote 给出可更新的 key（默认预览，--apply 落盘）
```

## 四、绑定：谁属于谁

```bash
# ① 开发仓库 ↔ 项目组（一个仓库可同时在多个组里）
nx-kv board assign --id <仓库key> --board <组id> --json          # 加入
nx-kv board assign --id <仓库key> --board <组id> --remove --json  # 移出
nx-kv board assign --id <仓库key> --board <组id> --before <仓库key> --json  # 插位（决定组内顺序）

# ② 参考仓库 ↔ 组 / 单个开发仓库（组级 = 组内共享）
nx-kv repo bind --id <参考仓库key> --board <组id> --json
nx-kv repo bind --id <参考仓库key> --repo <开发仓库key> --json
nx-kv repo bind --id <参考仓库key> --board <组id> --remove --json

# ③ 写「这个仓库在本组里干什么」（组内描述，关系本身的说明）
nx-kv board note --id <仓库key> --board <组id> --note "<角色与配合关系>" --json

# ④ 参考关系的说明（这个参考在该组/该仓库里参考什么）
nx-kv repo ref note --id <参考仓库key> --board <组id> --note "<参考它的哪一块实现>" --json
```

**批量与修复**：

```bash
nx-kv board prefix --prefix nx --board <组id> --json   # 按名字前缀一次性归组（不给 --board 就自动建同名组）
nx-kv board rekey --from <旧key> --to <新key> --board <组id> --json   # 组里的占位 key 重绑到本机仓库
nx-kv board prune --board <组id> --json                # 清理占位成员（默认预览，--apply 落盘）
nx-kv repo bind-topics --repo <仓库key> --json         # 把「未绑定」队列按路径前缀绑到真实仓库（默认预览）
```

## 五、参考仓库的日常维护

```bash
nx-kv repo ref of --id <仓库key> --json     # 这个仓库用到的参考：直接绑的 + 所属组绑的（两类并列）
nx-kv repo ref check --json                 # 完整性检查：目录/.git/origin 一致性 + 绑定死链（零副作用）
nx-kv repo ref sync --all --json            # 同步（只做快进合并）
```

## 六、组与仓库的信息

```bash
nx-kv board list --json                      # 全部组：成员 + 各自的一句话描述
nx-kv board get --id <组id> --json           # 单组详情（成员、组内描述、绑定文档）
nx-kv repo list --json                       # 全部仓库（--type dev|ref 可筛）
nx-kv repo get --id <仓库key> --json         # 单仓库详情（含所属组）
nx-kv repo knowledge --id <仓库key> --md     # 一把梭：项目介绍 + 所属组 + 参考仓库，拼成单篇 markdown
```

## 七、落盘与搬运

```bash
nx-kv repo export --zip --json                          # 导出布局 JSON（key + 分组 + 参考关系，不含本地路径）
nx-kv repo import --diff --file <布局.json> --json       # 导入前的差异检查（零副作用）
nx-kv repo import --file <布局.json> --strategy ours --json   # ours | overwrite | duplicate
```

## 八、克隆之后：**强制读**（调研的纪律）

参考仓库是**拿来看实现**的——克隆下来不读等于没克隆。

- 至少读 **README + 与任务直接相关的源文件/契约**；结论里写清**具体位置**（文件路径 + 函数名）。
- **不许**只凭 `grep` 命中一行或搜索摘要下结论——摘要会丢上下文。
- 引用时写清「参考的是哪个仓库的哪个文件」。
- 2 个以上候选仓库时，先各读入口与契约再取舍，不要凭 star 数拍脑袋。
- 读到的旧描述不修就顺手补正：`nx-kv board update --id <组id> --desc "<纠正后的描述>" --json`、
  `nx-kv board note --id <仓库key> --board <组id> --note "<组内角色的正确说法>" --json`。

多路调研时：3–5 路并行深搜 → 最多 clone 2 个最有价值的项目 → SSH 优先、失败双向回退 → `--depth 1` 浅克隆。
搜索关键词优先用域内术语（接口名、协议名、错误码原文）。

## 九、项目级「持续 get」

```bash
nx-kv repo update --id <仓库key> --get-loop on --get-loop-minutes 10 --json
nx-kv repo update --id <仓库key> --get-loop off --json
```

含义：该项目的 `get` 没有任务时阻塞等人回填（分钟数 = 阻塞窗口）。指令文案在 **设置 → 提示词模板 → 持续 get**，
仓库侧只有开关 + 分钟。

## 偏差与陷阱

| 偏差 | 正确做法 |
| --- | --- |
| 克隆参考仓库没先设 `gitRepoRoot` | 先 `setting set --gitRepoRoot <目录>`；不设会直接报错（不会落进 homedir） |
| 以为 `repo clone` 会 clone 到当前目录 | 它落到**存储根**（dev → gitDevRoot / ref → gitRepoRoot）；要落到指定目录就 `repo add --path` |
| 目录已存在还去 clone | 会报错让你改用 `repo ref add --path` 登记（不覆盖） |
| 改 key 当改名 | key 是身份不是名字：改名用 `repo update --id --name`；改 key 会连锁影响关系表 |
| 组内成员顺序乱了 | `board assign --before` 插位；顺序影响组视图里的呈现 |
| 参考仓库绑了但没人知道参考什么 | `repo ref note --id --board --note "…"` |
| `board prune` / `bind-topics` 直接落盘 | 它们默认**预览**，确认清单后再 `--apply` |
| 每次都手动 `git pull` 参考仓库 | `repo ref sync --all`（ff-only，脏工作区不动） |
| 用 `repo update --desc` 改项目介绍 | 描述已改为文档，介绍走 [[A03-文档与归属]] 的绑定 |
