# B01 · 知识 · 概念与寻址（谁是谁、key 怎么算、grep 什么能找到它）

> 本篇是**知识**不是 SOP：它回答「这个东西是什么、它的身份（key）怎么算、
> 我该 grep 哪个关键字才能找到它」。要动手改就走 A 序列。

**查它用这几条**：

```bash
grep -rn "export function deriveKey" src/modules/repos/service/identity.ts   # 仓库 key 怎么算
grep -rn "export function normalizeKey" src/shared/repo-key.ts               # key 归一规则
grep -rn "refIdFor\|attachmentId" src/core/attachmentdb/ids.ts              # 文档 / 附件 id
grep -rn "CREATE TABLE" src/core/db/migrations/                              # 库里有哪些表
```

## 一、四个概念

| 概念 | 是什么 | 存在哪 | 身份（key） |
|---|---|---|---|
| **topic** | 任务队列（谁在排队、谁被领取） | `topics` 表 | 由工作目录 / 仓库 / 组推导（`src/core/topic-key.ts`） |
| **repo** | 一个本机代码目录（开发仓库 `type=dev` / 参考仓库 `type=ref`） | `repos` 表 | `github.com/owner/name` 或 `local/<slug>`（`shared/repo-key.ts` 归一） |
| **group** | 一组仓库的命名空间（历史叫 board） | `repos` 表里 `type=group` 的行 | `board/<名>`（旧数据是 `group/<名>`） |
| **ref** | **文档库**里的一篇文档（不是仓库！） | `refs` + `ref_bodies` | `ref:<16位hex>` |
| **attach** | 挂在 task / ref 上的**资源**（文件、链接、任务、文档、md、文件夹） | `attachments` + `task_attach` / `ref_attach` | `att_<kind>_<hash>` |

**最容易混的两处**：

- **参考仓库 ≠ 文档 ref**：参考仓库是 `repos` 里 `type=ref` 的行（有路径、能 clone、能绑组）；
  文档 ref 是 `refs` 表里的行（有正文、能挂宿主、能被提示词引用）。名字都叫「参考」，不是一回事。
- **组（group）不是仓库的一种**：组是命名空间，一个仓库可同时在多个组里；
  组里的「参考仓库」是组级绑定（组内共享），仓库自己的「直接绑定」是另一条关系，两类并存、互不折算。

## 二、关系一览（谁引用谁）

```
topic ──▶ task ──▶ attach（资源：file/url/task/ref/mdfile/folder）
                    │
                    └──▶ 正文里用 nxkv://<kind>/<id> 引用

ref（文档）──▶ ref_bindings ──▶ 宿主：repo（仓库自己）/ group（组）/ group_repo（组内仓库那篇）

repo（开发）──▶ 直接绑定的参考仓库（repo 级）
group ──▶ 组级绑定的参考仓库（group_refs，组内共享）
group ──▶ 成员仓库（repo_group_members）
```

## 三、key 怎么算（唯一权威）

| 口径 | 规则 | 代码位置 |
|---|---|---|
| 仓库 key | 有 `keyCustom` 用它；否则由 **remote 地址**归一；再否则用显式 key | `src/modules/repos/service/identity.ts` 的 `deriveKey` |
| 仓库 key 归一 | 小写、`/` 分隔、去掉 `.git`、非法字符换 `-` | `src/shared/repo-key.ts` 的 `normalizeKey` |
| 组 key | `board/<名>`（历史数据 `group/<名>`） | `identity.ts` 的 `boardKeyOf` / `storedBoardKey` |
| 文档 ref id | `ref_` + sha1 前 16 位 | `src/core/attachmentdb/ids.ts` 的 `refIdFor` |
| 附件 id | `att_<kind>_` + hash（同路径幂等） | `src/core/attachmentdb/ids.ts` |

> **key 是身份不是名字**：改名字用 `repo update --id --name`；
> 改 key 会连锁影响关系表与文档绑定（`repo key set --follow` 可恢复跟随 remote）。

## 四、grep 什么能找到它（定位关键字表）

| 想找什么 | grep 关键字 | 落点 |
|---|---|---|
| 某个命令 / 接口的实现 | `cli: ['localtask', 'get']` | `src/modules/localtask/actions/*.ts` |
| 某条业务规则 / 判定 | `export async function <动词>` | `src/modules/<域>/`（service / repo / actions 分三层） |
| 某个交付给 agent 的字段 | `deliveryCtxOf` | `src/modules/tasktool/delivery-template.ts` |
| 附件在模板里的样子 | `attachTemplateCtx` | `src/modules/tasktool/attach-template.ts` |
| 提示词区块的定义 | `BLOCK_DEFS` | `src/shared/prompt-blocks.ts` |
| 模板引擎（占位符 / helper / 校验） | `renderInstruction` / `TEMPLATE_HELPERS` | `src/core/instruction-template.ts` |
| 库里有哪些表 / 列 | `CREATE TABLE` | `src/core/db/migrations/v*.sql` |
| 迁移边 / 版本 | `DIRECT_EDGES` / `CURRENT_SCHEMA_VERSION` | `src/core/db/migrations/index.ts`、`src/core/db/version.ts` |
| 某个附件 kind 的登记 | `registerFolder`（同款：`register<Kind>`） | `src/core/attachmentdb/<kind>.ts` |
| 面板页面 | `page/<名>/index.tsx` 的目录 | `src/web/frontend/page/` |
| 面板组件 | 组件目录名（如 `components/md/`） | `src/web/frontend/components/` |
| 前端调了哪些接口 | `api(` / `api<` | `src/web/frontend/page/<名>/api.ts`（页面不裸调 api） |
| 路由 / 面板互逆 | `routeOfPanel` / `panelSpecOfRoute` | `src/web/frontend/route-map.ts` |
| 单测 | `tests/unit/<域>-*.test.mjs` | 临时库夹具 `tests/support/test-store.mjs` |
| 决策记录（为什么这么设计） | `@decision` | `docs/decisions/`（唯一权威） |

## 五、几条容易踩的口径

- **组上下文只进组任务**：正文 frontmatter 带 `board` 的任务才带组材料（单 repo 主题的纯项目任务不带）。
- **参考仓库是文档宿主**：它和开发仓库一样能挂文档、能开「文档列表」（`kind=folder` 的路径指针等）。
- **绑定描述 = 文档**（#134）：组/仓库与参考仓库的「参考什么」写成该参考仓库的一篇文档
  （`ref_bindings.tag = link-note:<关系 key>`），关系边上只留一份供导出/导入带走的副本。
- **附件没有云端同步**：`file` 型只在本机附件仓，可达性看 `file.exists`；`mdfile` / `folder` 是路径指针。
