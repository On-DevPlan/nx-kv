# A02 · SOP · 提示词模板体系与扩展（领取 → 讲透 → 规范扩展 → 检查点）

> 命中信号：交付给 agent 的提示词不对（少了一段 / 变量渲染成空 / 文案不像你要的）/
> 要给 agent **多一条上下文知识**（流程规则、必须遵守的约束）/
> 要在设置面板里改模板 / 要加一个新模板区块。
>
> 本篇是「提示词模板体系」的**唯一入口**：先把整套东西怎么转起来讲透，
> 再给**规范的扩展方法**（三种动作，各有落点与步骤）与**每一步的检查点**。
> 区块 / 变量 / helper 的速查表在 `B03-提示词模板与上下文.md`。

## ① 前置：先把现场看清楚

```bash
node bin/kv.mjs localtask get --cwd "<项目目录>"                    # 领一条（无活时阻塞到超时）
node bin/kv.mjs localtask get --cwd "<项目目录>" --timeout 60       # 阻塞上限（**秒**；缺省用项目配置）
node bin/kv.mjs localtask get --cwd "<项目目录>" --param k=v       # 外部参数进 ctx（{{k}} / {{params.k}}）
node bin/kv.mjs localtask preview --id <id>                        # 零副作用：看这条会交付什么
node bin/kv.mjs localtask show --id <id> --cwd "<项目目录>"        # 任务本体 + 附件清单与本地路径
```

`get` 的三个关键点：

| 点 | 说明 |
|---|---|
| **默认输出就是交付原文** | 读原文别用 `--json`（那是给程序用的形状，不是逐字原文） |
| **拿到就要按段落执行** | 交付里的 `ack` 段写明「完成后必须调用 `localtask done --id <id> --summary "…"`」 |
| **阻塞 ≠ sleep** | `--timeout N`（秒）是服务端挂住请求到点返回 timeout，不是让你自己等 |

## ② 领取并读懂交付

交付是**几段拼起来的 XML 块**（默认 `XML 块` 模式；也可切成「正文直追加」）：

| 段（标签） | 内容 | 什么时候有 |
|---|---|---|
| `<nx-kv.context>` | 仓库 / 组 / 参考仓库 / 其余组 | 登记了仓库就有（组材料只进**组任务**：正文 frontmatter 带 board） |
| `<nx-kv.attachment>` | 附件清单 + 取用方式 + 文档原文 | 任务带附件时 |
| `<nx-kv.timecheck>` | 时间目标检查指令 | 带时间目标时 |
| `<nx-kv.goalhint>` | 时间目标的可算上下文 | 带时间目标时 |
| `<nx-kv.doneguard>` | 未到点不许 done 的拦截文案 | 只在 done 被拦截时出现 |
| `<nx-kv.ext>` | 同主题还有多少待领取 | 队列非空时 |
| `<nx-kv.ack>` | 完成回填指令 | 总有 |
| `<nx-kv.getloop>` | 持续 get 指令 | 项目开了持续 get |

读的时候：先看 `ack`（怎么交差）→ 再看 `doneguard` / `timecheck`（有没有时间门禁）→
再看 `context`（这个仓库/组是什么）→ 有附件先按附件段的「取用方式」读
（图片看图、md 读正文、**文件夹先列目录**再读里面的文件）→ 然后才动手。

## ③ 动作 · 体系总览：一条交付提示词是怎么转出来的（七个部件各管一段）

```
① 取数          service / repo / docs / repos → 各自域的读接口
② 投影成 ctx    deliveryCtxOf + attachTemplateCtx + goal + task + params
                 （ctx 只放**数据**；成文措辞不在这里）
③ 选模板        每区块取「当前生效的那条」：normalizeBlockTemplateLists → resolveBlockTemplates
④ 渲染          composeSystemBlocks：按 BLOCK_DEFS 顺序逐块 renderInstruction
                 坏模板 → 该块回落内置 + 记 warning（领取照常成功）
⑤ 包标签        XML 块（默认）/ 正文直追加（appendMode 全局一个开关）
```

**七个部件，各管一段**：

| 部件 | 位置 | 谁改 | 关键规则 |
|---|---|---|---|
| 区块定义 | `src/shared/prompt-blocks.ts` 的 `BLOCK_DEFS` | 改代码 | **定义顺序 = 输出顺序**；id / tag / label / desc / defaultTemplate |
| 模板条目 | settings 表的 `lt.blockTemplates`（每区块 `{active, list}`） | 用户在设置面板改 | 内置条目**恒在且不可删改**；`active` 指向生效项，失效自动回落内置 |
| 生效条目 | `src/shared/prompt-blocks.ts` 的 `resolveBlockTemplates` | 自动 | 每区块只取 active 那条 |
| ctx | `src/modules/tasktool/`（delivery-template / attach-template / plugins…） | 改代码 | 一份共享 ctx；字段是数据不是文案 |
| 渲染 | `src/modules/tasktool/system-blocks.ts` | 改代码 | 坏模板回落内置 + warning，**绝不静默、也绝不整单失败** |
| 引擎 | `src/core/instruction-template.ts` | 改代码 | `{{#if}}` / `{{#each}}` + 25 个 helper；保存期 `validateTemplate` 拒旧语法 |
| 设置面板 | `src/web/frontend/page/settings/prompt-templates-section.tsx` | 改代码 | 区块卡片 → 模板列表（新建/复制/启用/删除/恢复内置）→ 正文 → 「可使用参数」只读表 |

> 模板是**运行时数据**（用户在面板改），ctx 字段是**代码**——两者会漂移，
> 所以扩展必须同时动两边（见 §④）。

## ④ 动作 · 规范扩展方法：三种动作（加变量 / 加区块 / 加模板条目）

先判定要做哪一种：

| 你要做的事 | 动作 | 落点 |
|---|---|---|
| 已有区块里多给 agent 一个信息 | **扩展 1**：给区块加变量 | ctx 投影 + 默认模板 + 变量表 |
| 交付里多一段（新维度：规则、清单、提示） | **扩展 2**：加新区块 | `BLOCK_DEFS` + ctx + 模板 + 变量表 + 说明书 |
| 只是想改某段的**说法**（文案风格、多加一句） | **扩展 3**：加一条模板条目 | 设置面板：复制内置 → 改 → 启用 |

### 扩展 1 · 给已有区块加一个变量

| 步 | 落点 | 做什么 | 检查点 |
|---|---|---|---|
| 1 | 该域的 ctx 投影处（仓库/组 → `delivery-template.ts` 的 `deliveryCtxOf`；附件 → `attach-template.ts`；时间目标 → `plugins/`） | 取数并投影成**纯数据**字段 | 字段名与业务词一致（`repo.introRefId`，不是 `repo.intro_id`） |
| 2 | `src/shared/prompt-blocks.ts` 对应区块的默认模板 | 加占位 `{{新字段}}`（必要时用 `{{#if}}` 闸门） | **空数据时整段不出现**，不能印空标签 |
| 3 | 模板的 `vars_schema`（DB 里声明，前端据此渲染表单） | 声明变量名 / 类型 / 说明 | 面板表单里能填到这个变量 |
| 4 | `src/web/frontend/page/settings/prompt-template-params.ts` 的 `BLOCK_PARAMS` | 加一行「变量名 + 一句含义」 | 设置页「可使用参数」里能查到 |
| 5 | 内置 skill（`assets/nx-kv/references/`） | 写给 agent 的用法（什么时候用这个变量） | agent 看得懂这条信息是干嘛的 |

### 扩展 2 · 加一个新区块

| 步 | 落点 | 做什么 | 检查点 |
|---|---|---|---|
| 1 | `src/shared/prompt-blocks.ts` 的 `BLOCK_DEFS` | 加一条：`id` / `tag`（`nx-kv.<id>`）/ `label` / `desc` / `defaultTemplate` | **位置 = 你想要的输出顺序**；tag 不与现有重复 |
| 2 | 该域的 ctx 投影 | 提供这一块要的数据 | 数据为空的区块整段不出现 |
| 3 | `defaultTemplate` | 只放**措辞**；数据全从 ctx 取 | 模板里没有硬编码的业务文案 |
| 4 | `prompt-template-params.ts` | 给新块加变量分组 | 设置页自动出现这张卡片（它遍历 `BLOCK_DEFS`）+ 参数表可查 |
| 5 | 内置 skill | 告诉 agent 这段是干什么的 | — |

> 设置面板**不需要额外登记**（卡片是遍历 `BLOCK_DEFS` 生成的），
> 但 `BLOCK_PARAMS` 要手动加（这是目前唯一的漂移点，见 §⑥）。

### 扩展 3 · 加一条模板条目（改说法）

1. 设置面板 →「提示词模板」→ 选中区块 → **复制**（内置条目不可改，复制出来才能改）；
2. 改正文 → **保存**（保存即落库，`validateTemplate` 会拒旧语法 / 语法错）；
3. **启用**（`active` 指向它）——不启用就只是躺在列表里；
4. 出问题想退回 → 区块上的「**恢复内置**」。

> 模板是**每用户的数据**（settings 表 `lt.blockTemplates`），不是代码；
> 改代码里的 `defaultTemplate` **不会**覆盖用户已启用/复制的那条。

## ⑤ 检查点清单（扩展完必过，逐条有判据）

| # | 检查点 | 判据 | 怎么验 |
|---|---|---|---|
| 1 | **模板语法** | 保存不报错；没有旧语法（`{{#section}}` / `{{^x}}`） | 面板保存成功；`validateTemplate` 通过 |
| 2 | **变量解析** | 新占位符渲染出**真实内容**，不是空串 | `localtask preview --id <id>` 目视（**变量名写错不会报错，只会静默变空**） |
| 3 | **空数据闸门** | 数据为空时该区块**整段不出现** | `preview` 一条没有该数据的任务 |
| 4 | **老交付没坏** | 原有各段的输出与改动前**逐字一致** | 改动前后各跑一次 `preview` 对比 |
| 5 | **坏模板不炸队列** | 故意写错语法 → 告警 + 回落内置，**领取仍成功** | `preview` 看告警；再真领一次 |
| 6 | **参数表同步** | 设置页「可使用参数」能查到新变量；`tests/unit/prompt-block-params.test.mjs` 通过（它核对区块 ↔ 变量表，**缺表、多表都拦**） | `pnpm test:unit` |
| 7 | **门禁** | lint / typecheck / 单测全绿 | `pnpm lint`、`pnpm typecheck`、`pnpm test:unit` |
| 8 | **说明书** | 内置 skill 写清了新字段/新块的用法 | 人工过一遍 |

> 第 2、3 条是**目前唯一能发现变量写错**的手段（Handlebars 未知变量渲染成空串，不报错）——
> 所以 `preview` 不是可选项，是扩展的必过关口。

## ⑥ 现状体检：这套东西现在的问题

写这一篇时查了一遍（结论：**没有集中落点，也没有自动化的变量表**）：

| 症状 | 位置 | 建议 |
|---|---|---|
| ctx 装配分散在 4 处 | `wait.ts` / `delivery-template.ts` / `attach-template.ts` / `plugins/` | **新的**上下文知识统一落在 `src/modules/tasktool/` 下的一个 context 目录（**尚未建立**，遇到第一篇时建）；已有装配暂不动（改动面大，另起一次重构） |
| 变量知识化两处手写 | 模板 `vars_schema`（DB）+ 前端 `BLOCK_PARAMS` | 由 ctx 域自己导出变量清单，前端速查表由它生成（需要一次生成脚本，落在 `scripts/`） |
| 区块定义与 ctx 装配分离 | `src/shared/prompt-blocks.ts` ↔ `modules/tasktool/` | 给 `BLOCK_DEFS` 加 `needs: ['repo','group']`，渲染前校验 ctx 是否齐（缺字段 → 告警，而不是静默空） |
| 变量写错静默变空 | Handlebars 语义 | 给 `validateTemplate` 加「变量是否在 ctx 契约里」的检查（配合上一条的 `needs`） |

> 这四条是**建议**，不是既成事实；动手前先在本篇与 `B03-提示词模板与上下文.md` 同步口径。

## ⑦ 自检

```bash
node bin/kv.mjs localtask preview --id <id>      # 零副作用看渲染结果：分段 + 告警
node bin/kv.mjs localtask get --cwd "<项目目录>"  # 真领一次，看最终交付原文
pnpm lint && pnpm typecheck && pnpm test:unit
```

| 检查 | 通过判据 |
|---|---|
| 领取流程 | 交付里段齐全、顺序符合 `BLOCK_DEFS`；`ack` 段要求回填 |
| 扩展生效 | 新段/新变量在 `preview` 里出现且**有内容** |
| 老交付一致 | 改动前后 `preview` 的原有段逐字相同 |
| 坏模板 | 回落内置 + 告警，领取仍成功 |
| 门禁 | lint / typecheck / 单测全绿 |

## ⑧ 失败分支

| 症状 | 原因 | 处置 |
|---|---|---|
| 新变量渲染成空 | 变量名写错 / ctx 没投影 / 挂在别的域下 | 按 §⑥ 的表核对投影位置；`preview` 看渲染结果 |
| 交付里出现空标签（`组定位：`） | ctx 字段存在但内容为空 | 给默认文案，或用 `{{#if}}` 整段闸掉 |
| 设置面板改模板没生效 | 复制/新建后**没启用**（`active` 仍指向内置） | 面板里点「启用」；或「恢复内置」回退 |
| 改了代码里的默认模板，用户那边没变 | 用户启用的是自己那条（运行时数据优先） | 面板里恢复内置 / 改用户那条 |
| 模板存不进去 | 旧语法或语法错 | `validateTemplate` 的中文提示就是原因；改成 `{{#if}}` / `{{#each}}` |
| 领取整单失败 | 不该发生：坏模板只回落该块 | 查 `renderWarnings`；若整单失败说明不是模板问题（走 `A08-排障与定位.md`） |
| 新区块在面板上看不到 | 没进 `BLOCK_DEFS`（卡片靠它生成） | 补 `BLOCK_DEFS` + `BLOCK_PARAMS` |
| 参数表与模板对不上 | 两处手写漂移 | 以模板实际引用的变量为准补 `BLOCK_PARAMS`（并记一笔待做自动化） |

## ⑨ 反模式

- 在 ctx 里塞**成文措辞**（ctx 只放数据；措辞在模板里，用户才能改）。
- 只加模板不加变量表（用户不知道能写什么）或只加变量表不加模板（模板引用不到，等于没加）。
- 新增字段不 `preview` 就提交（变量写错不报错，只会静默变空）。
- 把「每轮都要说的规则」塞进任务正文（正文会被重排，规则会沉底）。
- 把「一次性要求」塞进全局模板（所有任务都被污染）。
- 改 `templates` / settings 里的运行时数据来「修」代码 bug（那是用户数据，不是代码）。
- 为了让某段出现，去改**别的**区块的模板（区块各有职责，串味了没人查得出来）。
