# A03 · 文档（ref）管理：四类宿主（含参考仓库）、可绑定列表、写一篇能照做的文档

## 这一篇解决什么

「这个项目 / 组的知识在哪儿」「怎么给一个仓库加一篇文档」「怎么让文档挂到正确的宿主」
「**参考仓库的文档列表怎么建、怎么查、怎么在面板里打开**」
「用户要一份详细的安装说明」。

## 一、先认清四类宿主（挂错地方 = 没人看得见）

| 宿主 | 是什么 | key 形态 | 能挂的文档 |
| --- | --- | --- | --- |
| **开发仓库** repo | 一个本机代码目录 | `github.com/owner/repo` | 主篇（项目介绍）+ 补充篇 |
| **参考仓库** ref | `kind=ref` 的仓库（拿来看实现 / 抄做法） | 同开发仓库 | **和开发仓库完全一样**：主篇 + 补充篇 |
| **项目组** group | 命名空间：一组仓库的集合 | `board/<名>`（历史数据 `group/<名>`） | 组介绍主篇 + 附加篇 + **组内仓库篇** |
| **组内仓库** group_repo | 某个仓库**在某个组里**的那一篇 | 组 key + 仓库 key | 「这个仓库在本组里干什么」 |

**开发仓库与参考仓库在底层只有一个 kind 的差异**（`ext_legacy_type` = `dev` / `ref`）：
文档宿主、绑定表（`ref_bindings`）、宿主 ext 结构全都一样——所以**参考仓库一样能提交文档、
一样能当文档列表的主题**，组视图里也会显示它的文档（标「参考 · xxx」）。

一篇文档 = `refs` 行 + 正文（`ref_bodies`）+ 归属（`ref_bindings`）。
归属只有三种 type：`repo`（宿主自己的）/ `group`（组自己的）/ `group_repo`（组内仓库的那篇）；
**position=0 是主篇**。

## 二、查：先看清现状再动手

```bash
nx-kv docs list --json                                  # 文档库索引（自有文档全量）
nx-kv docs get --ref ref:<refId>                        # 读某篇全文（默认输出即逐字正文）
nx-kv docs bindings --host <仓库key> --json              # 这个仓库自己的文档（含参考仓库）
nx-kv docs bindings --group <组key> --json               # 组域文档集
nx-kv docs bindings --ref ref:<refId> --json             # 这篇被谁引用（一篇可挂多处）
```

- `--host` **只给这个宿主自己的文档**（`type=repo`），不掺组域文档；给参考仓库的 key 就得到
  **参考仓库自己的文档列表**（每行 `hostKind=ref`）。
- 组域文档集的顺序是 **组 → 组内仓库 → 成员仓库自己 → 组内参考仓库自己**；
  每行带 `hostKind`（`dev` / `ref` / `group`）——看它就知道这条是挂在谁身上的。

## 三、建 + 挂：新建一篇，再挂到宿主

```bash
# ① 新建一篇（正文为空、拿到 refId 后去面板/正文里写；不创建任何文件）
nx-kv docs ref add --owner repo --repo <仓库key> --desc "<一句话说清这篇是什么>" --json

# ② 挂成宿主的主篇（项目介绍 / 组介绍）
nx-kv docs bind --repo <仓库key> --ref ref:<refId> --json      # 仓库的主篇
nx-kv docs bind --board <组key>  --ref ref:<refId> --json      # 组的主篇

# ③ 挂成补充篇 / 附加篇
nx-kv repo doc add --id <仓库key> --ref ref:<refId> --note "<这篇在仓库里的说明>" --json
nx-kv docs link --board <组key> --ref ref:<refId> --note "<这篇在组里的说明>" --json

# ④ 挂成「组内仓库的那一篇」
nx-kv docs note-bind --board <组key> --repo <仓库key> --ref ref:<refId> --json
```

同一篇 ref 重复添加 = 更新注解（不会多出一份）。

## 四、参考仓库也能构建文档列表（与开发仓库完全同构）

参考仓库不是「只读旁路」：它有自己的一等文档列表，**面板与 CLI 两条路都能建**。

### 4.1 面板侧（右侧栏，仓库管理页）

1. 打开 Web 面板（`nx-kv serve`），进**仓库管理页**。
2. 顶部筛选条选中某个**项目组** → 页面下方出现「『<组名>』的参考仓库」区块。
3. 每个参考仓库行上都有**文档入口**（和开发仓库行的「查看详情」是同一个面板组件）。
4. 点开 → **右侧栏**出现「**<参考仓库名> · 文档列表**」（例：`powertoys · 文档列表`）：
   同一套归属筛选器、同一个「＋ 新建」、同一套行样式。
5. 筛选器打开时落在「**仓库**」这一档（精确归属）；参考仓库宿主下只有这一档有内容，
   「组 / 组内」两档为空、不显示——和开发仓库的文档列表一模一样。
6. 标题用**名字**不用 key（拿不到名字才回落 key 末段：`github.com/microsoft/powertoys` → `powertoys`）。
7. 「＋ 新建」出来的文档归属写在这个参考仓库上（`type=repo`、`hostKind=ref`），
   行上徽标显示「**参考 · <名>**」（开发仓库是「仓库 · <名>」）。

### 4.2 CLI 侧（建 → 挂 → 查）

```bash
# ① 建一篇（正文为空；拿到 refId 后再写）
nx-kv docs ref add --owner repo --repo <参考仓库key> --desc "<这篇是什么>" --json

# ② 挂成主篇（这个参考仓库的「项目介绍」）
nx-kv docs bind --repo <参考仓库key> --ref ref:<refId> --json

# ③ 挂成补充篇（带一句说明）
nx-kv repo doc add --id <参考仓库key> --ref ref:<refId> --note "<这篇在参考里的什么>" --json

# ④ 查这一份文档列表（只有这个参考仓库自己的文档；每行 hostKind=ref）
nx-kv docs bindings --host <参考仓库key> --json

# ⑤ 查它的介绍文档集（主篇 + 其余各篇）
nx-kv repo doc list --id <参考仓库key> --json

# ⑥ 在组视图里一起看（组 → 组内仓库 → 成员仓库自己 → 组内参考仓库自己）
nx-kv docs bindings --group <组key> --json
```

### 4.3 口径要点

1. **只有 kind 差异**：参考仓库与开发仓库在文档层没有任何区别——建篇、挂主篇、挂补充篇、
   删文档、GC，全是同一套命令，宿主 key 都直接用参考仓库的 key。
2. **`--host` 精确到宿主**：`docs bindings --host <参考仓库key>` 只回这个参考仓库自己的文档；
   要看整个组域（含组内参考仓库）用 `--group`。
3. **组视图里参考仓库排在最后**（组 → 组内仓库 → 成员仓库自己 → 组内参考仓库自己），
   徽标 `hostKind` = `dev` / `ref` / `group`——按它分清每篇挂在谁身上。
4. **「组级描述」不是文档**：`repo ref note` 写的是「组 ↔ 参考仓库」这条**关系**的说明，
   留在关系侧；文档要走 `docs ref add` / `docs bind` 那条路。

## 五、摘 / 删：三个动作别搞混

```bash
nx-kv docs ref unbind --ref ref:<refId> --type repo --repo <仓库key> --json  # 只解绑归属，文档还在
nx-kv repo doc remove --id <仓库key> --index 2 --json                        # 摘掉仓库文档集的第 2 篇（1 = 主篇）
nx-kv docs remove --ref ref:<refId> --json                                   # 删文档本体（宿主里的悬空引用会一并清掉）
nx-kv docs gc --json                                                         # GC 没有正文的文档（默认只报数）
```

`docs gc --apply` 才会真删；删之前先备份库。参考仓库走同样这三步，宿主 key 换成它的 key。

## 六、用户要「一份详细的安装说明」时怎么写

这类需求的高频失败是**写成一堆说明，而不是一篇能照做的文档**。按下面走：

1. **问清三件事**：装什么（哪个仓库 / 哪个参考仓库）、装到哪（本机哪个路径）、装完怎么算成功。
   缺一个就问，别猜。
2. **定宿主**：装的是**开发仓库** → 挂它的主篇；是**参考仓库** → 一样能挂（kind 不同而已）；
   是**整个组共享的流程** → 挂组的主篇。
3. **建篇**：`nx-kv docs ref add --owner repo --repo <key> --desc "<安装说明>" --json` → 拿到 refId。
4. **写正文**（面板里直接编辑；或本地写好文件再 `nx-kv docs link-file --ref ref:<refId> --path <文件>`）。
   安装说明必须能**照做**，六段齐全：
   - 前置条件（版本、依赖、权限、网络/镜像可达）；
   - 逐步命令（可照抄：真实路径、真实参数、顺序标号）；
   - 验证方法（跑哪条命令、看到什么输出算成功）；
   - 回滚 / 卸载；
   - 常见坑（报错原文 → 原因 → 处置）；
   - 与本仓库其它部分的衔接（哪个脚本、哪个入口、哪个配置）。
5. **绑定**：`nx-kv docs bind --repo <key> --ref ref:<refId> --json`（或 `--board`）。
6. **复核**：`nx-kv docs bindings --host <key> --json` 能看到它、`nx-kv docs get --ref ref:<refId>` 能读出全文。

## 七、给文档挂附件

```bash
nx-kv docs attach --ref ref:<refId> --path <本机文件> --json   # 图片/文件（存本机附件仓）
nx-kv docs attach --ref ref:<refId> --folder <本机目录> --json # 文件夹（只登记路径指针）
nx-kv docs attach --ref ref:<refId> --mdfile <本机 md> --json   # 本地 md 指针
nx-kv docs attachments --ref ref:<refId> --json                 # 这篇挂了哪些资源
nx-kv docs detach --ref ref:<refId> --attachment <id> --json    # 摘掉一个（--purge 连资源一起删）
```

## 偏差与陷阱

| 偏差 | 正确做法 |
| --- | --- |
| 把组内仓库的那篇挂成「组附加篇」 | 组内仓库篇用 `docs note-bind --board --repo`；附加篇是 `docs link` |
| 以为参考仓库不能挂文档 | 参考仓库与开发仓库只有 kind 差异，`docs ref add --owner repo --repo <refKey>` 一样能用 |
| 以为参考仓库只能被读、不能建文档列表 | 参考仓库是**文档列表的一等主题**：右侧栏能开「<名字> · 文档列表」，也能新建 |
| 在参考仓库行只看到「组级描述」，以为那就是文档 | 组级描述是关系说明（`repo ref note`），不是文档；文档走 `docs ref add` / `docs bind` |
| 用 `docs list` 找某个参考仓库的文档 | `docs list` 是**自有文档全量**；要看某宿主的文档列表用 `docs bindings --host <key>` |
| 在组视图里找不到参考仓库的文档 | 参考仓库自己的文档排在**组域列表最后**（组 → 组内仓库 → 成员仓库自己 → 组内参考仓库自己） |
| 看不出某篇挂在开发仓库还是参考仓库 | 看 `hostKind`（`dev` / `ref` / `group`）；面板上徽标分别是「仓库 · xxx」「参考 · xxx」「组 · xxx」 |
| 一篇文档到处 add，重复出现 | 同一 ref 重复添加 = 更新注解；但同一篇挂到**不同宿主**是两件事（ref_bindings 允许多宿主） |
| 删文档只删一半（宿主还指着它） | 用 `docs remove`（会清宿主悬空引用）；别手改库 |
| 安装说明写成「参见 README」 | 文档要自足：前置/命令/验证/回滚/坑 五段齐全 |
| 用 `docs gc --apply` 手滑 | 先跑不带 `--apply` 的 dry-run 看名单 |
| 摘仓库文档集用错序号 | `--index` 从 1 起，1 = 主篇；先 `repo doc list --id <key>` 看清单 |
