> 模板能写什么。**要加一条上下文知识**走 `A02-提示词模板与扩展.md`。
>
> S0–S4 起是插件制：**一段 = 一个 `PromptPlugin` 类**；#152 起出厂正文进代码

## 一、交付 = 八个段落，**每段一份自己的数据**

```
compose({ plugins, groups: ['get','check','done'], seed, mode })
  └─ 每段：
     ├─ scope = { ...seed, ...await plugin.get('data') }   # 只有自己产的数据，不共享
     ├─ renderInstruction(plugin.get(), scope)             # 模板 trim 为空 → 该段不出
     └─ mode='xml' 包 <nx-kv.xxx> 标签；mode='plain' 直接拼文本
```

**没有共享 ctx**（#153）：一段的模板只能引用 `seed` + **自己** `dataSchema` 声明的字段。
跨段引用（ack 写 `{{repo.name}}`）在启动期被 `assertPluginList` 直接拒——
不再是「渲染成空串，靠 preview 才发现」。

| 段落 id | 标签 | 内容 | 何时出现 | 自己产的数据段 |
|---|---|---|---|---|
| `context` | `<nx-kv.context>` | 仓库 / 组 / 参考仓库 / 其余组 | 登记了仓库就有（组材料只进组任务） | `repo` `group` `refRepos` `groups` |
| `attachment` | `<nx-kv.attachment>` | 附件清单 + 取用方式 + 文档原文 | 任务带附件时 | `attach` |
| `timecheck` | `<nx-kv.timecheck>` | 时间目标检查指令 | 带时间目标时 | 无（只用 seed 的 `goal`） |
| `goalhint` | `<nx-kv.goalhint>` | 时间目标上下文（可算的秒数/人话） | 带时间目标时 | 无（只用 seed） |
| `doneguard` | `<nx-kv.doneguard>` | 未到点不许 done 的拦截文案 | 目标未到时 | 无（只用 seed） |
| `ext` | `<nx-kv.ext>` | 同主题还有多少待领取 | 队列非空时 | `ext` |
| `ack` | `<nx-kv.ack>` | 完成回填指令 | 总有 | 无（只用 seed 的 `task`） |
| `getloop` | `<nx-kv.getloop>` | 持续 get 指令 | 项目开了持续 get | `getloop` |

代码：**一个段一个文件**——`src/modules/promptplug/plugins/` 下 `context.ts` / `attachment.ts` /
`ext.ts` / `getloop.ts` / `ack.ts` / `timecheck.ts` / `goalhint.ts` / `doneguard.ts`（后三者的共享
shape 在 `goal-shape.ts`），基类 `base.ts`，编排 `compose.ts`，装配 `factory.ts`，
**交付组装** `delivery.ts`（assembleDelivery：seed 构造 + 三链合并 + compose——原在
tasktool/wait.ts，#227 收编进 promptplug；宿主取数在 tasktool/delivery.ts）。

> **「无自产数据」不等于「没有变量」**：ack / timecheck / goalhint / doneguard 四个类 `buildData()` 返回 `{}`，
> 但 `dataSchema` 仍声明 `goal.*` / `task.*`——那是**本段模板可见的变量域**，
> 也是启动期白名单的依据。变量域 = `seed` ∪ 自己 `dataSchema` 顶层。

## 二、每段的数据从哪来（seed + 自己的 buildData()）

| ctx 片段 | 来源 | 主要字段 |
|---|---|---|
| `task` | compose 的 **seed**（`tasktool/delivery.ts` 宿主取好 → `promptplug/delivery.ts` 组装） | `id` / `text`（交付前重排：最新轮置顶） |
| `cwd` / `source` / `summary` / `name` / `params` | seed | `params` 是**平面扩展**（`{{k}}` 或 `{{params.k}}`），内建键不被覆盖 |
| `goal` | seed（`tasktool/delivery.ts` + timegoal 插件算出人话字段） | `goalKey` / `durationHuman` / `remainingSec` / `check` / `statusLine` / `extra` |
| `repo` / `group` / `refRepos` / `groups` | `context` 插件的 `buildData()`（内部调 `deliveryCtxOf`） | `intro` / `docs` / `desc` / `peers` / `refRepos` / `note` |
| `attach` | `attachment` 插件的 `buildData()`（宿主用 `attachTemplateCtx` 构造后以 `Supply` 注入） | `count` / `inlineCount` / `areaCount` / `list[]`（按 kind 给子对象） |
| `ext` | `ext` 插件的 `buildData()`（宿主用 `pendingQueueInfo` 取，失败 → null） | `topic` / `count` / `list[]` |
| `getloop` | `getloop` 插件的 `buildData()`（宿主给 enabled 开关与分钟数；#230 删预渲染链） | `waitMinutes` |

**两条规矩**：

1. 数据只放**数据**，成文措辞归模板；服务端不拼多行文本（列表一律结构化，模板自己 `{{#each}}` 组织行）。
2. **数据生命周期止于本段**：`buildData()` 的产物只喂给本段的模板，不向后传——
   要共享就说明设计错了（该由一个段统一产出，或者合并成一段）。

## 三、模板语法与 helper

- 区块：`{{#if x}}…{{else}}…{{/if}}`、`{{#each list}}…{{/each}}`；
  **旧语法 `{{#section}}` / 反向区块 `{{^x}}` 已废弃**（保存时会被 `validateTemplate` 拒）。
- 占位符：`{{a.b.c}}`；未知变量**渲染成空串、不报错** → 只能靠 `localtask preview` 看结果。
- helper（`TEMPLATE_HELPERS`，共 25 个）：
  `eq ne gt gte lt lte between`（比较）、`and or not`（逻辑）、
  `add sub mul div mod round floor ceil percent ratio clamp`（数值）、
  `includes length default`（字符串）、`formatDuration`（秒→人话）。
  helper 自身异常会退化成可见兜底，不拖垮整份渲染。

## 四、模板存哪、谁能用

**出厂正文 = 插件类里的 TS 常量**（#152 起）：一段一个 `PromptPlugin` 子类，
正文写在该类的 `templates`（第一条 = 出厂默认）。**没有 JSON、没有 DB seed。**
**用户层模板 = template-store JSON**（#161 起）：每段可复制出多条、启用哪条自己挑
（`~/.nx-kv/promptplug-templates.json`；设置页「提示词模板」区管理）。

| 概念 | 落点 | 说明 |
|---|---|---|
| 出厂正文 | 各插件类的 `templates[0].text`（`src/modules/promptplug/plugins/*.ts`） | 出厂真相；builtin 永远可回 |
| 用户层模板 | `src/modules/promptplug/template-store.ts`（JSON 落 `APP_DIR`） | `items` + `activeId` per 段；保存前按变量白名单校验 |
| 生效优先级 | factory 装配 | 显式 overrides（预览/测试）> 用户启用模板 > 类内出厂 |
| 管理通道 | `prompt.template.save / activate / delete`（HTTP + CLI） | 设置页编辑器（prompt-template-editor.tsx）或命令 |
| 时机链 | 类的 `group`（`get` / `check` / `done`） | 交付 = 三条链合并（按 `order` 全局排序） |
| 链内顺序 | 类的 `order` | 只需链内唯一；不再有 `prompt.pluginOrder` 数组 |
| 注册表 | `src/modules/promptplug/registry.ts` 的 `PLUGIN_CLASSES` | 加段 = 类 + 一行登记（+ factory 分支） |
| 校验 | `assertRegistry()`（id 唯一 / 链内 order 不撞 / 模板非空 / 写回段不撞车） | 启动期一次，编译期常量 |

**timegoal 的三段同源（#161）**：任务级时间目标的出厂指令正文搬进了 `timecheck` 段
模板（`goals.prompt` 只存用户 `--prompt` 自定义；出厂原文视为未自定义）。所以
`nx-kv timegoal check` CLI 的「本轮提示词」= **check 链实时渲染**（timecheck + goalhint
段模板），与 get 交付同一段代码——设置页改段模板，两处同时生效。
`goalhint` 段的判据是 `goal.goalKey`（任务级 goal），别用 `goal.check`（出厂场景恒空）。

> 另一个「templates 表（category / vars_schema / scope…）」是**任务模板**体系
> （新建任务正文骨架、增强模板等），与提示词段落不是同一份数据，别混。

## 五、变量知识化：只有一份

| 位置 | 作用 | 谁维护 |
|---|---|---|
| 各插件的 `dataSchema`（zod `strictObject`） | ctx 形状 + 变量目录的唯一声明 | 改 ctx 的人 |
| `GET /api/prompt/registry` 的 `fields`（`schema-bridge` → `uiDescriptor` 派生） | 设置面板「可使用参数」、模板白名单同源 | 自动 |

派生规则（`schema-bridge.ts`）：

- 顶层段 + 段内一级叶子：`repo.name` / `attach.count` / `attach.list`；
- **数组元素再展开一层**：`attach.list[].file.localPath`（模板里在 `{{#each attach.list}}`
  内部写相对名 `{{file.localPath}}`，目录用 `[]` 标出这一层）；
- **联合（多 kind）取并集**：`attach` 的 6 种 kind 各有子对象，目录里都能查到。

> 没有第二份手写表。新增变量只改 `dataSchema` + `buildData()`，前端自动出现。
> 反例警告：`z.looseObject({})` 会让整段字段从目录里消失（附件曾经就是这么缩水的）。

## 六、失败时的行为（不静默）

| 情况 | 行为 |
|---|---|
| 模板语法错 / 旧语法 | 单测 `validateTemplate` 拒（模板在代码里，没有「保存」这一步） |
| 某段 `templates[0].text` 被清空 | `assertRegistry()` 抛「模板不能为空」（空段 = 配置错误，不是「该段关闭」） |
| `buildData()` 返回与 schema 不符 | `get('data')` 的 safeParse 抛错（`<id>: buildData() 返回与 schema 不符——…`）→ **整次交付失败** |
| 渲染抛错 | 同上，**不回落内置、不给空串**（静默降级比失败更贵，方案 §6） |
| 变量名写错 | **静默渲染成空**（Handlebars 语义）——只能靠 `preview` 发现 |
| 段落数据为空 | 该段整个不输出（`null` 段 / 模板 trim 为空）；不闸就会印空标签（`组定位：`这种） |

排查入口：`node bin/kv.mjs localtask preview --id <id>`（零副作用，能看到分段与告警）。
