# 2026-11-12 · 存储版本 6 说明

- date: 2026-11-12
- version: 6
- migration: `src/core/db/migrations/v6.sql`（DDL）+ `v6-data.ts`（归位与正文入库）
- tables: 改 `refs`（ALTER 加 3 列 + 1 索引）、新增 `ref_bodies`、重建 `ref_attach`（CHECK 增 `source`）
- changes:
  - `refs` 升级为「文档本体」：
    - `rel`：逻辑名（不再是物理路径），部分唯一
      `ux_refs_rel (rel) WHERE rel <> '' AND deleted_at IS NULL`；
    - `origin`：`own`（CLI/面板写入）/ `import`（导入与扫盘）/ `external`（外部文件镜像）；
    - `body_bytes`：正文 UTF-8 字节数（列表页不读正文）。
    - `locator` **冻结**为历史取证列：不删、不写新值、不参与唯一性。
  - 新增 `ref_bodies`（1:1 挂 `refs.id`，`ON DELETE CASCADE`）：
    `body` / `body_bytes` / `body_hash`（sha256）/ `updated_at`。
    1:1 且无 `deleted_at`：生命周期完全跟随 `refs`。
  - `ref_attach.role` 的 CHECK 扩为 `('inline','attach','reference','source')`：
    `source` = 这条 ref 的正文来自某个 `mdfile` 附件。
- 为什么 `refs` 用 ALTER 而不重建：重建父表会在 `DROP TABLE` 时**立即触发**
  `ref_bindings` / `ref_attach` 的 `ON DELETE CASCADE`（v5 已实测，`defer_foreign_keys`
  只推迟校验、不推迟级联动作）。`ref_attach` 因 CHECK 必须重建，按其自身的
  `CREATE TEMP TABLE` 快照 → 重建 → 显式列名回填，再 DROP 快照。
- 数据迁移（`v6-data.ts`，与 DDL 同一事务）：
  - 相对 `locator` → `rel = locator`，`origin='import'`；
  - 空 `locator` → `rel = legacy/<id>`（空壳，保留取证）；
  - 绝对路径 / URL → `rel = external/<sha1(规范化)>.slice(0,16)`，`origin='external'`；
    文件仍在且是 `.md` → 登记 `attachments(kind='mdfile')` 并挂
    `ref_attach(role='source')`；文件不在 → 只留空壳；
  - 盘上 docs 树全部 `.md` → `ref_bodies`；逐篇**回读**库内正文重算 sha256 与盘上
    文件比对，任一不符即抛错、整步回滚（硬门禁）；
  - 迁移后校验：`rel=''` 的活动行必须为 0，`ref_bodies` 行数必须等于盘上文件数；
  - 结果写入 `meta.refs_v6`（files / bodies / legacy / external / emptyBody /
    mdfiles / sources / warnings），供迁移后核对。
- 身份：沿用方案 A（`ref_<sha1(rel)>` 只用于新行），存量 133 行 id 全部保留，
  不换 ULID；`rel` 是唯一逻辑名，`id` 仍是外键目标。
- 回滚：只允许向前升级。迁移前备份由启动检查写
  `~/.nx-kv/backups/nxkv-<时间戳>.db`；v6 只加列/新表/扩 CHECK，旧程序读既有列
  不受影响，可直接回退旧版本程序（`ref_bodies` 被忽略）。
- 盘上副本：31 份 docs 树内 `.md` 入库后**只留档，不再读取**；v6 不把它们自动登记为
  mdfile（`registerMdfile` 不参与 docs 树内文件），磁盘副本留给人工回溯。
- `NX_KV_DOCS_DIR` 语义变更：不再是「文档根」，而是 **mdfile 的默认附件目录**。
  环境变量名不变；该目录只能经 `readMdfile`（附件表定位后）读取，任何模块不得直接扫盘。
  函数名相应改为 `mdfileDir()` / `mdfileDirFromEnv()`，违规写法由
  `tests/unit/docs-dir-policy.test.mjs` 拦截。
- 配套设计：`docs/decisions/2026-11-12-refs-body-in-db.md` §11（二轮确认与验收项）、
  §12（DOCS_DIR 收口）。
