# E03 · 坑库：症状 → 根因 → 正确做法

> E 序列 · 交付流程之三。都是本仓库**真实踩过**的，不是假想。
> 设计评审与提交前对一遍。

## 架构与分层

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 面板上有的操作 CLI 没有 | 绕过 action 直接在前端/服务里写逻辑 | 所有操作先做成 action（`cli` 必有，`http` 可选），面板只调 `/api/*` |
| 循环依赖 / 启动即报错 | `modules/A` import `modules/B` 内部文件；或 runtime ↔ module 成环 | 跨模块只用对方 service 导出面；runtime 可 import modules，反向禁止 |
| 业务逻辑散落 | 在 `core/` 或 `shared/` 写业务 | `core/` 只放原语，`shared/` 只放无副作用纯函数，业务留在模块 service |
| 页面用后端私有函数 | 前端 import 后端模块 | 前端只能 `/api/*` + `src/shared/`；违反会被 `eslint.config.js` 拦 |
| 新增模块后跨模块 import 没被拦 | eslint 模块禁列是**枚举式**，漏补新模块就静默 | 新增模块时手动补 `'../<新模块>/*'`；别只依赖 review |
| 模块 import 了 runtime 的装配层后循环依赖 | 只看到「模块不能 import runtime」的字面理解 | 禁的是**装配层**（cli / registry / server / api / spec / help / codegen）；模板契约层（types/module、action-base、action-decorator、container）正是模块要 import 的 |
| 单文件涨过 600 行没人发现 | 没跑行数门禁 | `check-lines.mjs` 进 lint：601–1000 必须登记 `line-lint-registry.json`（只许降），>1000 直接禁止；别「登记了就安全」——登记值只许降不许升 |
| 页面组件里直接 `api('/api/...')` | 习惯了旧写法 | 页面调用收口到本页 `page/<name>/api.ts` 具名函数（eslint `no-restricted-syntax` 拦截，`api.ts` 自身豁免） |
| 新增页面后整页白屏 / `X is not defined` | 前端漏 import | 前端全是 TS、strict 全开：`pnpm typecheck` 直接报 `Cannot find name`；不要指望 lint（`no-undef` 已对 TS 关闭） |
| 把 import 里的 `.js`/`.jsx` 后缀改成 `.ts`/`.tsx` | 看到「源码全是 TS」想顺手统一 | **import 路径保留 `.js`/`.jsx` 后缀**是约定（tsx loader / vite 按它解析到 `.ts`/`.tsx`）；改了 typecheck/dev/构建三条路径会一起炸 |
| 业务模块里写 legacy flags 表 | 旧文档或旧代码参考 | 业务 action 全走模板形态（zod 契约内联）；flags 表只剩 serve/help/version 三个内建命令在用 |

## 存储与 SQL

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 引入 JSON 文件 / 原子 rename / 文件锁做业务数据 | 沿用改造前的存储思路 | 本项目唯一业务数据源是 SQLite；文件只存附件 / 文档内容 |
| 测试把数据写进用户真实库 | 测试未隔离库路径 | 用 `tests/support/test-store.mjs` 临时库；它断言路径必须在 tmp 下 |
| 迁移后真实历史数据丢失 | 只适配夹具格式 | 迁移前跑 `db backup` / `db migrate --dry-run`，覆盖旧 JSON、旧 key、软删行、跨队列依赖 |
| 软删语义矛盾 | 部分路径软删、部分硬删；查询漏过滤 | 全链路统一 `deleted_at IS NULL`；软删后同 key 再建应是恢复同一行，不是两行抢 UNIQUE |
| 任务依赖指向错误任务 | 把队列内 `seq` 写进 `task_deps.dep_id` | `dep_id` 必须是全局 `tasks.id`；插入时按 `(topic_id, seq)` 解析后再写，并与插入同事务 |
| 并发新增撞唯一索引 | 事务外预分配编号 | 编号分配 + 插入放在同一事务（`topics.next_seq` 只增不减） |
| 事务中途失败留下半套数据 | 跨表操作未包事务 | 多表/多行写入统一 `txw(...)`；回调内不要 `await` 外部 IO |
| 用 `tasks.id` 当 CLI 编号 / 用 `seq` 当外键 | 两个身份混用 | 对外显示 `seq`（`#12`），外键/依赖/派生链一律 `tasks.id` |
| `version` 是死列 | 声明了乐观锁字段却不递增 / 不校验 | 每次更新递增并在 `WHERE version = :old` 中校验；与 `round`（派生轮次）不是一回事 |
| 把需要过滤的字段塞进 `ext` | 图省事 | `ext` 无索引，**凡是要进 WHERE 的字段都不许进 ext** |
| 可空列上的唯一约束形同虚设 | SQLite 里 NULL 在唯一索引中互不相等 | 用 `COALESCE(col,'')` 包一层；实例型还要带 `WHERE deleted_at IS NULL` |
| 改了已发布的 `vN.sql` | 想「顺手修一下」 | 迁移脚本是**不可变快照**，可能被外部库执行过；加 `vN+1.sql` + 登记边 |

## 提示词与模板

| 症状 | 根因 | 正确做法 |
|---|---|---|
| action 读 `ctx.某字段` 恒为 undefined | zod 校验**剥掉未声明键**——schema 里没写，HTTP body / CLI 里带了也到不了 `run` | 把字段补进该 action 的 `input` schema（#177 靠类型化抓出 6 处这种死路径） |
| 新加的 action / 路由面板上没有、serve 还是旧行为 | 没跑 `pnpm gen`，或跑了但没重启 serve | 改 action 声明 → `pnpm gen` → **重启 serve**；`routes` 输出是最快的核对手段 |
| 改了模板但领取结果没变 | 改的是 `templates` 表（任务正文模板），或没选中该区块的生效模板 | 提示词改对应区块的模板列表，并确认该块当前生效项 |
| 出现 `[object Object]` | 旧模板把列表变量当字符串插值 | 列表用 `{{#each}}`；旧纯文本占位符交给迁移处理 |
| 恢复出自研解析器 / 区块对象 | 参考了旧文档或旧代码 | 只保留「共享 ctx + 字符串模板 + 薄编排」；`items`/`wrapper`/`{{block.content}}` 仅迁移兼容 |
| 每个区块又搞一套变量域 | 沿用了旧「区块对象」思路 | 所有区块共用 `buildDeliveryCtx` 的一份 ctx，不要把变量字典或语法说明搬进 UI |
| 服务端先拼多行文本再塞模板 | 为了方便 | 传结构化数组，模板里 `{{#each}}` 组织行 |
| 提示词里的 `<` / `&` 变成 HTML 实体 | 忘了关转义 | 引擎固定 `noEscape: true`，不要给模板单独加转义选项 |
| 保存坏模板成功、领取时被悄悄换回内置 | 没有保存校验，只靠运行期回落 | 保存时 `validateTemplate`（precompile）拒绝；运行期回落必须写 `renderWarnings` |
| 一条坏模板让整个队列领不出任务 | 把渲染异常当致命错误 | 该块回落内置模板，不阻断领取，但告警必须可见 |
| 正文里的 `{{...}}` 被二次解析 | 多层渲染 / 预渲染 | 单遍渲染；`task.text` 只作为数据插入 |
| `{{#goal}}` 取不到 `{{goal.durationHuman}}` | 用了裸段（以 x 为上下文渲染） | 写 `{{#if goal}}…{{/if}}`，不要写 `{{#goal}}` |

## 任务 / 依赖 / 渲染链路

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 预览和真实领取不一致 | 复制了一套预览渲染 | 预览必须复用 `buildTaskDelivery`（`preview: true`），不得另写渲染 |
| 预览「看起来对」但真实 get 缺上下文 | 用 `--text` 草稿预览 | 草稿预览绕开库存/附件/目标路径；最终证据必须用 `--id` 或真实 `get` |
| 依赖查询卡死 | 递归 CTE 无深度 / 回环保护 | 使用 `core/workflow/readiness.ts` 的现有实现；新增图算法必须加回环 + 深度上限 |
| 引擎写回把手工依赖洗掉 | 快照覆盖 `blocks_following` / `blockBy` | 本地依赖取「现有 ∪ 快照边」并集；闸门边不写 `blockBy` |
| 跨队列依赖进了本队列 DAG | 没区分 `"topicKey:seq"` 与本地 id | 跨队列依赖只落 `ext_deps_foreign`，不进本 topic 引擎节点图 |
| 用 `tasks.seq` 重排队列顺序 | 以为顺序在 seq 上 | 顺序在 `topics.ext.ext_task_order` |

## HTTP 与 serve

| 症状 | 根因 | 正确做法 |
|---|---|---|
| `PATCH /api/templates/default` 更新不进去 | 静态路由被 `PATCH /api/templates/:id` 抢走 | 字面量路由优先于参数段（`api.ts` 已排序）；静态路由要**自己按载荷分派** |
| 改了 actions 顺序后某个接口 404/串了 | 路由按声明顺序匹配 | `api.ts` 按「字面量在前、段数多的在前」排序；不要依赖声明顺序 |
| 面板从外网提交任务 403 | 按 Origin 主机名拒绝写请求 | 已废止：浏览器对 POST 一律带 Origin；跨域交给 CORS 预检处理 |
| 面板白屏（`src/web/public` 空） | 没构建 | `pnpm build`（`src/web/public` 是 gitignore 的产物） |
| 端口被占后起了第二个面板 | 没做端口认领 | `resolvePortConflict`：`app.name` 相同则复用，否则顺延端口 |
| 自己的面板被误判成别人的服务 | 探测窗口太窄（800ms） | 探测窗口 1500ms，且超时再等一次 |
| 端口上跑着面板但 presence 看不见 | 只问了默认端口 | `registerPanel(boundPort)` 登记所有跑着的面板端口 |

## 前端

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 前端改了不生效 | 浏览器缓存 | 验证用 `?cb=1` cache-buster，并重启 serve / 重新 build |
| 点了文档，裂出两个页签 | `panelSpecOfRoute` 与 `routeOfPanel` 的 config 不是逐字互逆 | 两边字段必须完全一致（`configSig` 按序无关比） |
| 文档面板名对不上 | 面板名被二次 decode / encode | 文档页面板名用**原始字节**末段名 |
| 轮询把刚开的页签顶掉 | effect 跟数据数组走 | 跟**身份**（route / 面板名）走，不跟数据数组走 |
| 侧栏卡在「压窄的展开态」 | 拿绝对像素阈值判收起态 | 收起宽度是 tabset weight **百分比**；用显式状态 + 迟滞带（`side-state.ts`） |
| 收起侧栏后摸不到设置 | 窄轨 / 关闭态没保留齿轮 | 侧栏三态都要保留设置入口 |
| 提交混入并行会话的改动 | 图省事 `git add -A` | 提交前 `git status` 核对，只 add 自己的文件清单 |
| 新会话打开时右栏面板整块消失 | FlexLayout `fromJson` **丢空 tabset**——旧布局里只有空边栏 tabset 时它根本不会出现在反序列化结果里 | 右栏面板按**结构化识别**（找得到就聚焦、找不到就现建），不能假设「上次开过这次就还在」；清场类操作要豁免自己刚建的面板 |
| 页面 API 收口后 lint 红 | 页面组件还留着 `api()` 裸调用 | 调用搬进本页 `api.ts` 具名函数（路径/方法/body 逐字一致，只搬不改语义）；`api.ts` 自身豁免 |

## 术语与设置键

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 文档/UI 里「主题」「目录」「队列」混用 | 历史命名漂移 | 本地实体统一叫「主题（topic，本地队列）」；「云端主题」明确加 cloud 前缀；「目录」只是页面视图 |
| 「项目组」和「仓库组」对不上 | UI 叫项目组、CLI 叫 board、schema 叫 group | 代码/文档统一 `group` / `group_key`；`board` 仅历史 CLI 别名 |
| 继续写旧设置键当来源 | 不知道新权威位置 | 权威是各区块自己的模板列表与生效项；旧键只用于迁移 |
| 把 `config.groupId` 当成项目组 | 两个 `group` 重名 | `config.groupId` 是云端工作空间；项目组是 `repos.type='group'` |
| 仓库 key 又按名字/随机生成 | 沿用了旧 `local/<name>` 兜底 | key 只能显式给或由 remote 归一化；无 remote 时必须报错让用户填，导入同理 |
| clone 之后任务链断了 | clone 只复制正文，没写派生边 | 需要保留链用 `fork`（正文复制 + `task_links` type=comment）；两者语义不要混用 |
| 把 `localatt` 当成一张表 | 记错了 | 本机附件仓是**文件系统**（`~/.nx-kv/attachments/local/`）；元数据在 `attachments` 表 |

## 交付与文档

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 汇报「测试通过」但拿不出输出 | 只看退出码 / 凭感觉 | 附命令与关键输出；渲染给 preview/get 片段，DB 给 `verify` 结果 |
| CLI 改了但 README/技能还是旧命令 | 只改代码 | 同步 `README.md`、`docs/project&projectsCli.md`、`assets/<name>/` |
| 面板设置出现两套同样功能 | 任务模板与提示词模板混写 | 设置页保持「任务模板」与「提示词模板」分离，各自单一 CRUD |
| 在真实库上试迁移/试模板 | 图快 | 先 `nx-kv db backup`；迁移先 `--dry-run`；模板先在临时库或 preview 验证 |
| 新样式写进 `style.css` | 没注意 v1/v2 | 新样式优先 `style-v2.css` / `styles-v2/` 的 tokens；`style.css` 只存量维护 |
| 以为 `task_refs` 有数据 | 表存在 ≠ 功能在用 | v2 起附件模型是 `attachments` + `task_attach` / `ref_attach`；`task_refs` / `ref_relations` 已删除 |
| 裸 `git push` 失败 | 本机 `remote.pushDefault` 指向不存在的远端 | 显式 `git push origin <branch>`，别把它误导成 SSH 问题 |
