# A07 · 克隆参考仓库 + 强制读

## 三步（下面的「三步」命令块就是这条 SOP 的展开）

1. `repo ref clone <url>` 落盘并登记。
2. 可选：`repo bind` 绑到组或当前仓库。
3. **真读**：列文件清单 → Read README + 相关实现/契约 → 结论写清文件与函数名。

任务需要「看看别人怎么做的」时用。**参考仓库要真读**，不是搜两眼摘要就下结论。

## 三步

```bash
# 1) 克隆并登记为参考仓库（落到统一 gitRepoRoot，remote 即 key）
nx-kv repo ref clone <git-url> --json                 # → { repo:{ key, path, … } }
nx-kv repo ref clone <git-url> --board <组id> --bind <仓库key> --depth 1   # 顺手挂组 / 绑仓库 / 浅克隆
nx-kv repo ref clone <git-url> --no-bind              # 只落盘不绑

# 2) 绑定（可选）：组级（组内共享）或只绑当前仓库；说明用 repo ref note 单独写
nx-kv repo bind <ref-key> --board <组 id> --json
nx-kv repo ref note --id <ref-key> --board <组 id> --note "参考它的 xxx 实现" --json
nx-kv repo bind <ref-key> --repo <仓库 key> --json
nx-kv repo bind <ref-key> --board <组 id> --remove   # 解绑

# 3) 强制读：先列文件清单，再用 Read 真读 README / docs/ / 契约文件 / 入口实现
```

## 强制读的纪律

- 至少读 **README + 与任务直接相关的源文件/契约**；结论里写清**具体位置**
  （文件路径 + 关键行 / 函数名）；
- **不许**只凭 `grep` 命中一行或搜索摘要下结论——摘要会丢上下文；
- 引用时写清「参考的是哪个仓库的哪个文件」；
- 2 个以上候选仓库时，先各读入口与契约再取舍，不要凭 star 数拍脑袋。

## 多路调研（外部搜索时）

3–5 路并行深搜 → 最多 clone 2 个最有价值的项目 → SSH 优先、失败双向回退 → `--depth 1` 浅克隆。
搜索关键词优先用域内术语（接口名、协议名、错误码原文）。

## 偏差

| 偏差 | 正确做法 |
| --- | --- |
| 搜到就答，不 clone | clone 后真读关键文件 |
| 只读 README 就下结论 | README + 相关实现/契约 |
| 读到的旧描述不修 | 顺手 `board update/note` 补正（见 [[A06-仓库与项目组]]） |
