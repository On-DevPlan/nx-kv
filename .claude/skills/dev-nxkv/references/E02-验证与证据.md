# E02 · 验证与证据：只认跑出来的结果

> E 序列 · 交付流程之二。本项目只认「跑出来的证据」，不认「应该没问题」。
> 汇报时附命令与关键输出。

## 1. 固定检查项（交付前全跑）

```powershell
pnpm lint        # eslint . && node scripts/check-tdz.mjs --all
pnpm test:unit   # node --test tests/unit/*.test.mjs
pnpm test:smoke  # node tests/smoke.mjs（假后端 + 临时配置）
pnpm build       # vite build && node scripts/link-local.mjs --auto
pnpm test        # lint + build + smoke + unit 全量（最终以它为准）
```

- `lint` 自带 TDZ 全量扫描；`check-tdz` 失败等同 lint 失败。
- 只改数据库 / schema / migration 时额外跑 `pnpm test:db`。
- 改前端时还要**实际打开面板**验证（先 `pnpm build`，再 `nx-kv serve` 访问本地端口）。前端验证要带 cache-buster（`?cb=1`），否则浏览器缓存会让你以为「改了不生效」。
- 面板改动的端到端实测可用 `nx-kv-panel-probe` skill（独立 store 播种 + 临时端口 serve + Playwright 探针，绝不碰用户真实队列数据）。

## 2. 渲染层两层策略

提示词 / 模板改动必须**同时**验证两层（详见 [[B04-提示词渲染链]] §5）：

| 层 | 做法 | 证据 |
|---|---|---|
| 保存时 | `validateTemplate()`（`HB.precompile`）在 `setLtSettings` 内执行 | 故意提交坏语法应被**拒绝**，报错含模板名 + 区块名 |
| 运行期 | 坏模板**回落该块内置模板**并写 `renderWarnings`，不阻断领取 | 预览/领取载荷里出现 `renderWarnings`，且该块仍有内容 |

不要为了「让测试过」把保存校验绕过；也不要让运行期异常静默吞掉。正常入口保存不了坏模板，运行期回落只服务旧数据 / 手改库。

## 3. 「真实 localtask get」作为渲染证据

### 先做只读预览

```powershell
node bin/cli.mjs localtask preview --id <id> --cwd <dir>
```

看返回里的 `instruction`、`segments`、`switches`、`renderWarnings`：

- 六个区块按 `context → attachment → timecheck → ext → ack → getloop` 顺序出现；每个区块用的是它**自己**的当前生效模板；
- 该有的项目/组/附件/目标内容都在，且 `<nx-kv>` 根标签正确；
- `task.text` 没有被模板二次解析；
- 无 `renderWarnings`（或告警是你预期并已解释的）。

> `--text` 只适合草稿预览：它不读库存任务，绕开附件同步/任务级目标等真实路径，**不能作为最终交付证据**。

### 再做一次真实领取

```powershell
node bin/cli.mjs localtask get --cwd <dir>
```

- 在**可安全领取**的队列/任务上做；不要在用户正在跑的生产队列里制造假领取。
- 没有安全任务时，用临时库（见 §4）建一个队列 + 任务再 `get`，照样能证明同一条渲染链。
- 证据看返回载荷：`instruction` 完整、区块顺序正确、`coversBody` 合理、`renderWarnings` 不存在、`task.text` 逐字保留。
- 如果确实无法真实领取，**明确说明「只做了 preview」**，不要把 preview 冒充 get 证据。

## 4. 测试隔离（硬要求）

- 单测统一用 `tests/support/test-store.mjs` 造临时目录 / 库；它带有「必须位于 tmp 下」的断言，禁止指向 `C:\Users\<user>\.nx-kv\nxkv.db`。
- 需要手跑 CLI 验证时，显式设置临时库路径：

```powershell
$env:NX_KV_DB = Join-Path $env:TEMP ('nxkv-verify-' + [guid]::NewGuid() + '.db')
node bin/cli.mjs db migrate
node bin/cli.mjs ...
```

- 历史事故：测试代码把模板字面量写进真实库，导致用户领取时只看到 `DLV-<id>`。任何「单元测试」都不允许打开默认库。

## 5. 数据库改动验证

1. 改 schema：新增 `src/core/db/migrations/vN+1.sql`，在 `migrations/index.js` 登记边，**不改已发布快照的语义**（见 [[A01-数据模型]] §2）。
2. 先演练：

```powershell
node bin/cli.mjs db backup
node bin/cli.mjs db migrate --dry-run
node bin/cli.mjs db status
```

3. 正式迁移后：

```powershell
node bin/cli.mjs db verify
```

`verify` 覆盖版本、行数、状态分布、正文哈希、`seq` 对应、外键与 `PRAGMA integrity_check`；失败必须**定位到具体表/行**，不能只看「退出码 0」。

4. 迁移兼容真实历史数据：旧 JSON、旧 key、软删行、跨队列依赖都要有回归用例（参考 `tests/unit/db-migrate-from-json-structure.test.mjs`、`db-review-regressions.test.mjs`）。

## 6. action / 路由改动的验证

```powershell
node bin/cli.mjs routes                      # 全量对照（157 行）
node bin/cli.mjs routes --module <id>        # 只看某模块
node bin/cli.mjs routes --http "POST /api/xxx"
node bin/cli.mjs help --json                 # 与 routes 同源同长
```

- 新命令必须出现在 `routes` 里；CLI 路径与 HTTP 路由都不得与既有项重复（启动自检会抛，但**注册表要能列出来**才算真的登记了）。
- 改了路由形状 → 确认字面量路由没有被 `:param` 抢走（见 [[B03-action契约]] §4）。
- 前端调了不存在的 `/api/...` → `tests/unit/registry.test.mjs` 会红。

## 7. 前端改动的验证

```powershell
pnpm lint          # 前端 no-undef 是开着的：漏 import 会整页崩
pnpm build         # src/web/public 是 gitignore 的构建产物
pnpm test:smoke
```

然后**实际打开面板**走一遍：布局、交互、空态 / 错误态。必要时用浏览器检查。

- cache-buster：`?cb=1`。
- 面板 e2e 用 `nx-kv-panel-probe` skill；注意它「探针只隔离任务」——会写真实 `repos.json`，用前先确认隔离方式。

## 8. 汇报格式

汇报至少包含：

- 改了哪些文件（路径 + 一句话作用）；
- 跑了哪些命令、**实际结果**（lint/unit/smoke/build 的具体通过数或失败项）；
- 渲染证据：preview 或真实 get 的关键片段 / `renderWarnings` 状态；
- 数据库：是否备份、是否迁移、`db verify` 结果；
- 未做 / 做不了的事项与风险，**不要用「应该可以」带过**。
